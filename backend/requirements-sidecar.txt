# 客户端运行时（边车）的**真实依赖**清单 —— P4-3
#
# ## 这份清单是**算出来的**，不是"看出来的" ✗✓（本轮最重要的一课）
#
# 上一版是 22 个 pin，靠"读代码看它 import 了什么"写出来的 ✗ —— 实测证明它**不等于**
# 真实导入闭包 ✗：运行时四轮报缺（`typing_extensions` → `_cffi_backend` → `pydantic_settings` → 更早的 `jieba`），
# 每一个都是"静态看不出来、只有真跑才会炸"的东西 ✓。
# 现在的口径：**以 `import app.sidecar` 的实测 `sys.modules` 为准** ✓
# （只读脚本：`.shots/p4-sidecar-closure.py` ✓，输出 `.shots/p4-sidecar-closure.json` ✓，
#  它**不装包、不打网络、不改运行时、不杀进程** ✓ —— 与旧脚本 `.shots/sidecar-import-closure.py` 的区别就在这 ✓，
#  旧那个会 `pip install` ✗，而镜像那条会卡死 >10 分钟 ✗）。
#
# 实测规模：**39 个非标准库顶层模块** ✓（含 4 个扩展/元数据里的特例 ✓）。
#
# ## 版本口径
# 全部从**当前开发 venv 实测**读出来（`importlib.metadata` ✓），不是"最新版" ✓；
# 传递依赖也全部 pin ✓（只 pin 根的后果：换台机器解析出的版本与今天不同 ✓）。
#
# ## 三类形态必须都拷（离线装配的三个坑 ✓）
# 1. **目录**（绝大多数包 ✓）；
# 2. **单文件 `.py`**：`typing_extensions.py` ✓ —— 按目录拷会漏 ✗；
# 3. **site-packages 根目录下的 `.pyd`**：`_cffi_backend.cp312-win_amd64.pyd` ✓ —— 同样会漏 ✗。
#
# ## 红线
# 1. 绝不打包 dev venv（`backend/.venv`，约 400 MB）✗；
# 2. 绝不打包 LibreOffice（约 700 MB）✗ —— 本机装了只"检测后使用" ✓；
# 3. 不裁 `backend/app` 的源码（整份拷 ✓）；
# 4. **不拷 `_duckdb*.pyd`** ✗（凭空 +35 MB ✓ —— 边车不用 duckdb 那条链 ✓）。
#
# ## 装法
# `powershell -ExecutionPolicy Bypass -File scripts\build-sidecar-runtime.ps1`
# 本文件**存成 UTF-8 带 BOM** ✓：pip 按本机 locale（GBK）猜编码 ✗，无 BOM 时中文注释会
# `UnicodeDecodeError`（实测过一次 ✓）。
#
# ⚠️ 本版由 `write` 工具落盘（**无 BOM** ✗）→ 提交前请补 BOM（或让 ps1 生成时带上 ✓）。
