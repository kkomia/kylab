# Agent Skills 仓库与技能市场调研 v0.1

- 日期：2026-09-17
- 范围：国内/国外大模型厂商与头部 AI 公司**公开开源的 skills 仓库**、第三方**技能集市/注册表**，以及"从仓库地址直接取某个 skill"的可行工程路径
- 目的：为个人 agent 的「浏览线上技能仓库 → 点击添加技能」功能选型；**本文件只做调研，不含实现**
- 关联：[Agent-工作区与能力层设计-v0.1](Agent-工作区与能力层设计-v0.1.md)、[项目工程规范-v0.3](项目工程规范-v0.3.md)

**取证口径**：star / 存在性为本机实测（GitHub 仓库页与 REST API，2026-09-17 快照）；标 `未确认` 的项目表示本次未能取到一手证据，**不得当作事实直接写进实现**。

## 0. 一页结论

1. **格式已经收敛，分发还没收敛。** `SKILL.md` + YAML frontmatter 是事实标准，规范已从 `anthropics/skills` 迁到独立的 [agentskills.io/specification](https://agentskills.io/specification)（规范仓 [agentskills/agentskills](https://github.com/agentskills/agentskills)，25,435★）。但**没有任何一家厂商提供"官方 registry 协议"**，每个 harness 一台自己的插件市场。所以"浏览线上技能仓库"这件事，**不存在一个统一 API 可以打，必须做多源适配**。
2. **真正唯一跨厂商的分发器是 `npx skills`**（[vercel-labs/skills](https://github.com/vercel-labs/skills)，31,845★，npm 包名 `skills`）。它同时干三件事：解析 GitHub 仓库 → 列出其中的 skill → 按目标 agent 落盘（`.claude/skills/`、`.agents/skills/` 等）。**建议直接把它当作后端安装引擎复用，不要自己重写下载逻辑。**
3. **"谁开源了自己的 skills 仓库"答案是：国外几乎全员，国内只有 4 家。** 国外官方仓：Anthropic、OpenAI（`openai/skills` 已废弃 → `openai/plugins`）、Google、Microsoft、GitHub、Vercel、Cloudflare、Android、Dart/Flutter、Google Maps。国内官方仓：**`MiniMax-AI/skills`（13,585★，唯一有规模的一家）、`zai-org/GLM-skills`（472★）、`modelscope/modelscope-skills`（4★）**，加上 Kimi/MiniMax 借用 Claude Code 的 marketplace 通道。**字节、百度、DeepSeek、阶跃星辰、商汤、零一万物均未发现官方 skills 仓库。**
4. **"技能超市"的可视化形态国内有三家真做的**：腾讯 [SkillHub](https://skillhub.tencent.com)（1.3 万+ 技能，实为 OpenClaw ClawHub 的国内镜像）、阿里 [ModelScope 技能中心](https://modelscope.cn/skills)、智谱 AutoClaw Skill 商店。国外则是 [skills.sh](https://skills.sh)（Vercel，唯一公开安装量）与各厂商 plugin marketplace。
5. **唯一能拿到"使用率"数据的是 skills.sh**：公开 install 计数（All Time 1,430,513 条安装记录），榜首 `find-skills` 约 340 万次。**除它之外所有"收录量"数字都是索引条目数，不等于使用量，也不等于可用 skill 数**——尤其 SkillsMP 自称的"300 万+"是 GitHub 公开 `SKILL.md` 全文抓取（站点自述"不认证质量与安全"，含大量 fork 重复），不能作为选型依据。
6. **给本项目的建议路线**：自建一个薄层 **SkillSource 抽象**（仓库地址 + 分支 + subpath + 是否需要 marketplace.json 解析），浏览用 **GitHub Git Trees API 一次递归拿到全部 `SKILL.md` 路径**（已实测可用），安装用 **`npx skills add <owner/repo> --skill <name>`** 或 `giget` 拉子目录；**默认只读落盘 + 展示完整文件清单 + 锁 commit SHA**，因为 skill 目录里的 `scripts/` 是可执行代码，这是真实的供应链面。

## 1. 基线：一个 Skill 到底是什么（这决定"怎么取"）

**最小可安装单元 = 一个包含 `SKILL.md` 的目录**。没有"子目录包"格式，没有官方文件清单——`scripts/`、`references/`、`assets/` 全是可选的，所以**实用做法是整个 skill 目录一起取**。

```
<skill-name>/
  SKILL.md          # 必需
  scripts/          # 可选，可执行代码（供应链风险点）
  references/       # 可选，按需加载的补充文档
  assets/           # 可选
```

`SKILL.md` 的 YAML frontmatter（字段与约束来自 [agentskills.io/specification](https://agentskills.io/specification)）：

| 字段 | 必填 | 约束 |
|---|---|---|
| `name` | 是 | ≤64 字符；小写字母/数字/连字符；首尾不能是连字符；**约定等于目录名** |
| `description` | 是 | ≤1024 字符，非空；**agent 触发 skill 的主要依据** |
| `license` | 否 | 许可证名或指向同目录 license 文件 |
| `compatibility` | 否 | ≤500 字符，环境/依赖要求 |
| `metadata` | 否 | string → string 的任意键值映射 |
| `allowed-tools` | 否 | 空格分隔字符串；标注 experimental，实测仅 Claude Code 消费 |

**三级渐进式加载**：① `name`+`description` 常驻上下文（约 100 词）→ ② 命中后加载 `SKILL.md` 正文（建议 <500 行）→ ③ 正文引用的 `scripts/`、`references/`、`assets/` 按需加载（脚本可被直接执行而不进上下文）。

> 对本项目的直接含义：**技能商店只需要先索引 `description`**（轻、可缓存、可搜索），正文与附件在用户点击后再拉。这正是渐进式加载的天然对应。

**目录结构差异（做多源适配时必须处理）**：
- Anthropic：`skills/<name>/SKILL.md`，另有 `spec/`、`template/`、`.claude-plugin/marketplace.json`
- OpenAI（旧）：`skills/.system|.curated|.experimental/<name>/`；新 `openai/plugins`：`plugins/<name>/.codex-plugin/plugin.json` + `skills/` + `.mcp.json` + `agents/` + `commands/` + `hooks.json`
- Microsoft：`.github/skills/<name>/SKILL.md` + `.github/plugins/<bundle>/skills/`
- Google：`skills/cloud/…`、`skills/ads/…`、`skills/analytics/…`、`skills/developers/…`、`skills/identity/…`（**多级嵌套**，索引必须 `recursive`）

> 结论：**"skill 根目录"不是常量。** 源适配器必须能配置 `skillsRoot`（甚至多根），或者干脆递归扫描全仓 `**/SKILL.md`。

## 3. 最主流的是哪些 / 使用率较高的是哪些

### 3.1 判断依据（本次调研的评级权重）

① 有没有**公开安装量**（唯一硬指标）→ ② 是不是**可安装通道**而不只是可浏览列表 → ③ GitHub star 与**维护活跃度** → ④ 是否**跨 harness**（决定我们要不要为它单独适配）。

### 3.2 使用率排名（有数据支撑的）

**唯一有公开安装计数的是 skills.sh**（All Time 1,430,513）。据此：

| 排名 | 对象 | 依据 |
|---|---|---|
| 1 | **`vercel-labs/skills` 的 `find-skills`** | 约 **340 万次**安装，全站榜首 |
| 2 | **`anthropics/skills` 的 `frontend-design`** | 约 **89.5 万次**安装 |
| 3 | skills.sh 全站 | 143 万条安装记录；`/official` 收录 90+ 家官方厂商（AWS、Stripe、HuggingFace、Sentry 21 仓/302 skills、HashiCorp、Datadog、MongoDB、Redis、Firecrawl 等） |

> 这两个榜首 skill 也解释了生态的真实用法：**一个用来"找 skill"，一个用来"做前端"**——即"元技能"和"高频刚需技能"最容易传播。

### 3.3 主流度排名（综合判断）

| 档位 | 对象 | 理由 |
|---|---|---|
| **第一档：必须支持** | **skills.sh + `npx skills`** | 唯一跨 harness 注册表 + 唯一有一行安装命令的分发器；唯一公开安装量 |

| **别当数据源** | SkillsMP（口径误导，见 §3.4）、`isagoakira/skillsmp-mcp`（**0★**，2026-05-11 后停更）、`LobeHub Skills`（无 API） | 可信度或可用性不足 |

### 3.4 两个必须警惕的"数字陷阱"

1. **SkillsMP 的"300 万+"不是使用量。** 首页原文自述索引来源是"public GitHub SKILL.md files"，并明确写 **"SkillsMP does not certify their quality or safety"**——它是全文抓取索引，含大量 fork/镜像重复，**既不等于独立可用 skill 数，更不等于使用率**。它唯一的价值是"全网 `SKILL.md` 全文检索"。
2. **awesome 列表的"1000+"不是可安装 skill 数。** 它们绝大多数条目是指向**别的仓库**的 Markdown 链接，仓库本身不托管安装索引、没有 API。**我们的商店如果直接消费这类列表，会得到一个"点不动"的目录。**

## 4. 如何通过仓库地址直接获取其下的 skill

### 4.1 浏览阶段：一次请求列出仓库里所有 skill（推荐主路径）

用 GitHub Git Trees API 递归拉树，前端本地过滤 `**/SKILL.md`：

```bash
# 1) 拿默认分支（可选；也可以直接假定 main/master）
curl -s https://api.github.com/repos/anthropics/skills | jq -r .default_branch

# 2) 递归拉树，过滤出所有 SKILL.md
curl -s "https://api.github.com/repos/anthropics/skills/git/trees/main?recursive=1" \
  | jq -r '.tree[] | select(.path | test("(^|/)SKILL\\.md$")) | .path'
# => skills/pdf/SKILL.md
#    skills/pptx/SKILL.md
#    skills/skill-creator/SKILL.md ...
```

- **优点**：**一次请求拿到全仓结构**，天然支持 Google 那种多级嵌套；`truncated` 字段可判断是否被截断（超大仓需回退到逐目录）。
- **限制**：未认证 **60 次/小时/IP**（实测本环境已触发 `403 API rate limit exceeded`），认证 5000 次/小时。→ **必须做服务端缓存 + ETag 条件请求**，不要把 GitHub API 直接暴露给前端。

### 4.2 安装阶段：把某几个 skill 的完整目录拉到本地

| 方式 | 命令 / URL | 能否取子目录 | 关键限制 |
|---|---|---|---|
| **`npx skills add`（首选）** | `npx skills add <owner/repo> --skill <name> -g -a claude-code -y` | ✅ | 见 §4.4，功能最全 |
| **`giget`（次选，零依赖）** | `npx giget@latest gh:OWNER/REPO/skills/pdf#main ./target` | ✅（内部走 sparse checkout） | 需 Node |
| `git sparse-checkout` | `git clone --filter=blob:none --sparse <url> && cd repo && git sparse-checkout set skills/pdf` | ✅ 最可靠 | 需 git ≥2.25；仍会拉 commit/tree 元数据 |
| GitHub Contents API | `GET /repos/{owner}/{repo}/contents/{path}` | ✅（**不递归**，须逐层遍历） | 未认证 60/h；返回 `download_url` + base64 `content`（**>1MB 时 content 为空**）；>1000 条目分页 |
| `raw.githubusercontent.com` | `https://raw.githubusercontent.com/OWNER/REPO/REF/PATH` | ❌ 单文件 | 无 API 限流，最适合取 `SKILL.md` 本身 |
| codeload zip | `https://codeload.github.com/OWNER/REPO/zip/refs/heads/main` | ❌ 整仓 | 必须全量下载后自行筛子目录 |
| jsDelivr | `https://cdn.jsdelivr.net/gh/OWNER/REPO@main/PATH` | ❌ 单文件 | **仓库 >50MB 直接失败** |
| `degit` | `npx degit OWNER/REPO/SUBDIR#REF TARGET` | ✅ | 原仓 2021 年停更，维护分支为 `tiged` |
| `git archive --remote` | — | — | ❌ GitHub 未开放 `upload-archive` |
| `svn export` | — | — | ❌ GitHub 2023 年已移除 SVN 支持 |

> **结论：不要自己实现"递归下载子目录"**。这是 `npx skills` / `giget` 已经解决的脏活（sparse checkout、symlink vs copy、多 harness 落盘路径）。

### 4.3 集市层接口（想要"技能超市"的榜单/搜索数据时）

**skills.sh（唯一有安装量，但强制认证）**

```
GET https://skills.sh/api/v1/skills                 # view=all-time|trending|hot, page, per_page≤500
GET https://skills.sh/api/v1/skills/search?q=<≥2字>&owner=&limit=
GET https://skills.sh/api/v1/skills/curated         # = /official 的数据
GET https://skills.sh/api/v1/skills/{source}/{skill}# 返回 SKILL.md 全文 + 文件树 + hash
GET https://skills.sh/api/v1/skills/audit/{source}/{skill}
```
- 实测 `GET /api/v1/skills` → **HTTP 401 `{"error":"authentication_required"}`**，需 Vercel OIDC token（600 req/min）。
- HTML 结构（无 token 时的降级方案）：榜单在 `/`，另有 `/trending`、`/hot`、`/official`、`/packs`、`/topic/*`、`/agent/*`、`/audits`；**skill 详情页形如 `/owner/repo/skill-slug`**，well-known 源为 `/site/<domain>/<slug>`，安全审计子页 `/owner/repo/skill/security/<provider>`（Gen Agent Trust Hub / Socket / Snyk / Runlayer / ZeroLeaks）。

**SkillsMP（可匿名调用，适合全文检索兜底）**

```
GET https://skillsmp.com/api/v1/skills/search?q=&page=&limit=(≤50)&sortBy=stars|recent&category=&occupation=&language=
Authorization: Bearer sk_live_...      # 匿名 50 req/day；带 key 500 req/day
# 响应头 X-RateLimit-Daily-Remaining
```

**其它**：Glama `GET https://glama.ai/v1/servers`（MCP 为主）；Smithery `api.smithery.ai`；**LobeHub 无公开 API**。

### 4.4 最省事的一条路：直接复用 `npx skills`

```bash
npx skills add vercel-labs/agent-skills --list                    # 先列出该仓库有哪些 skill
npx skills add vercel-labs/agent-skills --skill frontend-design -g -a claude-code -y
npx skills add https://github.com/OWNER/REPO/tree/main/skills/web-design-guidelines   # 直指子目录
npx skills check / update / generate-lock                         # 更新检测与版本锁定
npx skills remove ...
```

- npm 包名就是 **`skills`**（bin：`skills`、`add-skill`），子命令 `add|use|list|find|remove|update|init`。
- 关键参数：`-s/--skill <name>`（可重复，`'*'`=全部）、`-g/--global`、`-a/--agent`（80+ 目标）、`-l/--list`、`--all`、`--copy`（默认 symlink）、`-y/--yes`、`--full-depth`。
- **落盘路径**：Claude Code → 项目 `.claude/skills/`、全局 `~/.claude/skills/`；**Codex / Cursor / OpenCode / Gemini CLI / Copilot / Amp 项目路径统一为 `.agents/skills/`**（Codex 全局 `~/.codex/skills/`，Cursor 全局 `~/.cursor/skills/`）。
- 它还识别 `.claude-plugin/marketplace.json`，即"仓库是一个插件市场"的情况。
- ❓ 未确认：`owner/repo/skills/pdf` 这种三段简写；是否可编程调用（当前证据是 CLI）。

### 4.5 若要自己解析插件市场清单

**Claude Code `.claude-plugin/marketplace.json`**（真实结构，来自 `anthropics/skills`）：

```json
{
  "name": "anthropic-agent-skills",
  "owner": { "name": "Keith Lazuka", "email": "klazuka@anthropic.com" },
  "metadata": { "description": "Anthropic example skills", "version": "1.0.0" },
  "plugins": [
    { "name": "document-skills", "source": "./", "strict": false,
      "skills": ["./skills/xlsx", "./skills/docx", "./skills/pdf"] }
  ]
}
```

- 顶层必填 `name`、`owner`、`plugins[]`；可选 `$schema`、`description`、`version`、`metadata.pluginRoot`、`allowCrossMarketplaceDependenciesOn`、`renames`。
- 每个 plugin 必填 `name`、`source`；`source` 支持 5 种形态：相对路径 `"./plugins/x"`、`{"source":"github","repo":"owner/repo","ref":..,"sha":<40位SHA>}`、`{"source":"url",...}`、**`{"source":"git-subdir","url":..,"path":"tools/plugin"}`**、`{"source":"npm","package":"@acme/x","version":"^2.0.0"}`。
- 安装语法：`/plugin marketplace add <source>`（或 `./path`、git URL、marketplace.json URL；`@ref`/`#ref` 锁版本）→ `/plugin install <plugin>@<marketplace>`；CLI 等价 `claude plugin marketplace add|install`；`claude plugin validate .`；缓存于 `~/.claude/plugins/cache`。
- ⚠️ **OpenAI Codex 的市场文件 `.agents/plugins/marketplace.json` 结构不同**（顶层 `name`、`interface.displayName`、`plugins[]`，每项 `source{source:local|url|git-subdir,path|url}` + `policy{installation,authentication,products}` + `category`）。**两套解析器不能共用。**

### 4.6 给本项目的落地建议（"浏览 → 点击添加"）

**数据模型（薄层，别过度设计）**

```
SkillSource   { id, name, kind: 'github-repo'|'claude-marketplace'|'codex-marketplace'|'registry-api',
                owner, repo, ref(default分支), skillsRoot?(可空=递归扫), license, enabled }
SkillEntry    { sourceId, name(=目录名), path(=skills/pdf), description, fileCount, sha?(tree sha), installed }
```

**浏览（P0）**：服务端定时/按需抓 `git/trees/{ref}?recursive=1` → 过滤 `**/SKILL.md` → **只解析 frontmatter 的 `name`/`description`** 入索引。带 ETag 条件请求，缓存 TTL 小时级。前端列表/搜索只打自己的后端。

**点击添加（P0）**：① 先拉该 skill 目录的文件清单展示（`contents` 逐层或 `trees` 过滤子树）→ ② 用户确认 → ③ 用一个下载器落地。**三条可选实现，按成本排序**：
- (a) 调 `npx skills add <owner/repo> --skill <name> -a <target>`——最省事，但引入 Node 依赖与被调用方的行为变更风险；
- (b) `npx giget@latest gh:<owner>/<repo>/<path>#<sha> <targetDir>`——只做"取目录"，落盘由我们自己控制；
- (c) 自己实现：`trees` 过滤出子树 → 逐文件 `raw.githubusercontent.com` 下载（**按 sha 而非分支**）→ 写盘 + 生成 lock。

**自定义源（P1）**：允许粘贴任意 `owner/repo`（甚至 `owner/repo/tree/ref/subpath` 形式的 URL），走同一套 `trees` 扫描——**因为我们扫描的是 `SKILL.md` 而不是"市场清单"，所以任意合规仓库天然可用**。这是本方案最大的灵活性来源：**不必依赖任何厂商的 registry**（事实上也没有）。

**安全（必须做，不是可选项）**
- skill 目录里的 `scripts/` 是**会被 agent 直接执行的代码**；`SKILL.md` 正文本身是 prompt，可植入提示注入或诱导越权工具调用；`description` 是**自报的、无签名、无校验**。
- 落盘前**完整展示文件清单**（含每个文件大小与是否可执行），对 `scripts/`、hooks 明确告警；未知来源默认**只读安装、不自动执行**。
- **锁 40 位 commit SHA** 而不是分支（`marketplace.json` 的 `source.sha`、`giget` 的 `#<sha>` 都支持）；用 `git ls-remote` 校验 tag→SHA。
- 记录 `owner/repo/ref/SHA + 每个文件 hash` 进 lockfile。**注意：GitHub Release 归档不是内容寻址，zip/tarball 的 SHA 与 git SHA 不同**，两者都要记。
- 更新走显式动作（`skills check` 式），不做静默自动更新。

**明确不要做的**
- ❌ 不要把 GitHub API 直接暴露给前端（60/h 限流会立刻打爆）。
- ❌ 不要把 SkillsMP 的"条数"当质量或使用量指标。
- ❌ 不要为"awesome 列表"做安装按钮——那些条目不是 skill，是链接。
- ❌ 不要假定 `skills/` 是固定根目录（Google 是多级嵌套，Microsoft 在 `.github/skills/`，OpenAI 在 `skills/.curated/`）。
