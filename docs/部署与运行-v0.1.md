> 日期：2026-09-11

## 1. 两条路线，先选一条

| 路线 | 适合 | 验证状态 |
|------|------|---------|
| **本地 venv + 脚本** | 单机自用、开发调试 | ✅ **本轮实测过** |
| **Docker Compose** | 交付给别人的机器、长期常驻 | ⚠️ **未验证**（开发机无 docker，计划风险 R9） |

**为什么还留着本地路线**：容器是交付形态，但开发与排障几乎都在本地跑。
只有容器一条路的话，"到底是代码问题还是镜像问题"会变成一个很难回答的问题。

## 2. 本地路线（已实测）

### 2.1 后端

```bash
cd backend
uv sync                                  # 装依赖（Python 3.11+）
cp .env.example .env                     # 按需填写；.env 不入库
uv run uvicorn app.main:app --reload     # http://127.0.0.1:8000
```

- 探针：`GET /api/v1/health` → `{"status":"ok",...}`
- 接口文档：`/api/v1/docs`
- 首次启动**无需手工建库**：连接时自动跑迁移（`apply_migrations`），
  数据目录与对象存储子目录也会自动创建。

### 2.2 前端

```bash
cd frontend
npm install
npm run dev                              # http://localhost:5173
```

开发服务器把 `/api` 代理到 `127.0.0.1:8000`，所以**同源、无跨域**。

### 2.3 内置消费线程

后端进程内会起一个消费协程（`KYLAB_RUN_WORKER=true` 时）。
**它是"上传之后文档会不会被处理"的关键**——关掉它，任务只会排队。

界面上「任务中心」的 `/tasks/health` 会直接告诉你它开没开
（`worker_enabled`），以及有没有任务卡住（见 §4）。

## 3. 容器路线（未验证，谨慎照抄）

```bash
export KYLAB_URL_SIGNING_SECRET=$(openssl rand -hex 24)
docker compose -f deploy/docker-compose.yml up -d
# 界面 http://localhost:8080 —— 首次打开会让你创建管理员账号
```

**为什么未验证**：开发机没有 docker（计划 R9）。这份 Compose 文件是按规范写的，
但"干净机器一键起"这条验收**只能在有 docker 的机器上做**。所以：

- 本文不声称容器路线可用；
- 首次在有 docker 的机器上跑时，**预期的失败点**是：
  1. `uv sync` 在 `python:3.12-slim` 里需要编译工具（`sqlite-vec` 带原生扩展）——
     若失败，给 builder 阶段加 `apt-get install -y build-essential`；
  2. 卷权限：容器内以 uid 10001 运行，宿主机 bind mount 时要 `chown 10001`；
  3. 首启健康检查有 20s 宽限（`start_period`），慢盘上可能不够。

### 3.1 架构上的三个决定

1. **不直接暴露后端端口。** 所有流量从 nginx 进，
   避免"一半请求带 `X-Forwarded-*`、一半不带"的排查噩梦。
   需要直连调试时取消 compose 里那两行注释。
2. **前端由 nginx 提供，并把 `/api` 反代到后端。** 同源就没有 CORS 问题——
   生产上配错 CORS 是"本机好用、部署后全 401"的常见来源。
3. **`/api/` 反代关掉了缓冲**（`proxy_buffering off`）。对话是 SSE 流式，
   缓冲会让用户等整段回答写完才看到第一个字（后端也发了
   `X-Accel-Buffering: no`，两边都要）。

## 4. 可观测性：怎么判断"卡住了"

`GET /api/v1/tasks/health` 给出运行态总览；任务列表里每一项也带 `health`。

| 判据 | 含义 | 怎么算 |
|------|------|--------|
| `running` | 正常执行中 | 状态 RUNNING 且**租约未过期** |
| `stalled` | **可能卡住了** | 状态 RUNNING 但租约已过期——没有 worker 在续约 |
| `overdue` | 该跑没跑 | PENDING 且 `next_run_at` 已过去 10 分钟以上 |
| `idle` | 排队中 | PENDING 且还在正常等待 |
| `done` | 已结束 | SUCCEEDED / FAILED / CANCELED |

**为什么用租约过期而不是耗时阈值**：租约是 worker 主动心跳续的，
过期就意味着"没人认领这个任务了"——这是**确定的事实**。
而"跑了超过 N 分钟"只是启发式：一份 500MB 的 PDF 解析半小时是正常的，
用耗时阈值会一直误报，误报多了用户就不看这个标记了。

### 4.1 常见症状与处置

| 症状 | 多半是什么 | 怎么办 |
|------|-----------|--------|
| 任务一直 `idle` 排队 | 消费线程没开 | 确认 `KYLAB_RUN_WORKER=true` 并重启 |
| 任务变 `stalled` | 进程崩过 / 被 OOM 杀 | 重启服务；租约过期后任务会被回收重跑 |
| 任务 `overdue` | 同上，或调度没起来 | 看 `/tasks/health` 的 `worker_enabled` |
| 任务反复失败 | 解析器或模型凭据问题 | 看任务详情里的 `error`（含阶段名） |

## 5. 容量与并发（T7.3：**未实测**）

计划里 T7.3 要求"至少两档内存配置实测数据"。**这一项没有完成**，
原因与容器路线相同：本机没有可做对照测试的环境，而编一张表出来
比不给更糟——用户会照着它做采购决定。

**可以确定的（来自架构与实测运行）**：

- 主服务常驻内存约 **300–500MB**（架构 §4.1 的量级，与本地运行观察一致）；
- 纯云端解析路线（MinerU / PaddleOCR 都走 API）**4GB 内存的机器可跑**；
- 摄入的主要开销在**向量化与解析**，不在这个进程本身——
  所以并发档位实际上受"云端配额"与"网络"约束，而不是本地 CPU。

**要拿到实测数据，需要做的对照**（留给有环境的机器）：

1. 同一批文档（建议 ≥200 份、含 10 份以上大文件）；
2. 两档内存（4GB / 16GB）各跑一遍，固定 `KYLAB_WORKER_LEASE_SECONDS`；
3. 记录：端到端耗时、峰值内存、失败率；
4. 结论写成"档位 → 推荐并发数"，写进本文件。

在此之前，**不要**给用户一个猜测的并发数。

## 6. 升级与备份

- **数据全在 `KYLAB_DATA_DIR`**（默认 `backend/data/`，容器里是 `/data`）：
  SQLite 库、向量分区、对象存储（原文与 Markdown 产物）。
  升级只要替换代码/镜像，这个目录不动。
- **迁移是只增不改的**：`MIGRATIONS` 版本号连续，
  启动时自动补齐。降级不受支持（旧代码不认识新表）。
- **备份**：直接拷 `KYLAB_DATA_DIR`。SQLite 处于 WAL 模式，
  建议先停服务或用 `sqlite3 ... ".backup"`，避免拷到半个事务。
- **回收站**：删除的文档原文保留 7 天（`data/.trash/`），
  到期由 worker 的空闲维护清理。**要立刻释放空间就手动清空该目录**。
