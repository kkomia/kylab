# 笔记功能调研报告 v0.1（对标 ima 笔记）

- 日期：2026-09-13
- 范围：对标腾讯 ima「笔记」板块，调研用 Vue 3 + Python 后端实现时的开源借鉴方案
- 目的：**给出"哪些能力借哪个项目、以什么方式接入"的具体清单**，优先可快速落地的
- 关联文档：[知识库产品对标调研-v0.1.md](知识库产品对标调研-v0.1.md)（本报告不重复其内容，只在衔接点引用）

## 0. 一页结论

1. **ima 笔记的本质是"轻编辑器 + AI 写作 + 知识库联动"三件事**，不是一个独立笔记软件。kylab 已有知识库、对话（SSE 流式）、摄入流水线三大底座，笔记板块**只缺"编辑器 + 笔记数据模型 + 三个 AI 写作动作"**，其余全是复用。
2. **编辑器选 Tiptap（`@tiptap/vue-3`，MIT）**：官方一等 Vue 3 支持、headless 可完全套用现有设计令牌、Markdown 输出直接对接现有摄入流水线。备选 Cherry Markdown（腾讯开源，开箱即用但自带皮肤，与设计规范冲突）。**BlockNote 不可用**（仅 React）。
3. **AI 写作不买 Tiptap AI Toolkit（付费），自建三个动作**：AI 续写（ghost text + Tab 接受）、选中改写（润色/翻译/摘要）、问答存为笔记。后端全部走现有 `llm.py` 的流式通道加三个薄端点即可，参考开源实现 `anuchin/tiptap-ai-autocomplete`（ProseMirror Decoration 方案）。
4. **应用层项目（思源/Memos/AFFiNE/Joplin/Trilium）全部是 AGPL 系或重量级**，**不要引代码，只借交互与数据模型思路**；真正"快速接入"的是编辑器层（MIT/Apache）+ 自建薄后端。
5. **工作量估计**：P0（可用的笔记 CRUD + 编辑器 + 笔记入库）约 4–6 人日；P1（三个 AI 动作 + 标签）约 3–4 人日；P2（语音听记、思维导图、分享链接）各 2–3 人日，可按需裁剪。

## 1. ima 笔记功能拆解（对标基线）

来源：[ima 官网](https://ima.qq.com/)、App Store 页面、知乎/人人都是产品经理的评测（2026-09 检索）。按"实现代价"重排为三档：

| ima 能力 | 具体表现 | 对 kylab 的意义 |
|---|---|---|
| **快速记录** | 侧栏「笔记」入口，左上「+」新建；文字/语音/图片随手记 | 核心缺口，需要编辑器 + 数据模型 |
| **笔记编辑器** | 富文本在线编辑，图文混排 | 同上 |
| **AI 写作** | 续写、润色、翻译、摘要、基于知识库的长文写作 | 核心缺口，但可全部复用现有对话通道 |
| **知识库联动** | 在线笔记**一键加入知识库**成为可检索语料；AI 问答结果可**存为笔记** | kylab 独有优势：摄入流水线现成，ima 反而是闭源黑盒 |
| **搜读写闭环** | 搜（检索问答）、读（文档解析/摘要/思维导图）、写（写作）一站式 | 已有「搜」「读」，笔记补上「写」 |
| **收藏/剪藏** | 微信公众号文章、链接、本地文档导入 | 已有 RSS/HTML 数据源，加 URL 剪藏即可覆盖大半 |
| **语音听记** | 录音转文字成笔记 | P2，faster-whisper 或浏览器 Web Speech API |
| **组织与分享** | 标签/列表、搜索、个人/共享库、分享链接 | 标签要做；分享可复用现有 `share.py` 两档授权 |

**明确不做**（与产品定位冲突，来自对标调研第 3 条结论"单机零依赖是差异点"）：协作编辑（CRDT/Yjs）、云端多端同步、模板市场。

## 2. 候选开源项目总览

### 2.1 编辑器层（可直接引依赖 —— 快速接入的主力）

| 项目 | 许可证 | Vue 3 | 定位 | 快速接入度 |
|---|---|---|---|---|
| **Tiptap** | MIT（2025-06 起 10 个原 Pro 扩展也转 MIT） | 官方 `@tiptap/vue-3` | headless 富文本/块编辑框架（ProseMirror） | ★★★★★ |
| **Cherry Markdown** | Apache-2.0（腾讯开源） | 无官方包装，原生 JS 可直接挂 | 开箱即用 Markdown 编辑器 | ★★★★ |
| **Milkdown** | MIT | 官方 `@milkdown/vue`（+ Crepe 预设） | Markdown 优先、插件化（ProseMirror） | ★★★ |
| **Vditor** | MIT | 原生 JS | 三模式（所见即所得/即时渲染/分屏），中文文档 | ★★★ |
| **Editor.js** | Apache-2.0 | 社区包装 | 块状编辑、JSON 存储 | ★★ |
| ~~BlockNote~~ | MIT | **仅 React，2026 年仍无官方 Vue 支持** | Notion 式块编辑 | 不可用 |

来源：[Tiptap 开源页](https://tiptap.dev/open-source-to-platform)、[Tiptap Vue 3 文档](https://tiptap.dev/docs/editor/getting-started/install/vue3)、[HN：Tiptap 开源 10 个原 Pro 扩展](https://news.ycombinator.com/item?id=44202103)、[BlockNote 官网](https://www.blocknotejs.org/)、[Tencent/cherry-markdown](https://github.com/Tencent/cherry-markdown)、[Milkdown](https://milkdown.dev/)。

**结论：Tiptap。** 理由按权重排：

1. **headless = 零皮肤冲突**。kylab 前端自绘了全套无障碍控件与设计令牌（`AppSelect`/`ConfirmDialog`/颜色三级/圆角四档），Cherry/Vditor 自带 UI 皮肤必然打架，Tiptap 的菜单、气泡、占位符全部自己画，风格天然一致。
2. **官方 Vue 3 包 + 官方安装文档**，`useEditor()` 组合式 API 与现有 `composables/` 风格吻合。
3. **Markdown 序列化成熟**（`@tiptap/starter-kit` + markdown 扩展），存 Markdown 即可直通现有摄入/切块流水线——这是"笔记入库"零改造成本的关键。
4. ProseMirror 的 **Decoration 机制**是做 ghost text 续写的标准底座（见 §3.2）。

代价：要自己写工具栏（约 1 天，套现有按钮组件即可）；ProseMirror 学习曲线在"自定义节点"处，但笔记 MVP 用不到。

### 2.2 应用层（只借思路，不引代码 —— 全是 AGPL 系或重量级）

| 项目 | 许可证 | 技术栈 | 值得借的一点 |
|---|---|---|---|
| [Memos](https://github.com/usememos/memos)（~62k★） | **已从 MIT 改为 AGPL-3.0**（搜索可见新旧口径并存，按 AGPL 对待） | Go + React | "随手记时间线"交互：一条短记录 + 标签 + 可见性，是笔记入口页的最佳交互模板 |
| [思源笔记 SiYuan](https://github.com/siyuan-note/siyuan) | AGPL-3.0 | Go 内核 + TS | 块级数据模型（SQLite 每块一行）、笔记与文档统一存储的思路；**不抄代码**，只参考"笔记也是一种文档"的建模 |
| [AFFiNE](https://github.com/toeverything/AFFiNE) | AGPL-3.0 | Node + Yjs + BlockSuite | 本地优先 + 笔记即画布的形态参考；协作部分明确不做 |
| [Joplin](https://github.com/laurent22/joplin) | AGPL-3.0 | Electron + React | 置信度高的"笔记本-笔记-标签"三层模型 |
| [Trilium / TriliumNext](https://github.com/TriliumNext/Trilium) | AGPL-3.0 | Node | 树状笔记 + 属性系统，MVP 不需要 |
| [NoteGen](https://github.com/codexu/note-gen) | MIT（Tauri 桌面应用） | Tauri 2 + Next.js | **可借交互不可引依赖**（桌面端）：截图/剪贴板/碎片记录 → AI 整理成完整笔记的"碎片聚合"流程，适合 P2 抄交互 |

**共同教训**：这层项目没有一个是"能拆个模块出来给 Vue+FastAPI 用的"——要么 AGPL 传染、要么技术栈不搭。所以正确姿势是：**编辑器层用 MIT/Apache 的组件，应用逻辑自己写（本来就薄），交互照着 AGPL 项目的产品形态抄（交互不受版权保护）**。

## 3. 具体借鉴内容与接入方式

### 3.1 笔记数据模型（自建，参考 Joplin/思源的建模）

后端 SQLite 加两张表，纳入现有迁移机制：

```sql
-- notes
CREATE TABLE notes (
    id          TEXT PRIMARY KEY,          -- 沿用现有 ID 生成
    user_id     TEXT NOT NULL,
    kb_id       TEXT,                      -- 入库后指向知识库，NULL = 未入库草稿
    doc_id      TEXT,                      -- 入库后生成的文档 ID（反查用）
    title       TEXT NOT NULL DEFAULT '',
    content_md  TEXT NOT NULL DEFAULT '',  -- 唯一事实源：Markdown
    source_kind TEXT NOT NULL DEFAULT 'manual',  -- manual|chat|clip|voice
    source_ref  TEXT,                      -- chat 存会话/消息 ID，clip 存 URL
    pinned      INTEGER NOT NULL DEFAULT 0,
    created_at / updated_at
);
-- note_tags
CREATE TABLE note_tags (
    note_id TEXT NOT NULL, tag TEXT NOT NULL,
    PRIMARY KEY (note_id, tag)
);
-- 全文检索用 FTS5 虚表（title + content_md），知识库内的笔记检索复用现有混合检索
```

要点：

- **`content_md` 是唯一事实源**，Tiptap JSON 不落库（避免编辑器锁死数据，换编辑器零成本）。
- **笔记入库 = 写一个 `source_kind='note'` 的文档走现有 ingest 流水线**（`backend/app/services/ingest.py`），切块/嵌入/检索全复用，`doc_id` 回填实现"从检索结果跳回笔记编辑"。这是 ima"笔记加入知识库"的等价实现，也是本次接入性价比最高的一步。
- **问答存为笔记**：`source_kind='chat'` + `source_ref` 指向消息，前端在对话页加"存为笔记"按钮。

### 3.2 编辑器接入（Tiptap，前端唯一新依赖）

```bash
npm i @tiptap/vue-3 @tiptap/starter-kit @tiptap/extension-link \
      @tiptap/extension-placeholder @tiptap/extension-task-list @tiptap/extension-task-item
```

借鉴内容清单：

| ima 能力 | Tiptap 对应 | 接入说明 |
|---|---|---|
| 图文混排编辑 | StarterKit（标题/列表/粗斜体/代码块/引用） | 开箱即用 |
| 图片粘贴 | StarterKit Image | 粘贴后传现有上传接口，回填 URL |
| 待办清单 | TaskList/TaskItem | ima 笔记标配 |
| 空态引导 | Placeholder | "记录点什么…/按 / 唤起菜单" |
| 工具栏 | 自绘 | 套用现有 `components/ui/` 按钮与 `RowMenu`，约 1 天 |
| 选中气泡菜单 | `@tiptap/extension-bubble-menu`（MIT） | AI 改写菜单的挂载点，见 §3.3 |
| Markdown 存取 | `tiptap-markdown` 社区扩展或官方 serialize | 保存时 `editor.getMarkdown()` |

MVP 明确不引入：表格（ProseMirror 表格复杂度高，ima 移动端也不做表格编辑）、协同光标、斜杠菜单（P2 再说）。

### 3.3 三个 AI 写作动作（自建，复用现有 llm.py 流式通道）

Tiptap 官方 AI Toolkit 是付费产品，**不买**；以下全部用 MIT 组件 + 现有后端能力拼装：

**① AI 续写（ghost text + Tab 接受）**

- 前端参考开源实现 [anuchin/tiptap-ai-autocomplete](https://github.com/anuchin/tiptap-ai-autocomplete)：光标处用 ProseMirror **widget Decoration** 渲染灰色虚影文本，流式更新内容，**Tab 逐词接受 / Esc 取消**。核心思路三句话：Decoration 只做展示不改文档；SSE 每个 token 更新 decoration；接受时把 ghost 文本 `insertContent` 进文档。
- 后端：`POST /api/notes/{id}/complete`，请求体带光标前 ~2000 字上下文，**直接走 `llm.py` 的流式生成**（SSE 下发增量 token），prompt 约束"只输出接续内容，不要重复前文"。
- 防抖 800ms 触发，光标移动即取消当前流（现有对话页的停止逻辑可复用）。

**② 选中改写（润色/翻译/更短/更长）**

- 前端：BubbleMenu 挂 AI 子菜单 → 选动作 → 调 `POST /api/notes/{id}/rewrite`（SSE）→ 流式**替换选区**。替换用 `editor.chain().insertContentAt(selection, ...)`，实现时可参考 [Liveblocks 的 Tiptap AI Copilot 教程](https://liveblocks.io/blog/building-an-ai-copilot-inside-your-tiptap-text-editor)（diff/流式更新的通用讲法）。
- 后端：同一个薄端点按 `action` 参数换 prompt，零新依赖。

**③ 基于知识库写作（ima「搜读写」闭环的"写"）**

- 复用现有检索 + 引用体系：笔记页一个"引用知识库写作"开关，后端把**现有检索服务的前 k 条结果**塞进 prompt，回答里的 `[n]` 引用沿用对话页已有渲染。
- 这是与 ima 差异化最大的一点：ima 的知识库是黑盒，kylab 能让写作**带行内引用**。

### 3.4 收藏/剪藏（URL → 笔记，低成本补齐 ima"收藏"）

- 后端加 `POST /api/notes/clip`：传 URL → 拉取 HTML → `@mozilla/readability`（Python 版 `readability-lxml` 或后端用现有 HTML 清洗逻辑）提取正文 → 生成 `source_kind='clip'` 的笔记。
- 现有 RSS/HTML 数据源（`services/connectors/`）已有抓取与清洗代码，**抽公共函数即可**，预计 1 人日。
- 微信公众号文章抓取有反爬与合规风险，**不做自动抓取**，用"分享链接粘贴"路径覆盖。

### 3.5 前端信息架构（借 Memos 的时间线 + 现有收敛原则）

- 侧栏加第 5 项「笔记」，页面收敛为一个视图：顶部新建框（Memos 式随手记）→ 下方时间线列表（pinned 置顶 + 标签过滤 + FTS 搜索框）→ 点击进入编辑（路由 `/notes/:id`，沿用"状态放路径参数"的现有约定）。
- 遵守对标调研的告诫：**不要为了功能多把 5 页导航撑开**，笔记相关操作全部收在笔记页内。

## 4. 分期落地路线

| 阶段 | 内容 | 预估 | 依赖 |
|---|---|---|---|
| **P0 可用** | notes 两表 + CRUD API + FTS5 搜索；Tiptap 编辑器 + 自绘工具栏；时间线页；**问答存为笔记**；**笔记入库**（接 ingest 流水线） | 4–6 人日 | 无新后端依赖 |
| **P1 AI 写作** | ①续写 ghost text ②选中改写 ③引用知识库写作；标签过滤 | 3–4 人日 | Tiptap BubbleMenu |
| **P2 按需** | URL 剪藏；语音听记（faster-whisper 服务端或浏览器 Web Speech API，二选一先试后者）；分享只读链接（复用 `share.py`）；思维导图（`markmap` 渲染笔记大纲） | 各 2–3 人日 | whisper 视选型 |

验收口径建议：P0 结束时"对话里一条回答 → 存为笔记 → 加入知识库 → 检索命中并跳回笔记编辑"全链路可走通，即 ima「搜读写」闭环的最小复刻。

## 5. 许可证与风险

| 项 | 结论 |
|---|---|
| Tiptap / Cherry / Vditor / Milkdown | MIT / Apache-2.0，**可商用引依赖**，无传染风险；注意 Tiptap 个别高级扩展（AI Toolkit、Comments 等）仍是付费 Pro，只引 MIT 清单内的包 |
| 思源 / Memos / AFFiNE / Joplin / Trilium | AGPL-3.0，**只抄产品交互与数据模型思路，不复制源码**；Memos 的 MIT→AGPL 变更说明此类项目许可证会漂移，引依赖前每次核验 LICENSE 文件 |
| BlockNote | MIT 但仅 React，Vue 项目不可用 |
| Tiptap AI Toolkit / Liveblocks | 付费 SaaS，不引入；对应能力按 §3.3 自建 |
| 微信内容抓取 | 合规风险，只做用户主动粘贴的分享链接 |
| 语音识别 | 浏览器 Web Speech API 在 Chromium 上依赖在线服务；离线优先则选 faster-whisper（本地推理，符合"零中间件"定位，但多一个模型文件的部署项） |
