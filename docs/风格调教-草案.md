## 1. 这一轮改了什么

### 1.1 色彩（`src/assets/themes/`）

底色从暖调换成**干净冷调纸白**。理由：暖米白 + 衬线标题 + 陶土色强调是当下生成式设计最扎堆的一套，撞脸比个性更显廉价。

| 用途 | 浅色 | 深色 |
|------|------|------|
| 画布（侧栏/外框） | `#fafafa` | `#1b1b1a` |
| 表面（内容区） | `#ffffff` | `#232322` |
| 静态底（姓名牌、提示块） | `#f5f5f4` | `#262625` |
| hover / active | `#f2f2f1` / `#e9e9e7` | `#2c2c2a` / `#35352f` |
| 正文 / 次要 / 三级 | `#2f2f2c` / `#6b6b66` / `#9a9a95` | `#e6e6e3` / `#a0a09a` / `#74746e` |
| hairline / 分割线 / 强边 | `#ededec` / `#e3e3e0` / `#cfcfcb` | `#2e2e2c` / `#383836` / `#4a4a46` |
| 成功 / 警告 / 危险 / 信息 | `#3f7a58` / `#b96a10` / `#c0483f` / `#2f6f96` | `#5aa377` / `#d9873c` / `#d96a5f` / `#5b9dc4` |

新增 `--border-hairline`：绝大多数分隔线用它，比原来的 `--border` 更淡，整体不再"到处是线"。

### 1.2 排版与节奏（`src/assets/base.css`）

- 页面标题 24 → **26px**，负字距 `-0.01em`；正文行高 1.65。
- 引入 **`--space-*` 间距阶梯**（4/8/12/16/20/24/32/48/64）。铁律：间距只能用阶梯值，禁止随手写 7px / 13px——节奏一乱，"克制"就退化成"没对齐"。
- 圆角收到两档：控件 **4px**、浮层 **6px**（原来 6/8）。
- `.tabular` 工具类：数字一律等宽，分数/条数/页码沿一条竖轴对齐。
- 阅读宽度改用 `--measure: 66ch`（按字符数而不是固定 720px）。

### 1.3 知识库清单（概览页）

从**卡片网格**改成**排版行**：

- 左端 36px 姓名牌（名称首字）——给每行一个扫视锚点，不必逐字读；
- 中间两行：名称 15px/600、元信息 12.5px 三级灰；
- 右端"最近更新"右对齐，与其它页的数字列共用一条视觉竖轴；
- 行间只用一条 hairline，不用容器包围。

### 1.4 文档列表

- 行高 40 → **44px**，加**列头**（文件 / 切块 / 大小 / 更新时间）——右侧那串数字从此有名字，不必靠猜；
- 状态从独立列挪到**紧跟文件名**：状态是文件的属性，不该飘在右边当孤立列；
- 数字列（块数、大小、时间）等宽右对齐，形成真正的竖轴；
- 中点分隔的 `1 块 · 676 B` 拆成两列。

### 1.5 检索调试台

- 命中从**卡片**改成**引文块**：顶部一行是"来源 + 章节 + 页码"，右端是等宽分数；
- 正文 `max-width: 66ch`，命中超过 12 条时收成三行摘要；
- 通道信息从徽标改成普通文字（`向量 第 1 位`），去掉 `·` 连接；
- 通道耗时排成"名称 + 计数 + 耗时"三列对齐。

### 1.6 其它

- 空状态去掉 48px 装饰插画，只留一句标题 + 一句指路 + 操作；
- 页头默认不挂描述句（每个页面都挂一句解释性灰字，是模板感最常见的来源）；
- 侧栏去掉"知识库"小标题，导航项与知识库项统一 13.5px；
- 状态"进行中"改用**呼吸圆点**而不是旋转箭头，更安静；
- 弹层/菜单的阴影与遮罩抽成 `--shadow-popover` / `--overlay-scrim`（原先 4 处硬编码色值）。

## 2. 第二轮：把"克制"换成可核对的东西（2026-09-10）

第一轮的判断是对的（排版行、引文块、去掉装饰），但**方向对不等于做完了**。这一轮先量后改：
用 `.shots/audit.cjs` 把六个页面在双主题下渲染一遍，逐元素量了对比度、生效间距、命中尺寸。
结果不好看：**双主题共 126 处文字达不到规范自己写的 4.5:1**，另有 20 处间距落不到 4px 阶梯上。

根因只有两类，都在 Token 层：三级灰定得太浅，以及间距没有真的被阶梯管住。

### 2.1 对比度：规范 §2.4 写了 4.5:1，交付值却是 2.83:1

| 项 | 改前（浅色） | 改后 | 说明 |
|----|-------------|------|------|
| `--text-tertiary` | `#9a9a95` → **2.83:1** | `#6e6e68` → **5.13:1**（纸白）/ 4.92:1（画布） | 元信息、表头、页码、时间全靠它 |
| `--text-secondary` | `#6b6b66` → 5.19:1 | `#5f5f5a` → 6.42:1 | 顺带压深，拉开与三级灰的差 |
| `--text-primary` | `#2f2f2c` | `#2b2b28` | 标题与正文 |
| `--border-strong` 控件边框 | `#cfcfcb` → 1.56:1 | `#8f8f89` → **3.25:1** | WCAG 对**非文字**控件要求 3:1；输入框底是纯白，边框是唯一的可见边界 |

- **元信息从 12.5px 提到 12–13px**：层级现在由**字号**承担，不靠把字调淡到读不清。这是本轮最实质的一处观念修正。
- **分隔符曾经是隐形的**：`/` 与 `·` 用了 `--border-strong` 着色，浅色下 1.56:1、深色 1.77:1——那已经不是"淡"，是看不见。新增 `--separator` 用前景色，分隔符承载"两项并列"这条信息，属于内容。删掉 `.summary-sep`，统一成一个 `.sep`。
- **语义色在自己那层底上也要过**：`--status-warning #b96a10` 在白底 4.09:1（它是当文字用的，不合格）→ `#a45c0b` 5.10:1；危险色要同时过白底与 `--danger-soft` 浅红底 → 浅色 `#b8433b`、深色 `#e07a6f`（深色下反而要提亮，否则在自己那层浅红底上只有 4.25:1）。
- **深色三级灰比浅色更容易踩坑**：`#85857e` 在画布上 4.64:1 看着"过了"，但内容区底是更亮的 `--bg-surface`，那里只有 4.23:1。**深色必须按最亮的那个底算**，现在是 `#8f8f88`（4.59:1 表面 / 5.03:1 画布）。

### 2.2 字阶：原来"一切皆 600"

h1/h2 是 26/17、h3 与正文同名，除了页标题全是 600——**粗体到处都是，粗体就不再是重音**，"文档优先"也就无从体现。现在：

| 层级 | 规格 | 用在哪 |
|------|------|--------|
| 页标题 h1 | 28px / 600 / `-0.018em` | 全界面唯一的重音 |
| 内容小标题 h2 | 15px / 600 / `-0.005em` | 设置页分组、"切块预览" |
| 三级标题 h3 | 13.5px / 600 / 二级灰 | 预留 |
| 正文 | 14px / 400 | 文件名、命中正文 |
| 元信息 | 13px / 400 / 三级灰 | 数字列、标签 |
| 微标签 | 12px / 400 / 三级灰 | 列头、脚注 |
| 重点正文 | 15px / **500** | 命中来源、知识库名（原先 600，现在只加半档） |

### 2.3 间距：阶梯没有被真正管住

上一轮定了 `--space-*`，但没清干净。这轮把根因也修了：

- **基础重置漏了 `button { padding: 0 }`**：浏览器给 button 的默认 `1px 6px` 一直漏在每个自定义控件上，`1px / 6px` 这两个不在阶梯上的值就是这样散布到全站的。补齐后全站零偏离。
- 侧栏导航 / 知识库项：`padding: 5px` → `min-height: 36px / 32px`，落在 4px 阶梯上；
- 命中行、连接器行、面包屑、输入框（`min-height: 32px`，与按钮同高）、下拉框、复选框（16px）逐条对齐阶梯；
- 审计现在报告"网格外间距 0 条"，后面每次改完都能复验，不靠眼睛。

### 2.4 命中尺寸与键盘

- 文档行展开器 `20×20` → **24×24**（`--hit-target`）；toast 关闭按钮同样；
- 文档行 / 任务行的文件名链接**撑满整行高度**才够得着文字本身 23.1px 的目标；
- 顺手修了一个 CSS 具体度问题：`.row-main` / `.task-row` 的 `align-items` 会盖掉子元素单独写的 `align-self`，所以链接样式写进 `.row-main .row-name` 才生效；
- 新增全局 `:focus-visible` 焦点环——原来键盘 Tab 到侧栏或行内菜单上，没有任何可见反馈。

### 2.5 结构上的三处小改

- **概览页补了列头 + 两列数字**（文档数、最近更新）。第一轮右侧只有一个"最近更新"，孤零零一根；现在两列与列头共用列宽，才真的是一条竖轴，而且"文档数"是选哪个库的实际依据。数据按库一次列表请求聚合，不是逐文档 N+1。
- **任务中心补列头**：之前"第 2 / 5 次尝试"和 "2026-09-10 09:28" 挤在一起无从分辨，现在 列头 + 四列对齐。
- **检索台通道信息改三列网格**："向量 / 第 1 位 / 0.841" 沿一条竖轴排开（原来是一串会折行的文字）；会话历史**可点回看**，行尾显示命中数与"多久之前"，选中态用 hover 底 + 左侧 2px 而不是更深的 `--bg-active`（active 底会把三级灰压到 4.3:1）。

### 2.7 跑通真实链路时抓到的两个后端缺陷（已修）

为验收而把前后端真正跑起来（而不是只跑单测），暴露出两个只在真实数据下才现形的问题：

1. **中文文件名入库即乱码**：`Content-Disposition` 头只允许 latin-1，浏览器把 UTF-8 文件名的**原始字节**塞进去，服务端照 latin-1 解出来就是 `æž¶æž„è®¾è®¡.md`。
   修法是在 `IngestService.submit` 入口把这段字符串按 latin-1 编回字节、再按 UTF-8 解一次，**只在能成功还原时才采用**（`strict`），否则原样返回——
   纯 ASCII 名与已经正确的名字都不受影响。落点：`app/services/ingest.py::normalize_filename`。
   单测 `tests/unit/services/test_filename_normalization.py`（5 条）+ 集成测试 `test_upload_keeps_chinese_filename_readable`（手工构造浏览器那种报文体）。
2. **文档正文取不到**：`GET /documents/{id}/parts` 只有分片元信息，详情页无法显示任何正文，于是"Markdown 预览"这条规范条款一直悬空。
   新增 `GET /api/v1/documents/{id}/chunks?limit=N`：按 `ordinal` 升序返回切块，并给 `total` 让界面能说清"这是前 5 块，共 137 块"。
   存储层 `iter_chunks` 增加 `limit` 参数并把 `LIMIT` 下推到 SQL（预览不该把整份正文读进内存），service 层 `list_chunks` 先校验文档存在，
   所以"文档不存在"给 404，而不是与"还没切块"混成同一个空列表。

顺带记一笔环境事实：本机只有 Python 3.12，而 `pyproject.toml` 声明 `>=3.11`。
后端 433 条测试里 **`test_lease_loss_stops_the_worker_without_stealing_the_outcome` 在 3.12 下必失败**
（`asyncio.wait_for` 5 秒超时，且已用 `git stash` 在**未改动的原始代码**上复现），与本轮改动无关，属既有环境问题。
其余 **432 条通过**。

## 3. 第三轮：圆角、铺满、检索跟库走（2026-09-10）

你给的三条反馈都指向同一个毛病：**前两轮只做"减法"，没做"成型"**。
去掉卡片、去掉装饰、去掉圆角之后，界面确实不模板了，但也变成了"一条条直线 + 居中一栏"，
既不像文档，也不像工具。这一轮补回来。

### 3.1 圆角：从两档 4/6px 改成四档 6/8/10/12px

原来"全局克制，控件 4px、浮层 6px"的代价是**整屏全是直角**（见 §1.2 与 §2 的取值）。
圆角在这里不是装饰，是用来表达层级和"这块可以点"的：

| Token | 值 | 用在哪 |
|-------|-----|--------|
| `--radius-control` | 6px | 按钮、输入框、下拉、行内菜单项、侧栏导航项 |
| `--radius-row` | 8px | 列表行、姓名牌 |
| `--radius-panel` | 10px | **列表容器、命中引文块、元信息面板、切块预览块** |
| `--radius-overlay` | 12px | 弹窗 |

关键变化是**列表终于有了容器**：知识库清单、文档清单、任务清单不再是一排悬空的横线，
而是"一个圆角面板 + 面板内用 hairline 分行"。行 hover 时底色换成 `--bg-surface`，
整行连同圆角一起亮起来——这才像"这一行被选中了"，而不是"这一行的背景色变了"。

### 3.2 布局：取消居中，信息铺满

六个页面原先各写一套 `.page { max-width: 880~1040px; margin: 0 auto }`，
内容区一宽就两侧留大片空白，全是"居中一条"。现在统一成 `PageShell` 组件（`components/ui/PageShell.vue`）：

- **一律左对齐铺满**，宽度还给信息：概览 / 文档列表 / 任务中心的列表面板实测 **1144px**（1440 视口）；
- `narrow` 只给真正的阅读型页面（文档详情），正文仍然限宽 `66ch` —— **限宽是内容的事，不是整页的事**；
- 面包屑收进 `PageShell` 的 `#breadcrumb` 插槽，页面不再各自拼一遍；
- 内边距从 `32px / 64px` 收到 `24px / 48px`，顶到内容更快。

### 3.3 检索收进知识库：`SearchView` 页 → `KbSearchPanel` 弹窗

原来的「检索调试台」是个独立页面：要检索得先离开当前库、进检索台、再从一堆库里勾选。
但检索本来就是"**在这个库里查东西**"，用户的意图和位置是同一个东西。

- 新增 `components/search/KbSearchPanel.vue`，挂在知识库详情页，标题直接是"在「产品手册」中检索"；
- 入口是页头的一个按钮「在此库检索」，**检索是动作，不是常驻视图**，所以做成弹窗（980px 宽，左查询右命中）；
- 库的范围天然就是当前库，不用再勾选——少一个控件，少一次误操作；
- `views/SearchView.vue` 已删除；`/search` 保留为重定向到概览，旧书签不会 404；
- 侧栏去掉「检索调试台」导航项（导航从 4 项减到 3 项，更短更清楚）。

### 3.4 其它同步改掉的地方

- 姓名牌：原来是 `--bg-subtle` 实心块，在圆角面板里发闷，改成白底 + hairline 边框（8px 圆角）；
- 文档详情：元信息行与切块预览各装进一个圆角面板，整页不再是散落的标签；
- 表格列头不再挂下边框（面板自己有边界），列头只是"标签行"。

### 3.5 侧栏宽度改成动态比例（第三轮补丁）

原来 `--sidebar-width: 232px` 是固定值，在 1440 以上的窗口里明显偏窄。改成 **`clamp(248px, 18vw, 320px)`**：
随视口增长、有上下限，窄窗口不挤内容、宽窗口不发空。实测：

| 视口 | 侧栏 | 内容区 | 占视口 |
|------|------|--------|--------|
| 1024 | 248px | 776px | 24.2% |
| 1280 | 248px | 1032px | 19.4% |
| 1440 | 259px | 1181px | 18.0% |
| 1680 | 302px | 1378px | 18.0% |
| 1920 | 320px | 1600px | 16.7% |
| 2560 | 320px | 2240px | 12.5% |

同时 `--page-gutter` 也从固定 32px 改成 `clamp(20px, 2.4vw, 40px)`——窗口越大越不该"内容贴边"。
侧栏宽出来的空间放了**文档数列**（右对齐等宽），并补了「知识库」分区标签：
侧栏一宽，光靠留白就分不开"导航"与"知识库"两段了。

顺带把侧的 store 收口：知识库列表与文档数统一由 `stores/knowledgeBases.ts` 提供
（新增 `summaries` 状态与 `loadSummaries()`），侧栏与概览页共用一份，
不再各查一遍——原来侧栏和概览页各自请求一遍知识库列表。
`useCardGrid` 这个 getter 是卡片网格时代的遗留（形态已改列表行），一并删掉。

### 3.6 第四轮：把"素"补成"实"（2026-09-10）

### 3.9 第六轮：加两套颜色，并把热力图方块改正（2026-09-10）

你的判断是准的：**"克制"做到了，"有颜色"没做到**。整站只有灰阶 + 三个被压得很灰的语义色，
读起来像终端而不是产品。这一轮按调研结果补两套色系，并把活跃度方块改成正方形。

#### 色系怎么定的（先调研，再算对比度）

参考了 [Linear 的设计系统](https://raw.githubusercontent.com/Khalidabdi1/design-ai/refs/heads/main/design-md/linear/DESIGN.md)
（公认"克制但有颜色"的样板，它的原则是 *let the accent guide action, not dominate the whole page*）
与 [Material for MkDocs 的配色做法](https://squidfunk.github.io/mkdocs-material/setup/changing-the-colors/)：
**主色只出现在"动作、当前位置、数据"三处**，其余仍然是灰阶。

| | 主色 indigo | 副色 青蓝 |
|---|---|---|
| 浅色 | `#5e6ad2`（控件/图表，白底 4.70:1）· `#4f5ac7`（**当文字**用，5.80:1） | `#1f7a8c`（4.98:1） |
| 深色 | `#8f9bff`（深表面 6.22:1） | `#5fbdcc` |
| 用途 | 主按钮、焦点环、链接、侧栏选中、趋势折线、活跃度色阶 | 第二组数据（文件类型分布等），避免两张图一个色 |

选 indigo 而不是常见的蓝：它比纯蓝多一点紫、少一点"企业 SaaS 蓝"的味道；
副色选青蓝而不是陶土/琥珀——后者与项目已淘汰的"暖米白 + 陶土强调"那套撞脸。

**一个新 Token 顶两处细节**：`--accent`（当底/当图）与 `--accent-text`（当文字）**是两个值**。
深色主题下最明显：提亮到 `#8f9bff` 当文字很舒服，但白字压上去只有 3.79:1，
所以按钮底色另取更深的 `#5560c4`（5.45:1）。

#### 活跃度方块：改正成正方形（第二轮修正）

上一轮那版是错的，而且**错了三次才量对**——记在这里，因为每一处都是"看着像对的"：

| # | 症状 | 真正的原因 | 修法 |
|---|------|-----------|------|
| 1 | 格子是长方形（实测 60×16px） | 我从没告诉 ECharts 格子多大，它按容器**双向拉伸**填满绘图区 | 基座加 `squareCells`：给固定 `cellSize`（ECharts 便不再拉伸），再由"列数 × 边长"反推绘图区宽度与高度 |
| 2 | 空值格子连成一大片实心矩形 | 我用 `borderColor: 'transparent'` 当缝隙——**透明边框挡不住相邻格子的填充** | 缝隙改用**底色**（`--bg-canvas`）画；`gap` 作为参数从基座下发 |
| 3 | 图形只占面板 1/3，断在中间 | 列数与面板宽度不匹配：18 列铺满 1100px 要 63px/格（太大），20px/格又只占 1/3 | 写了个扫描脚本（`.shots/heatmap-sweep.cjs`）一次量 12 组组合，按数据选 |

**扫描结果**（面板约 1100px，目标：格子 10–14px、图形占面板 35%–70%）：

| 窗口 | 列数 | 格子 | 图形宽 | 占面板 |
|------|------|------|--------|--------|
| 90 天 | 17 | 12px | 198px | 18%（缩在角落） |
| 180 天 | 32 | 12px | 380px | 34% |
| **365 天** | **62** | **12px** | **744px** | **67%（选定）** |

窗口从 120 天改成 **365 天**是跟着这个结论走的：一年也是这类图（GitHub 贡献图、Kimi 亲密度图）的惯例刻度。
另外月份刻度改成"只标当月开头那一周"、一列只有一个标签——
同一周跨月时后一个月必然省略，这是固有现象不是 bug（一年里约 2–3 个月会省略）。

色阶也从"`color-mix()` 现场算"改成**主题里给死四档** `--heat-0…3`，
并改为**离散分档**：连续映射会把"1 篇"和"2 篇"压成同一个色，而实例数据里这两者必须看得出区别。

这已经是同一个坑的第三次（`var()`、`structuredClone`、`color-mix()` 都是"canvas 不认"），
所以 `EChart.vue` 的注释里把三条并列写清楚了。

#### 顺带提纯了语义色

原来的成功色 `#3b7353` 发灰。既然要颜色，语义色也该是**真的绿/琥珀/红**，
只是明度仍然按对比度定：成功 `#2f7d4f`（白底 5.04:1）/ 深色 `#63b183`。

### 3.12 第八轮：外部评审（Kimi）意见处置（2026-09-10）

**这一轮改了什么**：

1. **禁用态不再用 `opacity`**。白字压在 50% 透明的 indigo 上，按 `color`/`background-color`
   算出来是 4.70 的「合格」，按**渲染后的真实像素**只有 **2.02:1**。改成实色
   （灰底 + 三级灰字 + 1px 边框），修后实测 **5.14:1**。这是评审里最有价值的一条。
2. **统计卡改成 3 列**（6 = 3×2）。原来 `minmax(180px, 1fr)` 在 1440 视口下正好排出 5 列，

3. **知识库卡片 `auto-fill` → `auto-fit`**。`auto-fill` 会**保留空轨道**，

   `auto-fit` 才会折叠空轨道。修后 2 张卡各 550px 铺满整行。
4. **「尚未开放」占位横幅改成真入口**。对话已经通了，留着禁用按钮就是在陈述一个不成立的

5. **统一弹窗高度**：`AppModal` 新增 `height="hug|tall|full"`，滚动只发生在内容区，
   标题栏与底部按钮常驻。设置弹窗用 `tall`，切换分组时高度稳定在 720px 不再跳动。
6. **「尝试」列改为「尝试次数」**，成功行也照实显示 `1 / 5`——同一列只有一个含义。
7. **三级灰整体压深一档**（浅 `#6e6e68`→`#5f5f59`，深 `#8f8f88`→`#9a9a93`）。
   起因是设置弹窗左菜单选中项里的 12px 副标题只有 4.22:1；与其反复调底色，
   不如让这一级本身留出余量。

**本轮抓到一个我自己引入的回归（很隐蔽，值得记）**：给 `.modal` 写 `display: flex`
实现统一高度后，**未打开的弹窗也开始渲染**——浏览器靠
`dialog:not([open]) { display: none }` 隐藏关闭的弹窗，而作者样式优先级高于 UA 样式。
于是「设置」和「新建知识库」两个弹窗叠在了每个页面正文上。
`document.querySelectorAll('dialog[open]').length` 依然是 0，**只有看截图或量 rect 才会发现**。
修法：`display: flex` 写到 `.modal[open]` 上。

**审计工具本身也补了两个盲区**（比改样式更重要）：

1. **不读 `opacity`**：只按 `color`/`background-color` 的 alpha 计算，禁用态一律假合格。
   现在累积元素自身与所有祖先的 `opacity` 再算有效色。
2. **不扫弹窗**：弹窗默认是关的，所以前几轮审计从未看见设置弹窗里的 4.22:1。
   现在显式打开弹窗再扫。合计覆盖 **1732 个元素 × 双主题，不达标 0**。

另外把「刻意脱离 4px 阶梯」做成**必须逐条声明理由**的清单（`DECLARED_OFF_GRID`），
报告里与「未声明」分列。现在知识库卡片的 `.stat` 与设置菜单的 `.nav-entry` 共 24 处
已声明、**未声明 0 处**——全过滤掉会让「故意的」和「写错的」再也分不出来。

### 3.13 成对间距进令牌（2026-09-10，收尾）

上一条的白名单机制再往前走一步：把「刻意紧贴的 2px」变成**设计令牌**
`--space-pair`，而不是靠选择器白名单兜着。

| 项 | 内容 |
|----|------|
| 新令牌 | `--space-pair: 2px`（`base.css`），注释写明**唯一允许脱离 4px 阶梯**，且用途限定在"主标题+副标题""大数字+小标签"这类必须读成一个整体的两行 |
| 迁移 | `KnowledgeBasesView .stat`、`SettingsModal .nav-entry` 改为 `gap: var(--space-pair)`；全库已无手写 `gap/margin/padding: 2px` |
| 审计判据 | 从"选择器在白名单里"改为**"实算值等于令牌值"**：读 `--space-pair` 的 computed 值再比对。白名单只留真正的一次性例外（当前为空） |

改判据的理由：选择器白名单只认"哪个元素"，不认"为什么"，而且要人肉维护；
认令牌之后，写 `var(--space-pair)` 是有据可依的刻意紧贴，手写 `2px` 仍然照报。
实测知识库列表页 12 处偏离全部归因为 `--space-pair（成对文本，2px）`，未声明 0 处。

**没有**进令牌的一处：`ChatView` 流式光标的 `margin-left: 2px` 是**光学对齐**
（让光标贴着最后一个字），不是间距节奏，给它套 `--space-pair` 会误导。
