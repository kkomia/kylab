# 主流大模型「思考模式」调研与落地（v0.1）

日期：2026-09-12  
对应实现：`backend/app/services/thinking.py`、迁移 v16、对话输入框的思考开关与强度。

## 1. 结论先行

主流对话模型**都支持"开/关思考"，多数支持"思考强度"**，但**参数名与取值没有任何统一**——
同一个 OpenAI 兼容协议下，各家自己加字段。因此不存在"发一个字段就能通吃"的做法；
本产品按**供应商方言**翻译同一组语义（开关 + 低/中/高三档强度）。

**默认开启思考**：主流模型默认就思考，关掉是例外。产品把"思考"作为默认态，
输入框另给一个显式开关供临时关闭。

**一个实测到的坑（本功能存在的直接原因）**：DeepSeek 的 OpenAI 兼容端点**接受
`enable_thinking` 但完全忽略它**——传 `false` 时 `reasoning_content` 照样有内容。
旧版全局开关对 DeepSeek 实际上是个"假开关"。真正能关掉的是 `thinking: {type: disabled}`。

## 2. 各家参数对照

| 供应商 / 方言 | 开关 | 强度 | 备注 |
| --- | --- | --- | --- |
| DeepSeek | `thinking: {type: "enabled"｜"disabled"}` | `reasoning_effort: low｜medium｜high` | 实测 `enable_thinking` 被忽略；`thinking.type=disabled` 后 `reasoning_content` 长度为 0 |
| Qwen / 百炼（DashScope） | `enable_thinking: bool` | `thinking_budget: int`（思考 token 上限，默认模型最大值） | 另有提示词后缀 `/think`、`/no_think` |
| OpenAI（GPT-5 / o 系） | 无真正的"关" | `reasoning_effort: minimal｜low｜medium｜high` | 关思考只能退到最低档，故关闭时不发该字段（等同模型默认） |
| 智谱 GLM | `thinking: {type: "enabled"｜"disabled"}` | 文档未提供独立强度参数 | GLM 的默认值为 `enabled` |
| 月之暗面 Kimi | `thinking: {type: "enabled"｜"disabled"}`（k2.6） | k3：`reasoning_effort: low｜high｜max` | k2.7-code 只接受 `enabled`（永远思考）；k3 无 `thinking` 参数、永远推理 |
| Google Gemini 2.5 | `thinking_config.thinking_budget`（0 = 关） | 同左（token 数） | `include_thoughts` 控制是否回传思考内容 |
| Gemini 3 | 同 config | `thinking_level: low｜high`（Flash 另有 minimal/medium） | 用档位而非 token 预算 |
| Anthropic Claude | `thinking: {type: "enabled", budget_tokens: N}`，不传即关 | `budget_tokens` | `budget_tokens` 必须小于 `max_tokens` |

## 3. 本产品的归一化与翻译

界面只暴露两件事，其余交给后端：

- **思考**：开 / 关（布尔）
- **思考强度**：低 / 中 / 高（归一化为 `low` / `medium` / `high`）

后端 `services/thinking.py` 按"方言"把它们翻译成上面那张表里的字段，**只发该家认识的字段**：
- 方言识别顺序：模型 `options.thinking_dialect` 显式覆盖 → 主机名 → 模型名特征 → 兜底；
- 兜底（未知供应商）只发 `enable_thinking`（旧行为），**不给不认识它的端点发新字段**，
  避免把请求打成 400；
- 强度到 token 预算：低 1024 / 中 4096 / 高 16384；
- 少数映射：Kimi k3 的 `medium → high`（其取值为 low/high/max）、
  Anthropic 的 `budget_tokens` 收敛到 `< max_tokens`、Gemini 3 用档位而非预算。

**默认值**：`llm.enable_thinking` 默认 `true`、`llm.thinking_effort` 默认 `medium`；
`llm.max_tokens` 默认从 1024 抬到 **2048**——思考内容也占回复预算，1024 常出现
"想完了、没有正文"。显式改小的部署不被强制覆盖，只给可读错误提示。

## 4. 落点与优先级

三层，优先级由高到低：

1. **请求级**：对话输入框的思考开关与强度（随会话保存，见迁移 v16 的
   `conversations.thinking` / `thinking_effort`）；
2. **模型级**：注册模型的 `options.enable_thinking` / `thinking_effort` / `thinking_dialect`；
3. **全局级**：设置 → 对话模型里的「思考模式」与「思考强度」。

`None` 与 `false` 严格区分：`None` 是"没表态、逐级回退"，`false` 是"明确关掉"。

## 5. 已知边界

- OpenAI 系没有真正的关闭，关闭时本产品不发字段（等同模型默认），界面上的"关"对它只是"不额外干预"；
- 非 DeepSeek 方言未在本地逐家实测（无对应凭据），参数以官方文档为准；
  猜错时可在注册模型的 `options.thinking_dialect` 写一个明确值掰回来；
- 强度到 token 预算的对应是产品口径（1024/4096/16384），不是各家的官方档位换算。
