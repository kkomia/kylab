## 1. 一条判定规则

**页面承载"你要看的东西"，弹窗承载"你要做的一件事"。**

| | 常驻页面 | 弹窗 |
|---|---|---|
| 承载 | 清单、状态、持续变化的产物 | 一次性动作、需要专注的表单、旁支详情 |
| 判定问句 | 用户会不会**反复回来看它**？ | 用户是不是**做完就走**？ |
| 生命周期 | 路由可达、可刷新、可分享 URL | 关掉即结束，不占路由 |
| 失败代价 | 看得见、可重试 | 必须把错误留在弹窗里，不能只发个 toast 就关掉 |

三条推论：

1. **不新增全局页面，除非它自己是一份清单。** 现在只有四个页面：概览、知识库详情、文档详情、任务中心、设置——已经是上限了；
2. **动作一律弹窗**：检索、上传、新建。它们都是"在某个上下文里做一件事"，做成页面就得让用户先导航过去、再选上下文；
3. **旁支详情用弹窗，主链详情用页面**：任务的错误详情是旁支（看完就关），文档内容是主链（要读、要分享、要刷新）。

### 2.1 侧栏下半部分不是"第二个知识库入口"（本轮修正）

侧栏的结构按参考图定为三段，**下段是对话的位置，不是知识库列表**：

```
┌──────────────────┐
│ 产品名            │
│ ── 主导航 ──      │  概览 / 知识库 / 任务中心
│                  │
│ ── 最近 ──        │  ← 对话与会话记录的位置
│   …（当前放真实   │     知识库**只**通过上面「知识库」标签进
│     的最近文档）   │
│ ── 底部 ──        │  设置 / 主题
└──────────────────┘
```

同一个东西只在**一个**地方有入口，是这条修正的核心：此前侧栏有知识库列表、
「知识库」标签又是一个页面，两个入口做同一件事，还各自维护一份列表。
现在侧栏那份撤掉，知识库只有卡片页一个入口。

`最近` 区当前先放**真实的最近文档**（来自已经加载的 `listDocuments` 结果，
不额外发请求）——不是为了占位，而是因为对话功能（检索式问答）落地后
这一整块会换成会话列表，位置与结构都不用动。

## 3. 设置页：只读一目了然，编辑进弹窗

凭据从 `.env` 搬到运行期配置（落 SQLite `app_settings`）之后，设置页要回答两个不同的问题：

- **"现在配的是什么、通不通？"** → 这是状态，**直接显示**（卡片 + 状态徽标 + 模型名 + 维度 + 是否已配密钥）；
- **"我要改它。"** → 这是动作，**进弹窗**（密钥输入、参数、测试连接）。

所以设置页的形态是：

```
设置
├─ 检索与向量  ← 一组卡片，直接显示
│   ├─ embedding（SiliconFlow / BAAI/bge-m3 / 1024 维）   [在线 · 延迟 210ms]  [编辑]
│   └─ rerank（未配置）                                                  [编辑]
├─ 文档解析    ← 一组卡片，直接显示
│   ├─ MinerU（已配置 · 标准 API · 每日 1000 页优先）    [测试通过]        [编辑]
│   └─ PaddleOCR（已配置 · PaddleOCR-VL-1.6）             [未测试]        [编辑]
├─ 存储与服务  ← 只读信息，直接显示（无需编辑）
└─ 尚未开放    ← 如实标注（访问鉴权等）
```

**密钥的显示口径**：接口**永不回显明文**，只回显形如 `sk-xu…ten` 的掩码与"是否已配置"；
弹窗里输入框留空表示"不改动"，填新值才覆盖。这条同时满足"用户能确认配得对不对"和"密钥不出库"。
