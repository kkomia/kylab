## 0. 本版的由来与"哪个数算数"

前三轮调教留下了两份草案（`风格调教-草案.md`、`界面信息架构-草案.md`）。
本版把它们并入正文，草案随即删除——**同一件事只有一个地方写**。

有一类问题贯穿三轮，值得单独说明：**规范写了 4.5:1，交付值却是 2.83:1**
（§2 详述）。根因不是有人偷懒，而是"规范里写的是目标值，代码里填的是取色时的直觉值"，
两者从来没有被放在一起比对过。所以本版的一条总纪律是：

> **凡是能测的条款，都写出实测值；没有实测值的条款不写。**

`.shots/` 下的审计脚本（`contrast-check.cjs` 等）是这些数字的来源，可随时复跑。
**规范与交付一旦分叉，以实测为准**——不对就改代码，改不动就改条款并写明代价。

## 1. 设计原则

1. **内容即界面**：去掉多余的壳与装饰，知识库内容本身就是界面。控制台不是仪表盘，不堆卡片和图表。
2. **以灰阶建立文字层级**：标题、正文、注释用明度分级；关键状态（失败/警告/成功）才使用有含义的颜色。
3. **细分割线配合留白分区**：1px 细线分段，文档像一张稿纸放在灰桌上，边界浅但清楚；复杂表格与输入控件可用更明确的边框。
4. **次要操作按需出现**：hover / 键盘聚焦时显示；触屏与键盘用户必须能找到同一入口（不只依赖 hover，提供可见的 `⋯` 按钮或焦点态）。
5. **全程禁止 emoji**（对 Notion 官方风格的覆盖）：界面、图标、空状态插画、状态标记、通知文案一律不使用 emoji。Notion 风中"emoji 作页面图标"的做法在本项目一律以内联 SVG 替代。
6. **形态随数据量**：同一种对象在不同规模下换形态，不要一套容器用到底——条目少（容器型对象）用**卡片网格**，条目多（条目型对象）用**列表**。判定条件与做法见 §5.1。
7. **动作不进页面**（v0.4 新增，见 §10）：页面承载"你要看的东西"，弹窗承载"你要做的一件事"。**页面的数量不设上限**，但"动作"不许做成页面。

## 2. 主题系统（黑白双主题，参考 Kimi）

两种主题均为**近白 / 近黑的克制灰阶**，不做高饱和品牌色铺底。主题跟随系统，可手动切换，切换按钮放侧栏底部。

### 2.1 浅色主题（Light）——实测值

| Token | 值 | 对比度 | 用途 |
|-------|-----|--------|------|
| `--bg-canvas` | `#FAFAFA` | — | 页面底层画布 |
| `--bg-surface` | `#FFFFFF` | — | 内容区 / 卡片 / 弹层 |
| `--bg-subtle` | `#F5F5F4` | — | 次级容器底（元信息面板、禁用块） |
| `--bg-hover` | `#F2F2F1` | — | 行 hover、菜单项 hover |
| `--bg-active` | `#E4E4E1` | — | 选中项（侧栏当前库等） |
| `--text-primary` | `#2B2B28` | 14.2:1（白底）/ 13.6:1（画布） | 标题、正文 |
| `--text-secondary` | `#5F5F5A` | 6.42:1 / 6.15:1 | 注释、元信息 |
| `--text-tertiary` | `#5F5F59` | **6.43:1 / 6.16:1** | 占位、表头、页码、时间 |
| `--border-hairline` | `#EDEDEC` | — | 1px 细分割线 |
| `--border-strong` | `#8F8F89` | **3.25:1（白底）/ 3.12:1（画布）** | 表格、输入框边框 |

> 三级灰 `#5F5F59` 与二级灰 `#5F5F5A` 只差一个色阶（1/255）——它们**实际几乎同色**，
> 层级靠 §4.2 的字号区分，不靠明度。这一处是刻意的：把三级灰继续调淡就会跌破
> 4.5:1，而"读不清的元信息"比"层级不明显"更糟。

### 2.2 深色主题（Dark，参考 Kimi 深色）——实测值

| Token | 值 | 对比度 | 用途 |
|-------|-----|--------|------|
| `--bg-canvas` | `#1B1B1A` | — | 页面底层画布 |
| `--bg-surface` | `#232322` | — | 内容区 / 卡片 / 弹层 |
| `--bg-subtle` | `#262625` | — | 次级容器底 |
| `--bg-hover` | `#2C2C2A` | — | 行 hover |
| `--bg-active` | `#2F2F2A` | — | 选中项 |
| `--text-primary` | `#E8E8E5` | 12.81:1（表面）/ 14.04:1（画布） | 标题、正文 |
| `--text-secondary` | `#A6A69F` | 6.42:1 / 7.04:1 | 注释、元信息 |
| `--text-tertiary` | `#9A9A93` | **5.56:1 / 6.09:1** | 占位、表头、页码、时间 |
| `--border-hairline` | `#2E2E2C` | — | 1px 细分割线 |
| `--border-strong` | `#6F6F69` | **3.11:1（表面）/ 3.41:1（画布）** | 表格、输入框边框 |

> **深色必须按最亮的那个底算。** 深色下 `--bg-surface` 比 `--bg-canvas` 更亮，
> 所以每个前景色都要按表面算一遍——历史上有颜色在画布上 4.64:1"看着过了"，
> 在表面只有 4.23:1。上表两列数字就是为这件事留的。

### 2.3 语义色（双主题，全部按"当文字用"的标准取）

| 语义 | Light | Dark | 用途 |
|------|-------|------|------|
| 成功 / 已索引 | `--status-success` | `--status-success` | 任务完成、文档 indexed |
| 警告 / 卡住 / 已禁用 | `--status-warning` | `--status-warning` | 任务标黄、块被禁用、额度将尽 |
| 失败 / 错误 | `--status-danger` | `--status-danger` | 解析失败、token 过期 |
| 信息 / 处理中 | `--status-info` | `--status-info` | 任务进行中、链接 |

- **语义色只用于状态传达**，不用于装饰。正文、标题、背景保持灰阶。
- **它们要过自己那层底，不只是过白底**：危险色同时出现在 `--danger-soft` 浅红底上，
  所以深色下反而要**提亮**（`#E07A6F`），否则在浅红底上只有 4.25:1。
- 状态**必须双编码**（图标/颜色 + 文字），见 §8。

### 2.4 实现约定

- 主题用 CSS 变量 + `data-theme="light|dark"` 切换；图片/SVG 图标全部走 `currentColor`，随主题自动变色；
- **所有文字/背景组合对比度 ≥ WCAG AA（正文 4.5:1，大字 3:1）**；非文字控件边界 ≥ 3:1。
  当前四页 × 双主题审计 **不达标 0 处**（`.shots/contrast-check.cjs` 可复跑）。
- 禁止纯黑 `#000` 与纯白文字直撞（Kimi 式柔化处理：深色文字用 `#E8E8E6` 而非 `#FFF`）。
- **层级由字号承担，不靠把字调淡到读不清**——这是三轮调教里最实质的一处观念修正（见 §4）。
- **分隔符属于内容**：`/` 与 `·` 曾经用 `--border-strong` 着色，浅色下 1.56:1——那已经不是"淡"，是看不见。
  现在统一走 `--separator`（前景色）。

## 3. 图标系统（全 SVG，零 emoji）

| 规则 | 说明 |
|------|------|
| 来源 | 统一内联 SVG（不引 iconfont、不用图片图标、不用 emoji） |
| 基准库 | **Remix 图标集合**（Apache-2.0，可商用；24×24 网格），统一一套不混用 |
| 呈现 | **填充式线稿**（`fill="currentColor"`）。Remix 的 "line" 系列以填充路径绘制线稿，视觉仍是线性单色；16px 下比描边更稳定（描边缩放会忽粗忽细） |
| 资产位置 | `frontend/src/components/icons/Icon<名称>.vue`，全部经 `IconBase` 渲染 |
| 尺寸 | 16 / 20 / 24 三档；侧栏菜单 16，按钮内 16，空状态可用 48 线稿 |
| 颜色 | 一律 `currentColor`，不硬编码色值 |
| chrome 图标 | 关闭 / 对勾 / 折叠箭头 / 加减 / 太阳 / 月亮取 Remix 同库同名图标（`close-line`、`check-line`、`arrow-*-s-line`、`sun-line`、`moon-line`…），不得手绘另一套 |
| 品牌标 | `IconLogo` 是**刻意例外**：品牌标要保持辨识度，不混进通用图标。v0.9 起为正式字标 `KYLAB`（用户提供）：去掉原画布留白、`fill` 用 `currentColor`、高度由 `size` 控制宽度按比例算；**`fill-rule="evenodd"` 必须逐条留在 path 上** |
| 文件类型图标 | 暂用通用文档图标；细分类型（PDF/DOC/表格/MD/图片/RSS）在需要时取 Remix 同库补齐 |
| 状态指示 | 优先"SVG 图标 + 文字"，不用色点单独表意 |
| 进行中 | **呼吸圆点**而非旋转箭头——更安静，长时间注视不累 |

**Emoji 禁令的执行范围**：UI 组件、空状态、错误提示、通知、文档内容渲染层的默认装饰。
用户自己文档内容里的 emoji 属于数据，照常渲染。

**执行机制**：`scripts/scan_emoji.py`（全仓扫源码）+ ESLint 规则 `kylab/no-emoji`（写代码时就报），二者都在门禁里。

## 4. 字体与排版

### 4.1 字体栈

| 项 | 规范 |
|----|------|
| 中文 | `"PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif` |
| 西文/数字 | `"Inter", system-ui`（数字等宽场景用 `tabular-nums`） |
| 代码/路径 | `"JetBrains Mono", "SF Mono", Consolas, monospace` |

### 4.2 字阶（六档，实测口径）

| 层级 | 规格 | 用在哪 |
|------|------|--------|
| 页标题 h1 | 28px / 600 / `-0.018em` | **全界面唯一的重音** |
| 内容小标题 h2 | 15px / 600 / `-0.005em` | 设置页分组、"切块预览" |
| 三级标题 h3 | 13.5px / 600 / `--text-secondary` | 预留 |
| 正文 | 14px / 400 | 文件名、命中正文 |
| 元信息 | 13px / 400 / `--text-tertiary` | 数字列、标签 |
| 微标签 | 12px / 400 / `--text-tertiary` | 列头、脚注 |
| 重点正文 | 15px / **500** | 命中来源、知识库名 |

> **原来"一切皆 600"**：h1/h2 是 26/17、h3 与正文同名，除了页标题全是 600——
> 粗体到处都是，粗体就不再是重音。**600 只留给页标题与内容小标题**；
> "重点正文"原先也是 600，现在只加半档（500）。

### 4.3 字号可调（v0.4 新增）

用户在「设置 → 外观」可选四档字号，做法是给根元素设 `--font-scale` 乘数，
**所有文字令牌都乘它**：

| 档位 | `--font-scale` | 正文实算 |
|------|----------------|---------|
| 小 | 0.875 | 14px |
| 中（默认） | 1.0 | 15px |
| 大 | 1.1 | 16.5px |
| 特大 | 1.2 | 18px |

- **硬约束：微标签在最小时也不得低于 12px**（可读性下限，不是偏好）；
- 档位由**生效的 `--font-scale` 反推**（`useFontScale.readApplied()`），
  不另存一份状态——两处各读一次 localStorage 会让"页面渲染一个档、选择器高亮另一个档"（实测踩过）；
- 首屏由 `index.html` 的内联脚本在**首次绘制前**设好 `data-theme` 与 `--font-scale`，避免闪一下。

### 4.4 内容宽度

- **限宽是内容的事，不是整页的事**：阅读类内容（文档正文、回答）限宽 `66ch`；
  数据表格 / 任务列表 / 卡片网格铺满。
- 页头默认**不挂描述句**——每个页面都挂一句解释性灰字，是模板感最常见的来源。

## 5. 布局骨架

```
┌──────────────────────────────────────────────────┐
│  侧栏 240px              │  内容区（铺满，左对齐）    │
│  ─ 产品名（SVG logo）     │  ─ 面包屑（可选）          │
│  ─ 导航项 ×4             │  ─ 页标题 + 次要操作       │
│  ─ 会话列表（下半区）     │  ─ 内容                   │
│  ─ 使用者 / 主题 / 状态   │                          │
└──────────────────────────────────────────────────┘
```

- 侧栏：`--bg-canvas` 底，选中项 `--bg-active` + 左侧 2px 指示条；
- 内容区：`--bg-surface`；
- 整体无卡片堆砌；分区靠留白 + 细线，不靠阴影和圆角大卡片。

### 5.1 形态选择：卡片网格 vs 列表

| 条件 | 形态 | 典型对象 |
|------|------|----------|
| 条目 ≤ 12，且一屏可看全（无分页需求） | **卡片网格** | 知识库、数据源等**容器型**对象 |
| 条目 > 12，或需要排序 / 筛选 / 批量操作 / 分页 | **列表**（含极简表格） | 文档、chunk 命中、任务、会话等**条目型**对象 |

- **判定依据是"要不要扫描比较"，不是数字本身**：要在一屏内做"选哪一个"的决策 → 卡片；要在长列表里"找某一条" → 列表。阈值 12 是默认起点；
- **同一对象随规模切换形态**：知识库从 3 个长到 30 个时，首页由卡片网格改为列表；
- **空状态与 1–2 条一律用卡片**：避免"只有一行数据的表格"这种空洞形态；
- 卡片是**受限形态**而非默认容器：§1 原则 1"不堆卡片"与 §8 的卡片堆砌禁令继续有效。

### 5.2 `PageShell` 布局口径（v0.4 新增）

六个页面原先各写一套 `.page { max-width: 880~1040px; margin: 0 auto }`，
内容区一宽就两侧留大片空白，全是"居中一条"。现在统一成 `PageShell` 组件：

- **一律左对齐铺满**，宽度还给信息：概览 / 文档列表 / 任务中心的列表面板实测 **1144px**（1440 视口）；
- `narrow` 只给真正的阅读型页面（文档详情）；
- 面包屑收进 `PageShell` 的 `#breadcrumb` 插槽，页面不再各自拼一遍；
- 内边距从 `32px / 64px` 收到 `24px / 48px`，顶到内容更快。

**例外：对话页（v0.12）**。对话不是一份清单，是一块会一直用下去的"对话面"，
所以它**不用 `PageShell`、也没有页头**（侧栏已经写着"对话"，再顶一个同名标题只是重复）。
布局改为整屏 flex 列：上方滚动、底部固定输入卡片；内容统一 **960px 居中窄列**
（欢迎区、示例问题、输入卡片、消息同列）——这个宽度取自 WeKnora 的实测值
（`.dialogue-answers` 与 `.rich-input-container` 都是 `max-width: 960px`）。
窄列在这里不是"居中留白"，而是**把行宽限制在可扫视的范围**：输入框跟着内容区铺满一整屏时，
用户先被它的宽度劝退（实测反馈："聊天输入框的宽度有点太大了"）。

### 5.3 侧栏折叠（v0.11 新增）

侧栏可折叠成 **60px 图标栏**（`--sidebar-collapsed-width`），把横向空间还给内容区。

- **开关在品牌行右端**：一颗侧栏（面板）图标 `IconSidebar`，28px 命中区。
  两种状态用**同一个图标**——面板图标本身不带方向语义，收 / 展靠 `title` 与
  `aria-label` 说清；不做"悬浮在边界上"的按钮，那会压住正文，也让 `overflow` 处理变复杂；
  （该图标由用户提供，原稿 1024 网格 + 硬编码灰色，已缩到 24 网格并改走 `currentColor`）
- **折叠态是"图标栏"而不是整条隐藏**：导航图标仍在（`title` 作提示），只是收起文字与会话列表。
  整条隐藏会把"回到对话 / 概览"变成一次额外的展开动作，省下的横向空间并不值这个价；
- **开关绝对定位在离右缘 `--space-4` 处**：展开态它在右边距 16px；折叠态 60px 栏里
  "居中"的位置恰好也是右边距 16px（60 − 16 − 28 = 16）。所以宽度动画一动，
  它就顺着右缘平滑滑到正中——既与导航图标同轴，又不必切换 `justify-content`
  （那是瞬时值，会让按钮在动画开始时"瞬移"到中间）；
- **折叠有 180ms 的宽度过渡**：字标与导航文字**不用 `v-if` 摘掉**（瞬时、无过渡），
  改用 `max-width` 收成 0 + 淡出；导航项只改左右内边距（8 → 14px）让图标滑到中间，
  不切 `justify-content`。`prefers-reduced-motion: reduce` 下关闭这些过渡；
- **折叠态持久化在 `localStorage`**（`useSidebar`）：与主题、字号同一类"这台机器怎么显示"，
  不进后端 `app_settings`——换台机器该重新选；
- 折叠态下**账号菜单从侧栏右缘飞出**（侧栏 `overflow` 转 visible），
  否则菜单会盖住只有 60px 宽的图标栏本身。

## 6. 核心页面映射

| 页面 | 落点 |
|------|------|
| 概览 | **六格大数**（3 列 × 2 行）+ 活跃度热力图 + 趋势图 + 构成图 + **模型用量** + 知识库规模列表。列数**写死 3 列**而不是 `auto-fit`：6 个数字用 auto-fit 在 1440 视口下算出 5 列，第二行只剩一个孤零零一张，视觉重心塌掉 |
| 知识库列表 | **卡片网格**（条目少时）：每张卡 = 名称 + 条目数/最近更新时间 + hover 出现的 `⋯`；超过阈值改列表 |
| 知识库详情 | 页头（库名 + 模型标识 + 操作）+ **文档列表**（条目多）+ **数据源面板**（容器型，卡片） |
| 文件列表 | **列表**：文件类型 SVG 图标 + 名称 + 状态 + 上传者 + 时间；大文件点击展开**子文件树** |
| 文档详情 | **双视角**：「阅读」渲染件（Markdown / PDF / 图片）与「切块」解析产物。默认「阅读」——用户打开文档的第一动作是"看它是什么"，不是"看它被切成几块" |
| 任务中心 | **列表**：每行一个任务；进度用文字 + 细进度条；**卡住/长时间未执行自动标出**（判据见架构 §M7） |
| 对话 | **无页头、960px 居中窄列**。空状态 = 居中问候语（28px / 600）+「你可以这样问我」+ 示例问题胶囊（后端依语料生成，失败回退静态样例）；有消息后整块让位给正文。输入卡片底部：**知识库多选** + **对话模型单选**（v12，随会话保存）+「提示词」（降级为纯文字）；右侧「发送 / 停止」。**引用永远显示** |
| 设置 | 弹窗，左侧分组 + 右侧控件。**默认落在「模型」**（配置模型的主路径：供应商 → 模型 → 用途） |
| 数据源 | 挂在知识库详情页的**面板**（不是独立页面）：它是"这个库从哪里来内容"，与文档列表同属一个上下文 |

## 7. 组件细则

### 7.1 圆角（四档）

| Token | 值 | 用在哪 |
|-------|-----|--------|
| `--radius-control` | 6px | 按钮、输入框、行内菜单项、侧栏导航项（**下拉触发器用 `--radius-row`**，见 §7.4） |
| `--radius-row` | 8px | 列表行、姓名牌 |
| `--radius-panel` | 10px | **列表容器、命中引文块、元信息面板、切块预览块** |
| `--radius-overlay` | 12px | 弹窗 |

> 圆角不是装饰，是用来表达层级和"这块可以点"的。关键是**列表终于有了容器**：
> 清单不再是一排悬空的横线，而是"一个圆角面板 + 面板内用 hairline 分行"。
> 行 hover 时底色换成 `--bg-surface`，整行连同圆角一起亮起来。

### 7.2 间距

- 4px 阶梯：`--space-1` 到 `--space-6`；
- **唯一允许脱离阶梯的令牌是 `--space-pair: 2px`**，用途限定在
  "主标题+副标题""大数字+小标签"这类**必须读成一个整体**的两行；
- **审计判据是"实算值等于令牌值"，不是"选择器在白名单里"**：白名单只认"哪个元素"、
  不认"为什么"，还要人肉维护。认令牌之后，写 `var(--space-pair)` 是有据可依的刻意紧贴，
  手写 `2px` 仍然照报；
- 一处刻意的例外：`ChatView` 流式光标的 `margin-left: 2px` 是**光学对齐**（让光标贴着最后一个字），
  不是间距节奏，不套令牌。

### 7.3 命中尺寸

- **`--hit-target: 24px`** 是可点元素的最小尺寸；文档行展开器、toast 关闭按钮、
  图标按钮（删除等）都必须给足，否则触屏上几乎点不中；
- 行内文件名链接要**撑满整行高度**才够得着；
- 全局 `:focus-visible` 焦点环——键盘 Tab 到任何可点元素都要有可见反馈。

### 7.4 其余

- **按钮（v0.8 收紧）**：主按钮 = 灰黑实心（Dark 下近白）；次按钮 = 透明 + 1px 边框；危险按钮 = 语义红文字，hover 浅红底。
  **按钮内不放图标**，只写动作名（"编辑""停用""测试连接"）——一颗按钮里塞图标 + 文字，
  一排看下来全是方块，比它承载的动作更抢眼。**唯一例外是"创建"类主操作**（新建知识库、添加供应商）
  可以带 `+`，因为那是全页唯一的入口，需要被一眼找到；
- **行动作（v0.8 新增）**：卡片与列表行里的次要动作**统一收进右上角「⋯」菜单**，不在行内并排铺开。
  判据是"一排超过两个按钮"就收；菜单项纯文字、无图标，破坏性动作（删除）用 `--status-danger` 文字色。
  入口常驻可见（不是 hover 才出现），点开才展开——**动作的总数不变，露在外面的只剩一个**；
- **输入框**：1px `--border-strong`，高度取 `--control-height`（与按钮、下拉同高），聚焦时边框加深 + 无外发光；
- **下拉**：v0.6 起为**自绘**组件（`AppSelect`）。触发器 = `--bg-subtle` 填充、无硬边、`--radius-row` 圆角，hover 转 `--bg-hover`，展开/聚焦时转纸面底 + `--accent` 细边 + `--accent-soft` 光晕；浮层 = `--bg-surface` + `--radius-overlay` + `--shadow-popover`，选项行高 36、当前值右侧打勾。**内核不再是原生 `<select>`**——系统渲染的弹出列表改不了选项行高/圆角/勾选，那正是"换了组件却像没换"的原因；键盘与无障碍按 WAI-ARIA combobox 实现（`aria-activedescendant`，焦点留在触发器）。空值选项（"未指定"）按 `--text-tertiary` 弱化为占位符观感，**不加粗**——它是"没选"，不是"选了一个叫未指定的值"；
- **可搜索下拉 / 组合框（v0.10 新增）**：`AppCombobox` 用于"候选可能不全"的字段
  （典型是模型 ID：上游探测得到最好，探测不到也不能把路堵死）。外观与 `AppSelect` 同源
  （`--bg-subtle` 填充、无硬边、`--radius-row`、展开/聚焦转纸面底 + `--accent` 细环），
  但**输入框本身可编辑**：聚焦展开全部候选（即使当前已有值），输入即按 id / 归属过滤，
  点选或 Enter 采纳；**候选之外的值原样保留**，绝不因为"不在列表里"就清空。
  空候选 / 加载中 / 无匹配各给一句就地说明，**不用通知条**。Esc 只关列表、不关外层弹窗；
- **多选下拉（v0.12 新增）**：`AppMultiSelect` 用于"选项可能很多"的多选（如知识库）。
  搜索输入 + 自绘复选列表 + 底部「全选 / 清空」，浮层同 `AppSelect`（原地 + `position: fixed`）。
  **勾选后面板不关**——这是多选与单选的关键差别，否则选三个库要开三次。
  触发器文案：一个没选 = 占位符；全选 = "全部 N 个"；其余报个数；
- **输入卡片内的选择器（v0.12）**：卡片底部工具条左侧放"这一问依据什么"的控件
  （知识库范围、对话模型），右侧只放低频文字入口与「发送 / 停止」。两个下拉各占 200px、
  窄屏收缩（`max-width: 42vw`），不把工具条挤成两行；
- **弹层/菜单**：`--bg-surface` + 1px 边框 + `--shadow-popover`，圆角 `--radius-overlay`；
- **卡片**（仅用于 §5.1 判定为卡片网格的场景）：`--bg-surface` 底 + 1px `--border-hairline` + `--radius-panel`，**无阴影**；
  卡内三段式——**标题（含状态标记）→ 元信息一行小字 → 右上角 `⋯`**；元信息压成一行
  （`类别 · 凭据 · 模型数`），不再各自做成标签与标题抢位置；hover 只把边框转 `--border-strong`，**不做位移/缩放/阴影动画**；
- **列表行**：行高 40px，行底 1px `--border-hairline`，无竖线；hover 整行 `--bg-hover`；
- **弹窗关闭（v0.9）**：关闭按钮**默认就有图标**，不接受"slot 没传就是空白"。
  一个只有 aria-label、没有可见图形的按钮，在用户眼里等于"这个弹窗关不掉"；
- **一个入口（v0.9）**：同一件事只能有一个可写入口。模型注册只负责**登记**
  （供应商 + 模型清单），"哪个用途用哪个模型"在对应功能的面板里选
  （向量化 / 对话模型）。判据是"这份数据能不能在两个地方写"——能，就迟早不一致；
- **空状态**：一句标题 + 一句指路 + 一个主操作，**不放装饰插画**；
- **加载**：骨架屏用 `--bg-hover` 色块呼吸；卡片网格的骨架屏保持与卡片一致的尺寸，避免加载完成时跳版；
- **Toast（v0.10 修订）**：顶部细条，语义色图标 + 文字，3 秒自消。
  **有弹窗时必须渲染进弹窗内部**：原生 `<dialog>.showModal()` 在 top layer，
  任何挂在 `body` 上的浮层（`z-index` 再大）都会被它盖住——设置弹窗里点「测试连接」的
  提示就这么"消失"过。做法是 `AppModal` 打开时注册一个 top-layer 宿主，
  `ToastStack` Teleport 进去（见 `useTopLayer`）。同一个成因也解释了
  `AppSelect` / `AppCombobox` 的浮层**为什么不 Teleport**：原地 `position: fixed`
  才与弹窗同处那个 top-layer 元素里；
- **解释性文字不进正文（v0.7）**：设置等处**不再**在控件下方写一段灰字解释——一屏几段说明会盖过真正的设置项。默认什么都不显示；确实需要时用 `InfoTip`（圆圈问号，`question-line`），悬停或键盘聚焦才展开。判据是"不写会不会做错"：会，才给问号；不会，删掉。**破坏性动作的后果说明是例外，必须常驻可见**（如删除账号会置空归属）。
- **菜单（v0.8 补齐）**：用原生 `<details>`（键盘 Tab/Enter 展开），视觉默认低对比但**始终可聚焦可点**。
  原生没做的三件由 `RowMenu` 自己补：**点浮层外部收起、Esc 收起、下方空间不够时向上弹**。
  Esc 还要**只关最内层**——设置弹窗是原生 `<dialog>`，Esc 会触发它的 `cancel`；
  菜单开着时若连弹窗一起关，用户就丢了位置。所以 `RowMenu` 在**捕获阶段**截住 Esc
  并 `preventDefault`，让菜单先关。
  向上弹不是美化——设置弹窗正文是滚动容器，贴着底边的卡片向下弹会被裁掉，而「删除」通常排在最后，
  裁掉它就等于**藏了破坏性操作**。判定用"浮层高度 vs 上下可用高度"，比较对象是**最近的可滚动祖先**，
  不是视口。

## 8. 可用性与禁忌

**必须**：
- 所有 hover 才出现的操作，同时提供键盘焦点可见与触屏可点的入口；
- 状态必须"图标/颜色 + 文字"双编码，照顾色弱与截图场景；
- 深浅主题切换无闪烁（CSS 变量一次切换，不做过渡动画 >200ms）；
- 卡片网格在窄屏退化为单列，且卡片内部不出现横向滚动；
- **破坏性动作要二次确认，并先给出影响清单**（见 §10.3）。

**禁止**：
- 任何 emoji（UI 全链路，见 §3 执行范围）；
- 高饱和品牌色铺底、渐变背景、玻璃拟态；
- 仅 hover 可见的关键操作（触屏无法发现）；
- 图片图标 / iconfont / 外链图标库；
- 大圆角（>12px）、重阴影卡片堆叠的"仪表盘风"。

## 10. 界面信息架构（v0.4 并入）

### 10.1 一条判定规则

> **页面承载"你要看的东西"，弹窗承载"你要做的一件事"。**

| | 常驻页面 | 弹窗 |
|---|---|---|
| 承载 | 清单、状态、持续变化的产物 | 一次性动作、需要专注的表单、旁支详情 |
| 判定问句 | 用户会不会**反复回来看它**？ | 用户是不是**做完就走**？ |
| 生命周期 | 路由可达、可刷新、可分享 URL | 关掉即结束，不占路由 |
| 失败代价 | 看得见、可重试 | 必须把错误留在弹窗里，不能只发个 toast 就关掉 |

### 10.2 页面的数量不设上限，但动作不许做成页面

> **2026-09-11 修订**：本条原先写的是"不新增全局页面……现在只有四个页面，**已经是上限了**"。
> 那句话写于只有概览/知识库/文档/任务四页的阶段，本意是**防止把动作也做成页面**
> （那确实会稀释信息架构），但它顺带把"以后不能再加页面"也写死了。
>
> 调研报告显示成熟产品（Dify / RAGFlow / FastGPT / MaxKB / Anything-LLM / Open WebUI）
> 的模型注册、切块干预、评测集、分享页、用户管理**每一项都有独立页面**——
> 它们都是清单或工作台，符合下面这条判定问句。
>
> **真正要守的是"动作不进页面"，不是"页面只有四个"。**

新增全局页面的门槛：**它自己是一份清单或一块工作台**。判定问句：
用户会不会**反复回来看它**、且它**不属于任何已有页面的上下文**？
是清单/工作台就建页面，能挂进已有页面就挂进去。

三条推论：

1. 满足上述门槛 → 建页面；
2. **动作一律弹窗**：检索、上传、新建。它们都是"在某个上下文里做一件事"，做成页面就得让用户先导航过去、再选上下文；
3. **旁支详情用弹窗，主链详情用页面**：任务的错误详情是旁支（看完就关），文档内容是主链（要读、要分享、要刷新）。

### 10.3 破坏性动作的确认口径

删除前**必须先给出影响清单**（会删掉几份文档、几个切块、多大体积、有没有在跑的任务），
而不是只问一句"你确定吗"。

- **数字要具体**：说"会删除该知识库及其内容"没人会有感觉；说"3 份文档、412 个切块、1.1 MB"才会让人停一下；
- **可恢复性要说清**：文档删除进回收站保留 7 天（可恢复），知识库级删除不可恢复——
  两者的警示强度必须不同；
- **给出更好的替代**：如果用户可能只是想"暂时不参与检索"，文案里要提"用禁用更好，禁用可以随时恢复"。
