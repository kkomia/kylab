## 一、这是什么（一句话）

**KYLAB = 本地优先的 Agent 工作台**：Agent 的界面、运行时、数据**全在用户本机循环**，知识库与备份作为**可插拔提供者**经局域网接入（NAS 上跑 PG + MinIO），提供者缺失时如实降级。

架构基线是 `docs/设计/架构设计-v0.3.md`（**v0.2 的知识库侧仍是现行基线**，见 v0.3 §10）；落地按五个里程碑推进，**M1–M5 全部完成并真机验收**（§五）。

## 二、架构速览（谁在哪、数据在哪）

```
┌ 用户的电脑 ─────────────────────────────────────────────┐
│  桌面壳（Tauri，React 前端打包在壳里）                    │
│     ↓ 起边车（Python，打包成 sidecar-runtime 随壳分发）   │
│  边车 127.0.0.1:8765 ── 本机权威面：会话/笔记/设置/记忆/  │
│      模型注册/工作区/定时任务/MCP/备份队列                │
│      kylab.db（SQLite，WAL）＋ 产物与记忆的文件            │
│      ↑ 长期凭据在 **系统钥匙串**（Windows 凭据管理器）     │
└──────────────────┬──────────────────────────────────────┘
                   │ 可插拔提供者（局域网）
┌ NAS ─────────────┴──────────────────────────────────────┐
│  知识库服务（PG 54321 + MinIO 9000/9001，桶 kylab）       │
│  备份提供者 `/backup/*`（同一个 MinIO，桶 kylab-backup）  │
│  Web 端（nginx 8081 → 后端容器）                          │
└─────────────────────────────────────────────────────────┘
```

**三条纪律**（改代码前先记住，违反会被门禁抓）：

1. **本地优先，本机权威面不回退**：会话/笔记/设置这些**只在边车**（`frontend/src/api/sidecar.ts` 的 `LOCAL_PATHS` 那张前缀表），边车不可达时**如实报错、绝不回退服务器**（回退 = 让用户以为会话丢了）；
2. **SQLite 方言只许住 `backend/app/storage/sqlite_impl/`**，`services/` 不许 `import sqlite3`（L2 规则，`scripts/check_layering.py` 会拦）；`api/` 不许 import 存储（L1）；
3. **秘密只进钥匙串**（`kylab:<用途>:<对象 id>`）：库里存空、日志不落、**快照擦洗让包里没有秘密**（`provider.` / `model.` / `backup.` / `auth.` 四个前缀族 + `SECRET_KEYS` 整族排除）。

## 三、怎么跑起来

**前置**：Python 3.12（后端用 uv）、Node 20+、Rust（msvc 档）+ VS2022 生成工具 + WebView2。

| 要跑什么 | 命令 | 说明 |
| --- | --- | --- |
| 后端（开发，服务器档） | `cd backend && sh ../scripts/dev-backend.sh` | :8000（端口占着会拒绝启动，别开第二个） |
| 前端（开发） | `sh scripts/dev-frontend.sh` | :5173，直连边车 :8765 与本机后端 |
| 桌面壳（开发） | `cd desktop/src-tauri && cargo run --release` | 起窗口；壳会按 `%APPDATA%\com.kylab.desktop\config.json` 的 `server` 连后端、并拉起边车 |
| **边车运行时（改完后端必须重打）** | `powershell -ExecutionPolicy Bypass -File scripts/build-sidecar-runtime.ps1 -Offline` | 产物 `build/sidecar-runtime`；**壳优先用 `desktop/src-tauri/target/release/sidecar-runtime`**——两份要同步（`cp -r build/sidecar-runtime desktop/src-tauri/target/release/sidecar-runtime`），否则"改了后端但壳跑旧代码"（踩过） |
| NAS 部署 | `sh deploy/nas/deploy-from-windows.sh` | git archive → ssh → build → up；README 在 `deploy/nas/README.md`（**建桶那条命令**、mc 要从 `kylab-minio` 容器里跑） |

**跑壳时最容易踩的三件**：① 上面那条"运行时有两份"；② 前端资源**热更新下次启动生效**（第一次启动装好新版本、第二次才加载它）；③ 壳配置里的 `server` 必须真的有服务在听（交接时开发机上是 `http://127.0.0.1:8100`——一个用同一份 `.env` 起的开发后端实例）。

```bash

backend/.venv/Scripts/python.exe scripts/sidecar-closure.py --json # **17 包 / 22 模块，不许涨**（加依赖会破，见下）
backend/.venv/Scripts/python.exe scripts/gen_api_types.py --check  # 过（`--write` 更新 frontend/src/api/schema.d.ts）
```

- **两条固定 skip**：① 记忆目录符号链接那条（Windows 要开发者模式，CI 的 ubuntu 真跑）；② 非 Windows 平台那条（反过来在 Windows 上 skip）。
- **闭包 17 的那条纪律**：边车运行时**只许用标准库 + 已在清单里的第三方包**（`scripts/build-sidecar-runtime.ps1` 的 pin 清单）。想加包要先看 `scripts/sidecar-closure.py` 的输出——`keyring` 这种"看起来该加"的包被明确否决过（17→23+），所以钥匙串是用 `ctypes` 直调 `advapi32` 做的。
- **内环工具**：`python scripts/affected_tests.py --dry-run`（按改动算该跑哪些用例；`--run` 直接跑，`test-changed.sh/.ps1` 是包装）。

## 六、还没做的 / 已知问题（按优先级）

**A. 要做才能上线的（部署侧）**

1. **NAS 还没部署 M5**：NAS 上（`192.168.31.18:8081`）后端没有 `/backup/*`（实测 404）、前端构建里也没有备份页 chunk。跑一次 `deploy/nas/deploy-from-windows.sh` 即可（**桶已建好**：`kylab-backup`，握手会报 `available=true`）。
2. **边车运行时与安装包要重打**：壳用的是打包进安装包的运行时（`scripts/build-sidecar-runtime.ps1 -Offline` → 再 `tauri build`），否则用户装的壳跑的是老边车。

**B. 已登记的功能缺口（都不是 bug，是没做）**

3. **本地档缺两条端点**：`/chat/turns/{id}/live`（断线补发）与 `/conversations/{id}/resume`（续跑）只在服务器档有（边车只提供 `/turn` 与 `/turn/stream`），而前端这两条路硬编码打服务器 → 对着本机会话 404。**影响**：流式回答进行中刷新页面，那一轮补发不了（答案不丢，当场看不到）；「续跑」在壳里点了就是 404。做法：在边车那侧补"在飞轮次补发"的等价能力（服务器档那套是 `live_turns` 注册表）。
4. **恢复完成后侧栏会话列表不自动刷新**（重载页面才看到新会话）。
5. **导入向导 UI**（选会话 / 进度条 / 批次历史）：M2 规格里写着由后续承接，一直没做。
6. **登录门禁 R13**：本机档在**没有 NAS 登录**时也进不去界面（M3 的明确边界）。
7. **体感收尾**：`/health` 探测预热（280ms 挡在首次本机读之前）、`useModelRegistry` 同形订阅补重读。

**C. 未验 / 环境限制（如实记着，别当成验过）**

8. 壳的**安装包形态**没真跑过（`tauri build` + 装包；开发态 `cargo run` 跑过并验了启动时序、钥匙串迁移、`--device-id` 链）；
9. `clippy` 本机没装（用 `cargo check --all-targets` 零警告替代）；
10. 恢复的 **dry-run 会把整包下载并解包**（逐会话判定必须读包里那份库，代价已知）；
11. **自动快照首启即打一份**（决策 D3：24 小时默认开，装好第一次开机就会往远端传一份）；
12. 遗留的两份临时知识库可手动删：`kb_2908cfba9c70`（M3）、`kb_0f60d527e52b`（M4）。

**D. 明确"不做"的边界（改之前先想清楚）**：应用层加密（包里已无秘密）、整库替换（改成"停边车 → 挪 `kylab.db*` → 再跑恢复"的文档路径）、逐文件勾选备份、增量快照、服务端凭据进本机钥匙串、预签名 URL、第三个提供者。

## 七、改这个仓库的纪律（门禁之外的部分）

- **分层**：`backend/app/{api,services,storage,core}` 四层各有规矩，`scripts/check_layering.py` 是唯一判据（104 = 基线，**新违规一条都不许**）；
- **文档分文件夹**：`docs/规范/`（现行口径）、`docs/设计/`（设计基线）、`docs/计划与记录/`（进度与验收）、`docs/归档/`（被取代或已完成的历史材料，**只供追溯，不是现行口径**）；命名 `<主题><类型>-v<主.次>.md`；
- **界面上不许出现实现语汇**（"缓存"那一类，U2 硬门禁）——界面文案收在各自的 `copy.ts` / `snapshot.ts` 一处；
- **提交信息写"落法 + 验收数字 + 偏离"**（这个仓库的既有风格，`git log` 前 20 条就是范例）；
- **别顺手改既有红**：`check-backend.sh` 整体跑会有若干**与本轮无关的既有红**（emoji 扫描那类），改之前先用 `git archive HEAD` 干净树复现一次，确认不是你引入的。
