## 4. 真机抓到的两个缺口（都已修 + 用例 + 变异验证）

### 缺口 ①：本机档的 SSE **从来不发 `sources`**（出处面板空着、编号点不动）

- **现象**（`02-turn-sse-before-fix.txt`）：工具步如实写着「命中 8 段原文」、模型的回答里也带 `[1]`，
  但事件流里**只有** `step` / `delta` / `done`（4 + 1 + 1 帧）——没有 `sources`。
  前端 `chat.ts:820` 那个 `sources` 分支永远收不到东西，于是**出处面板空着、
  回答里那串编号点不动**（服务器那条链是一直有的）；
- **根因**：本机这一侧的 `/turn/stream` 只处理 `step`/`thinking`/`delta`/`approval`/`done`/`error`，
  **没收 `SourcesEvent`**。这不是"漏抄一行"：M2 时本机档没有知识库可检索，
  `SourcesEvent` **根本不会产生**——少这一条没人看得出来；M3 把提供者接上之后它才第一次真的出现；
- **修**（`backend/app/sidecar.py`）：
  ① `/turn/stream` 照服务器那条链发 `{"type":"sources","items":[…]}`（形状**过 `ChatSourceOut`**，
  不手抄一份会漂的 dict）；② 非流式 `/turn` 的响应加 `sources`（同一份）；③ 这一轮的出处快照
  跟着 `record_turn` **落进本机会话**——不落的话，刷新回看时编号又点不动了（服务器那条链一直存着）；
- **用例**：`tests/unit/test_sidecar.py::test_turn_stream_publishes_and_records_the_sources`
  （两条判据一起钉：流里有 `sources` 且字段齐 + 库里那份快照与流出去的是同一份）；
  **变异验证**：把 `SourcesEvent` 那一支摘掉 → 用例红（改回 → 绿）。

### 缺口 ②：检索结果映射漏了 `knowledge_base_id`

- **现象**：出处的每一条都缺"它属于哪个库"。界面上引用点进去就只能走 `/documents/:id`
  转发一跳（会闪一下空白）——而 `chat.py` 的注释里写着这个字段的用处正是"直连到库页的文档抽屉"；
- **根因**：`RemoteKnowledgeClient.retrieve_sources` 逐字段搬了 chunk / 文档 / 标题 / 页码 /
  预览 / 分数，**唯独没搬 `knowledge_base_id`**——而线上 `SearchHitOut` 有它、进程内那条链
  （`chat.py:838`）也一直带着它；
- **修**：`backend/app/services/remote_clients.py` 补一行（并注明不映射的后果）；
- **用例**：上面那条新用例里一并断言（`items[0]["knowledge_base_id"] == "kb_1"`）。

两个缺口都是**阶段 7 之前没人碰到的路径**：单测里所有检索响应都是替身，
替身给什么就搬什么，而"替身有这一位、真响应也有、映射却漏了"只有真机能看出来。

## 5. 「页面激活两态」为什么没截到图 + 替代物

**结论：桌面壳那一趟实机走查这次没跑起来**，三条原因（都如实记，不当作达标）：

1. **桌面壳没起**：起壳要动壳的 `config.json`（`server` / `api_key`），而本轮纪律明确写着
   "桌面壳配置一律不动"；壳自己拉起的边车也不会用我这次的临时数据目录；
2. **浏览器控制通道对本施工代理不可用**：Kimi Code Desktop 的浏览器面板只能**读**
   （`page.text.snapshot` 正常），任何控制动作都回
   `BROWSER_UNAVAILABLE: Browser control requires a running turn`——不能 reload、不能点击，
   于是"改状态 → 让页面重探"这一步做不了（`ready` 时前端**不轮询**，只有焦点事件或重新加载才会重探）；
3. **新起一个浏览器没有 NAS 会话令牌**：M3 明确不动登录门禁（R13），
   而登录页拦在前面——没有会话就进不了界面。

**替代物（比"curl + 单测"更强的那一档）：活体检查。**
`04-live-page-check.test.tsx`（跑完即删，副本在物证目录里，要重跑就拷回 `frontend/tests/`）
**提供者那条链一条 mock 都不打**（只有侧栏另外两处列表用了 mock，好让侧栏渲染得出来）：
真前端模块（`api/provider.ts` + `features/layout/SideNav.tsx`）→ 真边车
（:8765，提供者指向用户的 :8000）→ 真 `PATCH` 切状态 → 真侧栏渲染。它证的是单测证不了的那件事：
**手写类型与后端响应对不对得上**。实测输出（`04-live-page-check.txt`）：

- `ready`：`providerView()` 拿到 `state=ready`、`credential=configured`、`protocol_version=1`、
  完整能力集（`ingest.extensions` 含 `pdf`）、**9 个库**（`kb_x:名字:文档数` 逐条打出来，

## 9. 偏离与决策（逐条理由）

1. **`capabilities.ingest.extensions` 的"唯一权威来源"最后定在提供者模块的常量**：
   审定前的核验已经点明 `app/parsers` 没有统一注册表（收不收由后缀 + MIME + 内容探测共同决定），
   机械导不出来——所以清单在 `api/v1/provider.py` 模块头集中定义一份并注明"今后的唯一口径"；
2. **钥匙来自桌面壳的 `config.json`，不是 `backend/.env`**：那份 `.env` 里没有钥匙
   （逐键点过：PG / S3 / 模型参数）。壳的 `config.json` 是这把钥匙唯一的长期落点（方案 §4.2 的
   "一处权威"），M2 阶段 6 的真机验收用的也是它；
3. **假模型而不是真模型**：这一轮要证的是"工具步真的打到 NAS"，
   假模型能把剧本钉死（先要 `search`、再吐正文）且可复现；真模型 1 是慢、2 是不可复现
   （同一句话不一定调同一个工具）；
4. **检索命中的"真伪"用回查证，不靠日志**：`search` 打到真 NAS 这件事没有旁证能直接看
   （不抓包、不进对面服务器），所以判据打在**结果的可核对性**上——
   把 8 条出处逐条回真 NAS 取回（`by-ordinal` 那条路 HTTP 200 且正文含 preview、
   `GET /documents/{id}` 200 且库对得上）。假 NAS 根本没实现 `/search`，这份数据不可能是它给的；
5. **`GET /documents?knowledge_base_id=…` 那条路不存在**（施工单里写的形状与线上略有出入）：
   真实端点是 `GET /knowledge-bases/{kb_id}/documents`（库里那一篇）、
   `GET /documents/{id}`（单篇 + stage）、`GET /documents/{id}/timeline`（流水线事件）。
   物证用真实那三条；
6. **`chunk_id` 是 `文档id#序号`**，`GET /chunks/{chunk_id}` 收不下它（404）：
   界面拿引用跳转走的是推荐那条 `GET /documents/{id}/chunks/by-ordinal/{序号}`
   （`api/v1/chunks.py` 模块头写着"推荐：URL 安全"），本次按那条回查；
7. **`ready` 时前端不轮询**，所以"页面从 ready 变成不可用"在**不重载页面**的前提下要等一次
   焦点事件——这正是方案 §3.2 的设计（`ready` 时没有"恢复"可等）。反过来
   "不可用 → 恢复"会在 30 秒内自己回来。§5 那条替代物就是按这个时序做的；
8. **页面两态的截图没拿到**（§5 三条原因），替代物是活体检查 + curl 三态响应 + 前端三态单测。
   如实记在这里，**不当成"已实机走查"**；
9. **`sources` 那条事件是本阶段补的**：它属于"补齐前端那条链"而不是"新能力"——
   服务器档一直有这个形状（`api/v1/chat.py`），本机档从 M2 起就没有，
   而 M3 之前**发不出去也看不出来**。M3 把提供者接上之后它才第一次真的出现，
   所以修它属于收官（真机验收的产出），不属于扩范围；
10. **出处快照也跟着落本机库**（不只是发流）：服务器那条链一直存快照（回看旧回答时
    引用编号要对得上），本机这一侧不存的话刷新之后编号又点不动——两半一起修才算修完；
11. **旧文案统一只动"尾巴"**：`KB_UNAVAILABLE_MESSAGE` / `SEARCH_UNAVAILABLE_MESSAGE` 的前半句
    （"知识库在 NAS 服务器上" / "检索在 NAS 知识库"）逐字保留——有用例按前缀钉着它，
    而它说的事实没变；变的是"接下来去哪儿"（等 M3 → 去设置里看「知识库连接」）；
12. **`check_layering` 的 5 处是新登记的、不是放宽规则**：阶段 6 新加的
    `KnowledgeConnectionSection.tsx` 带来 3 处 U2（**输入框占位符示例地址**，
    就是可复制的那条数据）+ 2 处 U3（① 失败态兜底文案；③ 表单字段约束"这一节只管连接、
    不设默认库集"，方案 §4.1 要求写清）。逐条写进 `U2_ALLOWED` / `U3_ALLOWED`，

    `indexed`、1 个切块）。脚本第一次中断时多建的那个**空**库当场删了（脚本 + 输出在物证目录）；
