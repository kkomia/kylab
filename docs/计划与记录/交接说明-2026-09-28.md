## 1. 最快上手

```bash
# 1) 依赖
cd backend  && uv sync --all-extras
cd ../frontend && pnpm install

# 2) 环境：后端读 backend/.env（**不入库**，需自己建）
#    必需：PostgreSQL（pgvector）、MinIO/S3。本机 dev 指向内网那台：
#      postgresql://<user>:<pass>@100.66.1.12:54321/kylab
#      MinIO http://100.66.1.12:9000（桶 kylab）
#    首次启动会自动补迁移，日志里会打印"已应用增量迁移 vNN"。

# 3) 起服务
cd backend  && uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
cd frontend && pnpm dev            # http://localhost:5173，/api 自动代理到 8000

# 4) 门禁（按改动范围跑，别一上来跑全量）
powershell -ExecutionPolicy Bypass -File scripts\check-backend.ps1
powershell -ExecutionPolicy Bypass -File scripts\check-frontend.ps1
```

**后端测试需要一个独立的测试库**：设 `KYLAB_TEST_DATABASE_URL`（指向维护库，
例如 `.../postgres`）。**不设不会报错，依赖仓储的用例会静默跳过**——
只看"通过数"会误判，务必先确认它在生效。

## 3. 这一批改了什么（一个提交：`4c510cf`，52 文件 / +2858 −454）

都是用户真用下来报的问题，逐条。**每条都写了"为什么"，不是"改了什么"**——接手时
先读代码里的注释，那里有当时的判断依据。

### 3.1 对话与消息

| 问题 | 根因 | 改法 |
| --- | --- | --- |
| 新对话发出第一条消息时闪一下 | `send` 建会话后地址变成 `/chat/<新 id>`，被两个 effect 当成"换会话"（一个清空消息、一个拿还没落库的空详情覆盖） | 新增 `createdEntryRef`，让这两个 effect 放行建会话这一次 |
| 用户消息**没有文件组件标识** | 不是前端没画：**消息与文件之间没有任何关联**（上传只记到会话，消息是纯文本） | 迁移 **v16** 给 `chat_messages` 加 `attachments` 快照（**只挂用户那条**）；请求体 `ChatRequestIn.attachments=[{key}]`（只带 key，名字/类型/大小由服务端按记录回填并校验属于本会话）；前端在用户气泡渲染文件片，点击走文件区预览 |
| 过程面板两行没用 | —— | 删掉「本轮带入长期记忆与人设 N 字」；「本轮没有命中资料 / 直接作答」不再显示（**只有真有出处时**才显示"检索完成 · 引用了 …"） |

### 3.2 项目（工作区）

- 补上**归档 / 重命名 / 删除**：迁移 **v15** 给 `workspaces` 加 `archived_at`；
  侧栏项目行加「…」菜单（删除会二次确认并写明"会话不会被删"）；清单底部一条「已归档」入口。
- 归档**不推 `updated_at`**（与"最近用过"这条排序口径无关）。

### 3.3 文件：落点与上传

- **上传必须先建会话** → 改成"附件先暂存、发送时才上传"，建会话发生在发送那一步。
- **同一项目里上传的文件分不开**（用户原话）→ 查下来是三层：文件区等于整个项目目录、
  工作区模式下上传**直接写磁盘且不记账**（实测那条会话的产物记录数是 **0**）、
  两类会话语义不一致。现在**按用途分落点**：
  - **用户上传** → 会话文件区（对象存储 + 按会话记账）——**不再写进用户的项目目录**；
  - **Agent 产物**（导出的 docx 等）→ 挂了项目就落用户真实目录，没挂落对象存储；
  - **显式入库** → 知识库（复制一份）。
  文件区随之分**两档**：`list_files(scope=conversation|project)`，界面文案「本会话 / 项目文件」。
- **支持上传文件夹**：文件名允许带相对路径（`_upload_name` 逐段清洗、丢掉 `..`），
  前端加「添加文件夹」菜单项与拖拽目录递归。

### 3.4 迁移（**部署时必须知道**）

| 版本 | 改动 |
| --- | --- |
| v15 | `workspaces.archived_at` |
| v16 | `chat_messages.attachments`（jsonb，默认 `[]`） |

**NAS 部署时不能只重建前端**——后端要一起起（起一次自动补迁移）。
部署脚本与坑见 [`deploy/nas/README.md`](../../deploy/nas/README.md)。

### 3.5 Agent 工具面

- 新增三个**内部**工具（只进对话侧，不动 MCP/REST 对外契约）：
  `list_conversation_files` / `read_conversation_file` / `ingest_file`
  （配 `agent_files.read_bytes`）。补的是"**非工作区会话上传的文件，模型一个字都看不到**"
  这个洞——原先 agent 的文件面只有 workspace / sandbox 两个根。
- 沙箱：没有 bwrap / sandbox-exec / docker 时**默认降级为直接执行**并如实标注"未隔离"，
  只有打开设置项 `sandbox.require_isolation` 才按纪律拒绝。

## 5. 这一批踩过的坑（省你时间）

1. **`pnpm --dir frontend vitest run …` 在 Windows 上会把 `frontend` 当命令解析**。
   用 `pnpm --dir frontend exec vitest run …`，或先 `cd frontend`。
2. **后端测试不设 `KYLAB_TEST_DATABASE_URL` 会静默跳过**（见 §1）。门禁脚本本身
   不设它，得由你的环境提供。
3. **`uvicorn --reload` 会把长跑的进程顶掉**：跑 lint / pytest 时若发现前后端服务
   不在了，先看是不是被同名终端顶了；重启即可。
4. **工作区根恰好是服务端源码目录时，模型能读到我们的源码**：因为 `run_command`
   在本机是"直接执行"，不受工作区约束。这不是漏洞（降级直执的已知代价），
   但它解释了那次 12 次读源码的弯路。要堵只能上隔离（Docker/bwrap）。
5. **迁移的语义变化会"吃掉"历史数据**：v15/v16 只是加列，但**落点语义**变了
   （上传不再进项目目录），老的、已经在项目目录里的上传在新语义下只算"项目文件"。
