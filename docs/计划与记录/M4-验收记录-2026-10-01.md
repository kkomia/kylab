**3.4 真机抓到的真缺口：守卫有时「不挡」（已修 + 用例 + 变异验证）**

复跑物证时抓到的：**冷启动直接进知识库页、而提供者不是 `ready` 时，路由守卫有时不挡**——
页面照常渲染、既没有页顶说明也没有 toast，要等下一次广播（30 秒轮询 / 窗口获得焦点 /
在设置里点一下）才纠正。真机现场（同一台真边车 + 真浏览器）：

| 时刻 | 观察 |
| --- | --- |
| 冷启动 2 秒后 | `url = /knowledge-bases`、10 张库卡片在屏幕上、`provider-offline-note` 与 toast 都没有 |
| 用真模块实例调一次 `refresh()`（**强制广播一次**） | 立刻 `url = /chat` + toast「…本机没留上次看到的内容，已回到对话页…」 |
| 修完之后同样冷启动 | **不等任何广播**就重定向 |

- **根因**：`api/provider.ts::useKnowledgeProviderStatus` 是 `useState` + 订阅 effect 的写法。
  状态可能在"这次渲染"与"挂上订阅"之间被改（提供者状态常常是**别的组件**先探到的——
  `ProviderBoot` / 顶栏那条），那一瞬间的广播没人听见，组件就停在旧值上不再更新；
  守卫恰好是那一档里最早的订阅者（它在路由树里，且它的渲染取决于"算不算本机档"）。
- **修法**（`api/provider.ts`）：**挂上订阅之后再对一次表**（`bump` 一次）——等价于
  `useSyncExternalStore` 订阅后那次重读，把那个窗口关掉；`features/knowledge/store.ts`
  的 `useKnowledgeBases` 同一处理（"先画一帧"那条链也不该有这个缺口）。
- **用例**：`provider-gate.test.tsx` +2（兄弟组件在 effect 里播状态——它排在守卫前面，
  effect 因此先跑，正好落在那个窗口里）。**变异验证**：把那一行重读去掉 → 两条用例都红
  （守卫停在页面上），加回来 → 绿。
- **为什么它不是 M4 新引入的**：这段订阅写法是 M3 的（`useKnowledgeProviderStatus`），
  而 M4 的 D-A 正好把"非 ready 时守卫要做什么"变成了**必须准确**的一件事（要么放行给说明、
  要么重定向），所以这个缺口在 M4 的真机验收里才露出来。同形的还有
  `useModelRegistry`（M2/M3 的），本次没动，登记在 §8。

## 7. 偏离与决策（逐条理由）

1. **真机冷启动的自然轮没能稳定满足"内容可见早于实时响应"——这是一个真发现，不是编数**：
   先量清楚两条线的成本：**快照读 p50 6.05ms**（本机回环，§8-A 的"p50 ≤ 100ms"成立）、
   实时读（带令牌打真 NAS）**39.95ms**；但**冷启动第一次**读快照前要先走 M2 的"本机后端可用性
   探测"——`requestLocal` → `resolveLocalBase` → `localAvailable()` → 边车 **`/health`**，而这一台
   边车的 `/health` **每次都会去探一次 NAS 可达性**（`sidecar.py` 的 `_probe_health`），实测
   **280.85ms**（6 次）。于是快照那一读**晚发出 ~60–270ms**，在"NAS 也在本机回环"这个环境里
   就追不回来了（自然轮 5 次里 0 次赢）。**处置**：a) 如实记在 §2 与这里；b) 延迟轮（只延
   页面那条实时读）证明**机制本身**成立且差值 658.8ms；c) 活体物证（`04-*`，把那段探测预热掉）
   5/5 成立。**改那段探测（预热 / 缓存 / 让 `/health` 不探 NAS）是 M2 的账**——它影响所有
   `requestLocal` 的第一次调用，不在 M4 的范围内，登记为后续（§8-1）。
2. **延迟轮是"测量手段"，物证里写清了**：700ms 只加在**浏览器这一侧**（Playwright route），
   模拟"NAS 慢或远"；边车与 NAS 一个字节没改，两轮的原始数字都在 JSON 里。
3. **"两帧的 `fetched_at` 都在画面里"这一条按"帧一有、帧二本来就没有"实现**：
   `fetched_at` 是**快照**的时间戳；实时那一帧是刚取回来的，界面上不该再挂一个旧时间（§5
   "两个时间戳不许混"）。所以帧一那张截图里是小字「上次更新于 刚刚」、帧二那张小字收走；
   两帧的 ISO 时间戳（`fetched_at` / `checked_at` / NAS 侧改名时刻）都在 `02-nas-change.json` 里。
4. **"断连快照页"没有用"把地址改错"来造**：§5 定死了**按地址隔离、不清旧行**，而快照的键
   第一列就是地址——**改了地址就等于换了键空间**，那一档"本机没有那份内容"是**正确行为**
   （§3.3 的③如实拍了它：重定向 + toast）。要造"地址没变、却真连不上"这一档，本次用了一条
   **临时转发**（`:8791` → 用户的 `:8000`）：先把提供者指到转发上确认一次（内容因此是**真 NAS 的**），
   再把转发**停掉**——连接真的被拒、地址一个字没变、那份内容还在同一个键上（§3.3 的②）。
5. **断连时"页面那条实时读"是浏览器侧 `abort` 出来的**：它直连 NAS（经 :5173 代理），
   与本机那一份无关；NAS 好好的它就会成功，屏幕上也就不是"上次看到的内容"了。这模拟的正是
   "NAS 断了/网络不通"，**没有改任何产品代码、没有改 NAS、没有改边车**（脚本里写明了）。
6. **D-A 的"只读"是机制里长出来的，不是守卫加的**：守卫只做"放行 + 页顶说明"；页面上写/管理
   入口的显隐看的是**快照帧的权限位**，而 `can_write` / `can_manage` 在**进快照前就被剥掉了**
   （D-B / `withoutPermissions`）。真机上两帧的差别就是证据：帧一**0 个齿轮**、帧二**10 个**。
7. **新增 `GET /local/kb-cache/stats` 是"顺手但没扩面"**：设置那一块要"行数与最近更新"，
   而那份读数在服务层早就有（`KbMetaCacheService.stats()`，与 `DELETE` 同一族），只是没有端点。
   新增端点照既有七条的手法（`ReadDep`、手写响应模型、docstring 写清口径），**只读、零网络、
   只算当前地址**；服务器档照旧 404（用例里逐条钉）。
8. **`clearKbCache()` 是全仓唯一会抛的"快照读"**：其余读沿用"从不抛"（它是顺手快一点那一下），
   而**清除**是用户明确点的动作——静默失败会让用户以为"清干净了"。这条差异写在 `kbCache.ts`
   的模块头与函数 docstring 上，用例也分开写（一条 rejects、其余回 `null`）。
9. **真库上留下的东西**（用户可手动删）：临时库 **`kb_0f60d527e52b`**「m4-验收-改过名-1021」
   （0 篇文档；建的时候叫「m4-验收-改名前-1021」）。它**故意留着**——物证要能被复核。不想要了：
   `node .shots/m4-phase7/02-nas-change.cjs --cleanup kb_0f60d527e52b`。
   脚本前两次跑各建过一个临时库（`kb_c966c5231781` 名字太长被截断、`kb_d0145f61db9e` 是
   修缺口前那一版物证的），两个都**当场删了**（`--cleanup` 的输出在收尾那几行）。
   除此之外在 `:8000` 上只做读。
10. **真机②那一档的原因串里带了 `ConnectError: [WinError 10061]`**：那是**后端的原话**
    （M3 起就有，`services/knowledge_provider` 的失败分档），界面照旧如实显示——U2 查的是
    **前端字面量**，这句不是文案而是运行时事实。M4 不改这一档；"要不要把 WinError 折成人话"
    登记在 §8-2。
11. **断连时页面上还有一行浏览器原话「Failed to fetch」**（`03b` 截图里看得见）：
    知识库页那条实时读走的是 `request()`（直连 NAS 那条链，不是 `requestLocal`），
    所以拿不到"折成中文"的那一层。M2/M3 就这样，M4 不动它（登记 §8-2）。
12. **`check_layering` 仍是 104、U2 零新增**：本次新加的界面文案（页顶说明 / 顶栏入口 /
    设置那一块 / 按钮）都不带实现语汇（"缓存"二字一个都没有），所以一条例外都没登记。
13. **前端 eslint/prettier 只跑本次动的文件**（M2/M3 同一条口径）；后端 `ruff`、前端 `tsc`/`vitest`
    都是全量。
14. **活体检查是临时测试**（`frontend/tests/zz-m4-live-cold-start.test.tsx`，跑完即删，
    副本与输出留在 `.shots/m4-phase7/04-*`）：沿用 M3 阶段 7 的手法——单测里的网络全是替身，

15. **端口与进程纪律**：临时边车 **8765**、临时转发 **8791**、临时数据目录 `.tmp/m4-phase7/`，
    **用完即停**（脚本 `finally` + 收尾核过）；用户的 `:8000` / `:5173` / 桌面壳配置**全程只读**。
16. **只读那句措辞收口成"那一份只能看，不能改"**（阶段 7 自查）：原文写"下面是本机留的那一份（X），只能看，不能改"，读起来像是在说"这一页只能看"。而页面那条实时读**压根不经过本机后端**（会话身份直连 NAS），理论上存在"非 ready 但实时读成功"的窗口——那时这一页是能读能写的。收口成"**那一份**只能看"之后，两种档位下都成立。真机上把最容易被误读的那一档也拍了（`03d-*`：关掉提供者 → 解析出的地址为空 → 键空间都换了 → 那份内容**根本不可用**，守卫照旧重定向 `/chat`）。
