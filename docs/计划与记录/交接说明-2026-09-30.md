## 四、坑与口径（都是踩出来的）

- **测试环境变量**：不设 `KYLAB_TEST_DATABASE_URL=postgresql://kylab:kylab123@192.168.31.18:54321/postgres`，后端测试会**整体静默 skip**（看着"全绿"其实什么都没跑）。
- **改文件前先看 mtime**：关键文件 2 分钟内被写过 ⇒ 说明有人/别的进程正在改，这时候跑门禁只会拿到"中途快照"（本会话因此误判过 4 次）。
- **端口表不可信**：`Get-NetTCPConnection` 会留下已退出 PID 的僵尸条目，**只有 HTTP 能作准**。
- **边车是两个进程**：包内 `sidecar-runtime\Scripts\python.exe` 是 shim，真身是它拉起的系统 Python 子进程；杀 shim 会把边车带走。
- **cwd 相关**：`isolation.py::run_isolated` 的 `cwd` 现在按档分（`BACKEND_DIRECT` → 工作区根；其余 → 会话沙箱目录）。
- **设置写入**：`PATCH /api/v1/settings`，body 是 `{"values": [{"key": ..., "value": ...}]}`（**list**，不是 dict；用 `PUT` 会 405）。
- **Windows ACL**：`backend/data/workspaces` 上挂着 `Everyone:(DENY)(DC)` 与 `Mandatory Label\Medium:(NW)` —— 那是沙箱给工作树打的标签；**低完整性进程写不进去**（用户看到过 `[Errno 13]`），直接执行（用户身份）不受影响。
- **提交纪律**：ruff + `tests/unit`（必要时 integration）+ 前端 typecheck/eslint/vitest 全绿才提交；中文提交信息；`git add` 只写显式路径；`.workflow/**`、`.shots/**`、`scripts/affected_tests.py`、`scripts/test-changed.*` 是别人的未跟踪文件，**不要动**。
