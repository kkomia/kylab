## 0. 目标与验收

**目标**：把评审报告里**经核实的** P0/P1 清掉，P2 收口；界面形态向三家公开面上能看到的成熟做法靠拢
（空态输入卡、工具在左下发送在右下、侧栏主操作做成卡片、输入区收纳"这次问的是哪份知识"），
但**不照搬**营销落地页那套极简。

**验收（每条都要有）**：

1. **同位置前后对照图**：用 `.shots/capture-round.cjs` 那套脚本重拍同编号的图，人工比对；
2. **门禁**：`sh scripts/check-frontend.sh`（661 条用例 + lint + tsc + 构建）与 `sh scripts/lint.sh` 全绿；
3. **文案纪律**：不新增解释性小字（`check_layering` 的 U1 会拦）；界面文案改动要么删、要么进 ⓘ；
4. **不回归既定选择**：思考块默认展开（v0.25）、正文 66ch 列宽、克制动效、无 emoji —— 都不动。

**硬约束**：只动前端；不引新依赖（沿用既有组件与令牌）；后端协议不变。

**C. 数字与单位体例（§5.1 第 10 条）**

| 条目 | 口径 | 理由 |
| --- | --- | --- |
| 计数 | 一律 `formatCount`（千分位）；**序号例外**（第 N 块 / 第 N 页 / 第 N 步）不分位 | 量级不可预知（用量已到 `18,497,332` token、切块 `19,790`）；序号是"位置"不是"量" |
| 体积 | 一律 `formatBytes`（1024 进制、一位小数）；**进位按取整后的读数判**（`1048575 B` → `1.0 MB`，不再写 `1024.0 KB`） | 同列里 `1024.0 KB` 与 `1.0 MB` 是一样大的两个数却像差一档 |
| 单位位置 | 列头 / `dt` 已给出单位时**才**省掉单格单位；一行里多量级并列时不省 | 上提只在"整列同量级且单位恒定"时成立；`744.9 KB / 2.5 MB / 3.1 MB` 混排的一列把单位提上去，量级就看不出——而量级正是这列要回答的 |
| 时间 | **同一条记录在同一屏的两处只允许一种口径、同一串文本**：列表用 `formatRelativeTime`，详情面写同一个值、绝对时间挂 `title` | 列表写「6 天前」、抽屉写 `2026-09-16 11:42`，读者既要换算又认不出是不是同一时刻 |
| 分数 | 一律 `formatScore`（三位小数） | 同一个融合分数在检索页三位、记忆召回两位，会让人以为换了算法 |
| 百分比 | 新 `formatPercent`：**≥10% 取整、<10% 留一位**，收掉 `.0`，非零不值 0.1% 写 `<0.1%` | 10% 以上一位小数是噪音；10% 以下必须留一位（把 `0.6%` 取整成 `1%` 差近一倍、`0.04%` 取整成 `0%` 等于说"没有"） |

| A/B 配比 | 斜杠两侧一律带空格 `a / b`（含 `aria-label`） | 任务页本来就这么写，只有 LoadPanel 写 `0/1`；一种写法走到底才不用逐处记 |

#### 顺带挖出的真缺陷（都不在用户清单里）

1. **重连补发之后输入框永远卡在「停止生成」**：`api/chat.ts` 的 `emit` 是**先 dispatch、再报锚点**（顺序本身正确），而 `liveTurn.adoptHandlers` 把 `onSeq` 也当"有事件来了"去认领——`done` 把 `streaming` 落回 false 后，同一事件的 `onSeq` 又抬回 true。刷新任何"缓冲里还留着刚跑完那一轮"的会话都会中招。已修（收尾后封口）+ 补了一条**按真实 emit 顺序**的回归用例（既有用例的调用顺序是反的，所以一直没抓住），并**实测过它有效**：把闸门临时摘掉，那条用例红在 `streaming: true`。
2. **`@` 菜单的键盘高亮从来没跟过键盘**：`Menus.tsx` 的 `active` 存在 `ref` 里，↑↓ 只改 ref 不重渲染 → 高亮永远停在第一条，而回车选中的是正确那条（"看得见的"与"实际选的"对不上）。顺手修了。
3. 上下文那格**读数被截断**（百分比看不见）——见第 7 条。
4. 「到 70 会自动压缩」**漏了 `%`**（后端字段是百分比）——见第 7 条。

#### 没做 / 要用户拍板的

- **`exec_policy=allow` 要不要吞掉 build 的确认**：没动逻辑。建议改成"模式只收紧、不放松"（allow + build/plan 时把**命令**这一路降级为 ask），但会牵动 12 个文件约 270 条用例的基线，且会让设置页「总开关」这个名字与行为不符。
- **记忆沉淀阈值**（`memory.capture_every` 默认 5 个用户回合）：真实最长会话 4 回合 → **从未沉淀过一次**。实测改成 2 会让这批历史入队 10 次、改成 3 入队 2 次；但 ReMe 不通时每次都会变成失败任务，建议先把它改成"静默跳过 + 计数"再调默认值。
- **笔记"目录"的含义**：这一轮按**正文大纲**做了（右侧 176px、点击跳转、滚动跟随）。如果用户要的是**按文件夹组织笔记**（左栏树），那是另一件事——后端笔记侧现在只有 tags，没有文件夹概念。
- 第 6 条的 `@` 并入知识库做成了**持久**（与输入框那颗「知识库」开关同源），不另造"仅本轮"的临时状态。
