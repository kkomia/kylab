# docs/ 索引

本目录按**类型**分四个文件夹（判据见《[项目工程规范 v0.6](规范/项目工程规范-v0.6.md)》§2.3；
原五类中的 `调研/` 已整目录并入 `归档/`，见下文「归档 · 调研/」）：
路径本身就该说明"这篇文档是干什么用的、现在还算不算数"。

| 文件夹 | 装什么 | 什么时候打开它 |
|--------|--------|----------------|
| [规范/](规范/) | 改代码或部署时**必须遵守**的硬约定，门禁会拿它当依据 | 动手之前 |
| [设计/](设计/) | 系统怎么搭、为什么这么搭（取舍与边界） | 想改架构、或看不懂某块为什么长这样时 |
| [计划与记录/](计划与记录/) | 按时间线读的：里程碑计划、逐轮落地记录、交接快照 | 想知道"做到哪儿了、下一步是什么" |
| [归档/](归档/) | 被新版取代的旧版，以及已完成的一次性材料（**调研**、产品走查、旧交接） | 追旧账、查"当时为什么那么做"时 |

> 一个主题升级版本时，**旧版进 `归档/`、新版留在原文件夹**——
> "当前有效的是哪一份"看文件夹就知道，不必逐个点开读状态行。

> **归档区怎么读**：`归档/` = 被取代或已完成的历史材料，**只供追溯，不是现行口径**。
> 接手与动手时从 `规范/`（硬约定）、`设计/`（设计基线）、`计划与记录/`（进度）出发；
> 只有要查"当时为什么那么选"时，才回 `归档/` 翻。
