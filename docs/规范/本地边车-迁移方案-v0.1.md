## 3. 数据流向（出本机的只有"问题 + 命中片段"）

```
本地循环 ──(1) 检索请求：query + kb_ids + top_k ─────────────▶ 服务器 KB
        ◀─(2) 命中片段：SourceRef[]（文档名/章节/页码/preview）──
        ──(3) 模型请求：messages（含片段）+ tools ─────────────▶ 服务器 模型代理 ─▶ 上游
        ◀─(4) 增量文本 / tool_calls ─────────────────────────────
        ──(5) 工具执行：**全部在本地**（沙箱 / 工作区 / 隔离）──────▶ 本机
```

三条硬边界：
1. **工作区文件永不上传** ✗ —— 除非用户**明确要求入库**（那时才走 KB 的写入通道 ✓）；
2. **key 不下发** ✓（模型请求在服务器侧加 key）；
3. **会话权威在服务器** ✓（本地只是执行者；事件日志按既有 `session_events` 口径回传 ✓）。

## 5. ⭐ 硬问题：**边车靠什么运行 Python**（本轮必须回答 ✓）

现状：循环 / 工具 / 沙箱**全是 Python** ✓（`tool_loop.py` / `agent_tools.py` / `isolation.py` ✓），
而"本地边车"要能在**用户机器**上跑起来 —— 用户机器上**通常没有 Python** ✗。

| 选项 | 优 | 劣 / 代价 | 判断 |
| --- | --- | --- | --- |
| **(a) 随壳打包一个 Python 运行时** | 循环/工具/沙箱**一行都不用重写** ✓；今天所有用例继续有效 ✓；隔离能力（bwrap/Seatbelt/docker）本来就要按平台探测 ✓，与打包解耦 | 安装包体积（~40–80MB ✗）+ 打包复杂度（PyInstaller/uv 冻结、原生扩展 `.pyd`/`.so` 交叉编译 ✗）+ 首次启动慢 | **推荐** ✓（见下） |
| **(b) 边车用 Rust/Node 重写工具执行层** | 与壳同栈、体积小 ✓ | **重复实现** ✗：工具表、沙箱三道闸、路径策略、审批、事件流全要再写一遍 —— 两份实现必然漂移（安全语义漂移最贵 ✗） | 不推荐 ✗ |
| **(c) 只把"工具执行"下沉（循环留在服务器）** | 改动最小 ✓（只加一条"到本机的执行通道" ✓） | **每次工具调用都要过一次 WAN** ✗（列目录、读一个文件都往返 ✗）→ 与"本地快"的目标相反 ✗；而且**沙箱在远端 vs 工具在本地**会让"工作区"概念分裂 ✗ | 可作为**过渡** ✓，不作终态 ✗ |

**推荐：先 (c) 过渡、(a) 为终态** ✓，理由：
1. (c) 用**今天已有的接缝**（就是 ② 那两个协议 ✓）就能先跑通"本地工作区 + 远端模型/KB"，
   验证数据流向与权限口径 ✓（一到两周 ✓）；
2. 终态走 (a)：**循环与工具不动** ✗（这是"别复制两份循环"的直接收益 ✓），
   只多一层"随壳分发解释器 + 首次启动自检" ✓；
3. (b) 明确排除 ✓：安全语义两份实现是最贵的债 ✗。

**分期**：
- **P1（本轮 ✓）**：协议抽象（`KnowledgeClient` / `ModelClient`）+ 可替换用例 ✓；
- **P2**：`agent_tools.py:1314` 改走协议 ✓ + 远端 `KnowledgeClient` 实现 + 远端模型代理 ✓（一次真会话验证 ✓）；
- **P3**：边车入口 + 打包解释器（(a)）✓ + 平台隔离探测 ✓；
- **P4**：账号/配额与会话权威在边车模式下的口径对齐 ✓。
