## 1. 根因（比逐条修更重要）

三条问题其实是**同一个**：控件的高度与外观没有一处定义。

- `AppInput` 写的是 `min-height: 32px` + `padding: 8px 12px`，字体 15px、行高 1.65
  → 实高 `8+8+2+24.75 ≈ 43px`。规范 §7.4 写的是「输入框 `min-height: 32px`，与按钮同高」，
  **交付值 43px 与规范承诺的 32px 不一致**——和上一轮"规范写 4.5:1、交付 2.83:1"是同一类失效。
- `AppSelect` 只有 `min-height: 32px; padding: 0` → 实高 32px。
  两者放一行，差 11px，肉眼一眼看出"大小不一"。
- 外观上，原生 `<select>` 只加边框仍是系统渲染（系统箭头、系统内边距），
  所以"换了组件"但"样式没变"。

**结论**：需要一个**控件尺寸 token**，让输入框/下拉/按钮共用同一个高度定义，
而不是各自用 padding 凑。

## 2. 改进项

### P1 控件统一（用户点名的"大小不一""下拉没改"）

1. `base.css` 增加 `--control-height: 32px`，并写清它是**控件唯一高度口径**。
2. `AppInput` 单行改为 `height: var(--control-height)` + `padding: 0 var(--space-3)`；
   文本域保持多行（`min-height` + `padding`），不受此约束。
3. `AppSelect` 改为**定制外观**：
   - `appearance: none` 去掉系统箭头；
   - 右侧自绘 Remix `arrow-down-s-line` 雪佛龙（绝对定位、`pointer-events: none`）；
   - 补 hover / focus 态；依然是**原生 `<select>`**（键盘、触屏、无障碍不重造）。
4. 三个控件（输入/下拉/按钮）同高同圆角，排成一行时基线一致。

### P1 侧栏页脚收敛（批注 1/2/3）

- 删掉「后端在线」状态行与其探活代码（不再有消费者）。
- 删掉主题切换按钮（移入设置）。
- 「退出登录」收进账号的**二级菜单**：点账号行展开，菜单里只有「退出登录」。
  仍用原生 `<details>`（键盘可展开、Esc 收起），菜单向上弹出。
- 「设置」保留为页脚常驻项——它是入口，不是动作。

### P1 主题移入设置（批注 2）

- `useTheme` 增加 `setTheme('light' | 'dark' | 'system')`：`system` 清掉本地选择、
  回到跟随系统（与 `index.html` 首屏脚本共用同一键，不闪烁）。
- 设置 → 外观改为「主题」+「正文字号」两块，主题三档用与字号相同的
  `scale-picker` 卡片式选择器。

### P2 滚动条（批注 7）

- 全局细滚动条：Firefox `scrollbar-width: thin` + `scrollbar-color`；
  WebKit `::-webkit-scrollbar` 8px、滑块 `--border-strong`、轨道透明、圆角。
  颜色只引主题变量，深色下自动跟随。

### P2 模型配置：测试移到注册环节（批注 4）

- 后端新增 **`POST /model-registry/providers/{id}/test`**：用**该供应商已存的凭据**
  真发一次最小请求（llm 走一次最短对话、embedding 走一次 embed、rerank 走一次 rerank），
  返回可用/失败原因。取该供应商下**第一个已登记模型**作为模型 ID；没有模型则明确提示
  "先登记一个模型再测试"。
- 前端：**去掉用途分配行里的「测试」按钮**（布局挤压缩窄的直接原因），
  改到供应商卡片上（与「编辑 / 删除」同级）；供应商登记表单里也放一个
  「测试连接」——若还没保存，先保存再测（避免"草稿探测"这种额外凭据面）。
- 用途分配行只剩「标签 + 状态 + 下拉」，不再被按钮挤。

### P2 图标落到该落的地方（批注 8）

- 设置左侧八个分组各配一枚 Remix 图标（模型/向量化/对话模型/服务配置/存储配置/外观/用户/系统与安全）。
- 常见动作补齐图标：添加供应商/添加模型 `add-line`、编辑 `edit-line`、
  删除 `delete-bin-line`、测试 `shield-check-line`（"验活"语义）、
  下载 `download-line`、外部链接 `external-link-line`。
- 原则不变：**图标是辨认加速，不是装饰**——纯文字已经够清楚的地方不加图标。

## 6. 第四轮：下拉改成自绘（用户：「依旧不好看，我更喜欢 Kimi 的」）

**为什么前两版都没解决**：第一版各处原生 `<select>` 各写一套样式；第二版统一到
`AppSelect` 但**内核仍是原生 `<select>`**——系统渲染的弹出列表改不了选项行高、
圆角、勾选与悬停，所以看着"就是没换过"。这次把触发器与列表都自己画。

**Kimi 观感的三个要点（逐一落地）**

| Kimi 的元素 | 落地 |
|-------------|------|
| 触发器是**灰底圆角块**，不是"白底 + 1px 边框" | `--bg-subtle` 填充、透明边、`--radius-row` 圆角；hover 转 `--bg-hover` |
| 聚焦/展开时有**细边 + 光晕** | `--accent` 1px 边 + `--accent-soft` 3px 光晕；箭头翻转 180° |
| 弹出列表是**白卡 + 阴影**，当前值右侧**打勾** | `--bg-surface` + `--radius-overlay` + `--shadow-popover`；选项行高 36，`IconCheck` 标当前值 |

**工程上的两个坑（都已修）**

1. **浮层不能 Teleport 到 body**：设置弹窗是原生 `<dialog>`，处于 top layer，
   挂在 body 上的 `z-index: 60` 浮层会被整个盖住——实测选项完全看不见。
   改回原地渲染 + `position: fixed`（既不被 `overflow: auto` 裁剪，又与弹窗同层）。
2. **`scrollIntoView` 在 jsdom 是未实现桩**：调用会往虚拟控制台抛错、弄脏测试输出。
   改成按 `offsetTop/scrollTop` 手算滚动位置；顺带免掉 `CSS.escape`（jsdom 无 `CSS` 全局）。

**无障碍**：`role=combobox/listbox/option` + `aria-activedescendant`（焦点始终留在
触发器，键盘与服务阅读器共用同一份高亮状态），方向键/Home/End/Enter/Esc/Tab 全覆盖，
点外部关闭（捕获阶段监听 `pointerdown`）。新增 8 项单测钉住这些行为。

**规范影响**：触发器圆角与填充式外观属规范级变更 → 新增《前端设计规范 **v0.6**》
（只改 §7.1 一行与 §7.4 一条），v0.5 标注为已被取代保留。

## 8. 第六轮：动作收进「⋯」+ 未指定文案（用户批注）

用户原话：「供应商的测试/编辑/停用按钮，应该在这个卡片方块右上角有三个点，点了才显示这些按钮出来。
你现在按钮全部露出来，太多了很杂乱。另外这种按钮（非菜单的）用纯文字就好，不要加图标，显得很臃肿。」
另一条：「应该是**未指定**，而不是不指定。」参考 wekora 的卡片交互截图。

### 8.1 供应商卡片：5 颗按钮 → 1 个「⋯」

**问题不是按钮不好看，是它们的数量盖过了卡片本身**：一张卡片第一行挤着
`测试 编辑 停用 加模型 [删除图标]` 五颗控件，标题反而最不显眼。

按 wekora 的卡片改法重排为三段式（规范 §7.4）：
1. 标题行：供应商名 + 「已停用」标记，右上角**一个** `⋯`；
2. 元信息行：`类别 · 凭据掩码 · N 个模型`（原先这四项各占一块，与标题抢横向空间）；
3. 接口地址一行小字，下面是模型清单。

菜单项：`测试连接 / 编辑 / 添加模型 / 停用（启用）/ 删除`，纯文字；删除用语义红。
模型行同样收成 `编辑 / 删除` 两项。**动作总数没变，露在外面的只剩一个。**

### 8.2 非菜单按钮去图标

`添加供应商` 去掉了 `+` 图标；卡片与模型行里的动作按钮连同图标一起进了菜单。
保留图标的只剩"创建"类主操作（新建知识库、添加供应商）——那是全页唯一入口，值得被一眼找到。

### 8.3 顺带修掉的两个真问题

- **`menu-item-danger` 一直是死代码**：`DocumentView` 的切块菜单写了这个类，
  但全项目没有任何地方定义它——切块的「删除」**从来没有变红**。本轮在 `RowMenu` 里统一定义
  菜单项样式（含 danger / disabled），这类语义色不再靠调用方各写一遍。
- **菜单会被滚动容器裁掉**：弹出层是 `position: absolute`，而设置弹窗正文
  `overflow-y: auto`。贴着底边的卡片向下弹时，「删除」正好被裁在可视区外——
  **等于把破坏性操作藏了**。`RowMenu` 现在按"浮层高度 vs 上下可用高度"决定是否向上弹，
  比较对象是**最近的可滚动祖先**而不是视口。
  **Esc 只关最内层**：菜单开着时按 Esc，原先会连同原生 `<dialog>` 的 `cancel` 一起把设置弹窗关掉，
  用户丢了位置——现在在捕获阶段截住 Esc 并 `preventDefault`，只收菜单。
  （实测：菜单可见数 1 → 0，`dialog[open]` 仍为 1。）

### 8.4 「不指定」→「未指定」

空值选项的语义是"没有指定"，不是"指定了一个叫『不指定』的东西"，
所以用「未指定」；渲染上继续走占位符弱化（`--text-tertiary`、不加粗）。
`SideNav` 的归属下拉早已是「未指定」，本轮把模型注册面板的三处对齐。

### 8.5 验收

- 截图核对：卡片三段式、`⋯` 菜单（含向上弹）、模型行菜单、空值弱化；
- 交互核对（真实浏览器）：点浮层外部收起（可见菜单数 1 → 0）、Esc 收起（1 → 0）、
  `⋯` 常驻可见；
- 新增 `tests/unit/components/RowMenu.test.ts` 8 条，钉住上述原生 `<details>` 不提供的性质
  （点外收起 / Esc 收起 / Esc 只关最内层 / 空间不足时向上弹）；
- `scripts/check-frontend.sh` 全绿：**146 项单测**（+8）、vue-tsc、eslint+prettier、生产构建、emoji 扫描。

## 9. 第七轮：模型归属整理 + 取消哈希兜底 + 品牌字标（用户批注）

用户原话（四条）：
> 菜单 × 号不明显。行状态错误。取消 hash 兜底，未配置向量时，不允许建立知识库。

### 9.1 `×` 号其实一直没画出来

`AppModal` 的关闭按钮是 `<slot name="close-icon" />`，而**全项目没有一个调用方传过这个
slot**——于是每个弹窗右上角都是一个空的 24×24 方块。用户说的"不明显"实际是"不存在"。
现在默认渲染 `IconClose`（18px），并把命中区放大到 28×28。

### 9.2 行状态错误 = 「开发兜底」这块牌子

「向量化」那一行原本写着 `未配置 Key 时用确定性哈希兜底…`，状态标「开发兜底」。
在"没配也照样跑"的前提下这是对的；一旦取消兜底，同一行就自相矛盾了。
现在未选定就是 `未选定`（警告色），说明写的也是"不能建库、去哪配"。

### 9.3 取消哈希兜底：没配就是没配

- **产品实现不再静默退回** `DeterministicEmbedder`。`build_embedder` 在没配模型时抛
  `EmbeddingNotConfiguredError`，报错文案统一为一句可执行的指引（设置页 / 建库失败 / 接口错误三处共用）。
- **建库被拒**：既没在建库时挑注册模型、全局默认也没配 → `422` + 指引；建库时挑了就够，
  全局默认没配不拦（这正是"每库可自选"的意义）。
- **检索跳过向量通道**而不是整体报错：全文通道照常返回，`embedding_configured=false`
  让界面如实说"本次只做了关键词检索"。**不降级成假向量**——那才是原来的问题。
- 哈希实现本身保留（`DeterministicEmbedder`），但必须显式开 `KYLAB_DEV_EMBEDDING`；
  测试夹具显式打开它，生产默认关闭。开关存在的唯一理由是离线开发与测试要一条不联网的链路。

### 9.4 模型归属：注册只有一个入口

| 面板 | 改前 | 改后 |
|------|------|------|
| 模型注册 | 供应商 + 模型 + **用途分配** | **只有**供应商 + 模型清单 |
| 向量化 | 地址 / Key / 模型 ID / 维度 精细字段 | **默认嵌入模型**选择器 + 重排模型选择器 + 批大小 |
| 对话模型 | 地址 / Key / 模型 ID 精细字段 | **默认对话模型**选择器 + 温度 / 长度 / 思考开关 |

后端同步收口：`SETTING_GROUPS` 只留行为参数（批大小、温度、最大长度、思考开关、提示词），
`SECRET_KEYS` 只留云端解析节点的 token；`runtime.embedding()/rerank()/llm()` 的身份
**只从注册表绑定取**，设置页那些 `embedding.model_id` 之类的键不再参与解析（`.env` 引导值同步作废）。
"没绑定就是没配"成为唯一口径。

### 9.7 用户分组：开通表单默认收起（用户批注）

用户原话：「这个新增用户的界面怎么默认打开的。收起来。注意 UI 逻辑统一。」

问题不在表单本身，而在**它是唯一一个常驻展开的表单**：模型注册的「添加供应商」、
各面板的「编辑」都是点开才出现，只有「用户」一进来就把四字段空表单摆在最上面，
把「成员与名册」推下去——而多数时候用户只是来看名单的。

改法与「添加供应商」完全一致：分组标题右侧一颗 `添加用户`，点开才是表单、按钮变 `取消`，
开通成功后自动收起；切换分组时也收起（与 `editing = null` 同一处）。

### 9.8 左下角：只显示当前用户，菜单向上展开（用户批注）

用户原话：「只显示当前用户，不提供系统内直接切换用户的行为，只支持先登出再登入切换用户。
通过点击用户名，向上展开含有设置和登入登出、切换主题的菜单。」

**删掉的是"当前使用者"下拉**（名册选择器）。它是账号体系之前的产物：靠
`X-Kylab-Operator` 头声明"我是谁"，不参与鉴权。两套身份并存时，
"我以为我是谁"与"后端认为我是谁"会分叉——正是用户要禁掉的那种行为。

**页脚现在只有一行**：`图标 + 名字 + 角色 + 折叠箭头`，点它向上弹出
`设置 / 切换为深色|浅色 / 退出登录`。没有会话时不显示「退出登录」（控制台令牌通道没有会话可退）。
主题项是**动作式**的：文案说清"点一下切到哪边"，而不是给一个状态开关。

**顺带修掉的归属分叉**：上传归属原先只认 `X-Kylab-Operator`（本地声明的 id），
现在登录态下取**当前账号 id**，与"谁登录着"永远一致；只有没有登录态的旧部署才回退到本地声明。

**顺带修掉的身份不恢复**：`App.vue` 原先只在 `auth_enabled` 时 `restoreSession()`。
`auth_enabled` 说的是"控制台令牌那一套"，而会话令牌本来就是后端账号体系签发的有效凭据——
于是控制台通道下明明带着令牌，界面上却当你没登录（页脚显示不出名字、
管理员入口也不出现）。现在只要本地有会话令牌就验一次。

### 9.9 当时那台机器的凭据状态（已被 §9.10 取代）

核对时发现这台机器的 dev 环境**已无有效凭据**：本地会话令牌已过期（后端 `/auth/me` 返回 401，
客户端按设计清掉了它），而后端数据库里没有控制台令牌（`/auth/status` 返回
`needs_token: true`），业务接口一律 401，设置弹窗会自动打开提示"请在「设置 → 系统与安全」粘贴令牌"。
这是既有设计里的恢复入口，不是本轮改动造成的。

**后续（§9.10）**：控制台令牌整条取消，"粘贴令牌"这条路已经不存在了；
现在唯一的方式是用账号密码登录。

### 9.10 控制台令牌机制取消（用户批注）

用户原话：「控制台令牌机制取消。」并明确两点：项目还在开发阶段、直接删干净；
以及取消"无鉴权本机模式"——**强制先建管理员账号**。

**删掉的东西**（没有过渡、没有兼容开关）：

| 位置 | 改动 |
|------|------|
| `.env` | 去掉 `KYLAB_CONSOLE_TOKEN`、`KYLAB_AUTH_ENABLED` |
| 接口 | 删 `POST /auth/console-token`；`GET /auth/status` 只回 `needs_setup` |
| 鉴权 | `current_caller` 不再有二选：**没凭据就是 401**，没有"未启用鉴权就放行"这条支路 |
| 身份 | `Caller.is_console` → `is_admin`，`require_console` → `require_admin`：管理员身份只能来自会话角色 |
| 签名密钥 | 不再拿控制台令牌兜底；只认专用密钥（首次 setup 会生成一条落库） |
| 前端 | 删 `useConsoleToken`（含"需要控制台令牌"提示与设置里的令牌输入框）；401 只有一条恢复路径——回登录页 |

**为什么值得删**：控制台令牌与账号体系并存时，"我以为我是谁"与"后端认为我是谁"
会分叉（页脚显示"未指定"、401 时弹一个用户根本没有的令牌输入框）；
而"还没配凭据"与"忘了配凭据"在代码上无法区分，于是"没配就放行"等价于
"无账号即裸奔"。删掉之后只剩一条路：先建账号，再登录。

**代价（如实记下）**：忘记管理员密码将**没有应急入口**。原先控制台令牌兼任
恢复钥匙，现在这条路没了。开发阶段可以换数据目录重建；正式发布前应当补一个
本机 CLI（如 `kylab admin reset-password`）——它不经过 HTTP，所以不属于"后门"。
这条已记入开发计划。
