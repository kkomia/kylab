## 1. 怎么取的证（可复核）

- **截图管道**：`.shots/` 下已装好的 playwright + chromium（`.shots/package.json`），
  脚本 `capture-round.cjs` / `capture-round2.cjs` / `capture-scroll.cjs` / `capture-peers.cjs`。
- **真实数据**：把本机 dev 会话令牌注入浏览器（`kylab-session-token`），**只读**——不点任何写数据的按钮、
  不发消息；令牌只在 页面 → 本地 8788 端口 → `.shots/.token` 之间流动，**没有打印、没有入库**（`.shots/` 已 gitignore）。
- **截图规格**：1440×900、`zh-CN`、亮色为主，另拍 6 张深色。
- **三家**：只访问公开页面，**不登录、不提交任何表单**。结果如实标注：
  DeepSeek 拿到落地页 + 登录墙；豆包拿到"未登录的对话壳"（但被下载推广弹窗盖住并模糊）；
  Kimi 拿到"未登录的对话壳"（它没有营销落地页，两个域名都落在这里）。
  ——**登录后的三家界面一律没有素材，本文不对其做任何描述。**
- **评审方式**：五个子智能体各自 Read 原图（含像素取样与坐标测量），本文的"现象"都指得出图号与屏幕位置。

### 1.2 更正记录：评审员的**图面判断**都回代码/DOM 核过一遍（这一轮改了 5 条）

**结论：子智能体的"看图"很有用，但不能直接当缺陷清单用。** 五个评审员报的首批发现里，
5 条经不起核实（其中两条被他们列为 P0）。记录在此，作为方法的一部分：

| 评审员说 | 核实结果 | 处置 |
| --- | --- | --- |
| 「回答里 `[6][2]` 找不到任何来源列表」 | **部分误判**：`markdown.tsx` 早把 `[1]` 渲染成**可点徽标**（参考 WeKnora / Perplexity），且只替换"确实存在对应出处"的编号；那一轮的徽标写着**「本轮没有命中资料」**，所以确实没有出处可列。真缺口是**联网搜索的来源没有实体可落** | 改写 C1，P0 → P1 |
| 「思考过程默认全展开，应该改成默认折叠」 | **误判**：那是 **v0.25 的既定选择**（`turns.ts`："默认展开，而且不再自动收起（v0.25，照 Kimi 的对话页）"），且用户点过之后按记忆走 | 改写 C2：**不动默认**，只改视觉区分（P1） |
| 「抽屉『原文版式』预览整块空白，无骨架/无失败/无重试」（列为 **P0**） | **误判**：headless Chromium **没有内置 PDF 阅读器**，iframe 里的 PDF 必然是白的。用**有头**浏览器重拍（`43-doc-pdf-headed.png`）——**渲染完整**：12 页、页码 1/12、缩放 37%、缩略图栏、正文都在；失败态另有用例覆盖（"预览失败要说原因；不能预览的格式连链接都不换"） | **整条撤回** |
| 「术语不一致：列表写『切片』、抽屉写『切换』」（列为 **P0**） | **误判**：页面真实文本（`textContent`）里是 **`切块`**（Tab「切块」/ 字段「切块数 74」/ 「共 74 个切块」），`切片` 与 `切换` 在**源码里一处都不存在**——是看错了字形 | **整条撤回** |
| 「状态/健康 两列都写『已完成』」 | **属实**：每行 `SPAN`（绿徽章 `rgb(15,133,58)` + 浅绿底）紧跟 `SPAN.m-row-health-done`（`rgba(0,0,0,0.45)` 纯灰字），12 行皆如此 | 保留，T2 定级 **P1** |

另外两条**部分属实**、已按核实结果改写：页签（T1/M5）`aria-selected` 语义正确、
但当前项**没有任何视觉差异**（两边都是透明底、字重 400）——属实、且是纯样式问题；
发送键空输入时 `disabled` **确实为 true**，只是底色透明、视觉区分弱（C8 改写为"禁用态视觉弱"）。

**教训（与 §1.1 那四条量法纪律同源）**：`body.innerText`、`domcontentloaded`、类名前缀、字段名、
**headless 缺 PDF 阅读器**、**小字看错字形**——都是"看起来是产品缺陷，其实是取证方式的问题"。
规矩是：**任何要动手修的发现，先回代码或 DOM 核实一遍**。

## 2. 与三家的形态对照（可以直接抄的）

三家公开面能看到的形态（DeepSeek 落地页/登录页、豆包对话壳（模糊）、Kimi 未登录对话壳）里，
**与"知识库 + 对话"这个形态直接相关的**：

| 形态 | 出处 | 关键数字 |
| --- | --- | --- |
| 空态输入卡：白底 + 1px 极浅描边 + 大圆角，占位在首行 | Kimi / DeepSeek | 768×114（主列 64%）/ 878×138（视口 61%）；圆角 20 / 24 |
| **卡内布局：工具在左下、发送在右下** | Kimi / DeepSeek | 发送是 34–36px 圆形按钮（Kimi 空输入时是灰禁用态；DeepSeek 是实心靛蓝） |
| **输入卡下方挂一条更窄的副条，放「选择项目 / 插件」** | Kimi | 左右各内缩 16px、只圆下角——"这次问的是哪份知识"收进输入区本身 |
| 侧栏「新建会话」做成**白底描边卡片 + 右侧 Ctrl K 键位徽标** | Kimi | 218×40、圆角 10px，权重大幅高于普通导航行 |
| 侧栏分组：13px 灰标签 + 行内 16px 图标、14px 文字 | Kimi | 行距 33–39px；侧栏占视口 16.6% |
| 侧栏底部把次要入口收成**一张浮动白卡**（获取应用/关于/语言/帮助） | Kimi | 每行约 40px，右侧统一 chevron |
| 空态快捷入口：一排描边 pill | Kimi | 6 颗、高 36px、间距 12px、图标 + 14px 文字 |
| **登录页两栏等高**：表单 + 二维码，整体视口居中 | DeepSeek | 表单 334px、二维码卡 241px、间距 32px；验证码框**内嵌**「发送验证码」+ 竖分隔线；备用方式压成主按钮下方一行 13px 灰字 |
| 语言/模式切换用**分段胶囊**（选中项为实心） | DeepSeek | 高约 28px —— 很小的成本换很清楚的选中态 |
| 内容按**主列**居中，不是按视口居中 | Kimi | 侧栏收起/展开时内容重新居中 |
| 页脚一行 13px 灰、靠大间距分隔合规信息（不用竖线） | Kimi | — |
| 两栏弹窗：左文案 + 单一主按钮贴底、右整幅插画 | 豆包（下载推广弹窗） | 764×556、圆角 16px |

**明确不要抄的**：DeepSeek 落地页"只剩一个输入框、全页无导航无页脚"（我们还要暴露知识库）；
输入框下面再放一颗同义按钮（DeepSeek 落地页）；到达即弹推广弹窗并模糊背景（豆包）；
二维码卡用无描边无投影的浅灰块（DeepSeek）；模式切换只用两段纯文字、没有选中态（Kimi）。

## 4. 跨页面的共性问题（比逐条修更重要）

1. **主操作四种形态**：实心黑按钮（404）/ 描边方框（侧栏新建会话）/ 无边框文本链（能力页、知识库页、任务页）/ 裸图标（对话发送键）。而三家的主操作都是**实心按钮**、且**空态时明确灰化**。
2. **"灰胶囊"被当成两种东西**：只读统计（能力页页头、技能卡标签）与可点筛选（能力页胶囊组）形状完全相同 → 用户分不清哪个能点。
3. **蓝色至少三套取值**：导航/链接 #006EED、环形图 #1783FF、AI 徽标 #006EED；选中底色又是第四种冷蓝（#E3EDF9），而全站底色是**暖**中性。
4. **"当前位置"信号缺失**：任务/记忆页签无当前态（P0）、工作区/任务中心在左侧导航里无归属、侧栏会话项无选中态、抽屉打开时列表行无选中态。
5. **解释性小字按既有口径（§7）应改 ⓘ 或删**，现仍常驻在 6 处以上（19、12、13、16、17、20）。
6. **数字与单位体例不统一**：千分位（21606 无）、小数位（2.5 MB vs 744.9 KB）、单位位置（"222 题" vs 无单位）、日期格式（列表两行 vs 抽屉一行）。
7. **圆角两种语言**：小标签 5–6px vs 全圆角胶囊。
8. **浅色主题的次级文字普遍偏弱**（1.87:1 / 3.15:1 / 3.4:1 / 4.16:1），而**深色主题的主色文字也偏弱**（4.18:1 / 4.32:1）——两套主题的同一令牌没有做反向补偿。
