## 1. 我们现在的对话命令（代码核对过）

> **下面是调研当时的现状（内置 8 条）**。定案后已扩到 **12 条内置**（新增 `/rewind` `/context`
> `/status` `/skills`，技能也各自成一条命令 `/技能名 [任务]`）——本节保留原样，改动记在开发计划 §12.282。

**后端**（`backend/app/services/commands.py` + `api/v1/chat.py` 的 `_dispatch_builtin`）：

- **内置 8 条**：`/help`（列全部；带名字看详细用法）、`/compact`、`/new`、`/stop`、
  `/mode [plan|build|edit|yolo]`、`/model [模型名]`、`/plan [描述]`（**两面派**：不带描述＝切计划档，
  带描述＝改写提示）、`/skill <技能名> [任务]`（把技能正文注入这一轮）。
- **自定义命令**：数据目录 / 仓库的 `commands/*.md`，**文件名即命令名**（`^[a-z0-9][a-z0-9_:-]{0,63}$`），
  扁平 frontmatter（`description` / `argument-hint`），`$ARGUMENTS` 与 `$1..$N`（**1 起**），
  **有参数但正文无占位符时自动追加「用户参数：…」**。
- **两类执行**：**短路类**（不进模型、不产生 assistant 消息、只回结果）与**改写类**（渲染后的正文当这一轮的提示）。
- **三层优先级**：内置 > 用户自定义 > 仓库自带，重名 first match wins，被遮蔽的仍列出并带 `shadowed_by`。
- **两条纪律**（照 DSH/QwenPaw 抄的）：认不出的 `/xxx` **也当命令**（回一句"没有这个命令"，永不静默降级为普通 prompt）；
  **命令执行写 session log、不进模型历史**。
- 接口：`GET /chat/commands` 返回 `{name, summary, usage, group, details, argument_hint, short_circuit, shadowed_by, error}`。

**前端**（`features/chat/ui/Menus.tsx` 的 `SlashMenu` + `Composer.tsx`）：
输入框里打 `/` 触发菜单，**前缀优先**再包含匹配，按 `group` 分组，上/下键循环、回车选中，
选中一条**把它的 `usage` 填进输入框**（需要参数的命令尤其有用）；菜单数据来自 `/chat/commands`，懒加载。

**已经很好的地方（这轮不动）**：短路/改写两分、自定义 md 命令、遮蔽可见、未知命令不静默降级、选中即填 usage。

## 2. 四家怎么做的（2026-09-24 现拉）

| | 命令从哪来 | 自定义命令 | 参数 | 值得抄的 |
| --- | --- | --- | --- | --- |
| **Claude Code**（官方文档） | **命令＝技能**：`.claude/commands/x.md` 或 `.claude/skills/x/SKILL.md` 都得到 `/x` | md + frontmatter（`description` `argument-hint` `arguments` `disable-model-invocation` `user-invocable` `allowed-tools` `model` `effort` `context` `agent` `hooks`…） | `$ARGUMENTS`、**`$ARGUMENTS[N]`（0 起）**、`$N`、**`$name`（`arguments:` 里按位置映射）**、shell 式引号、`\$` 转义 | ①**命名参数**；②**0 起下标**；③**`!\`cmd\`` 在模型看到之前执行**（有政策开关、失败即中止整次调用）；④菜单可见性四档（on / name-only / user-invocable-only / off）；⑤子目录命令名用 `:`（`/frontend:component`） |
| **Gemini CLI**（官方文档） | `~/.gemini/commands/`（用户）+ `<项目>/.gemini/commands/`（**项目优先**） | **TOML**（`prompt` 必填、`description` 可选） | `{{args}}`（原样；在 shell 块里自动转义）／**没写占位符就追加到末尾** | ①`/commands reload\|list`（改完文件不用重启）；②`@{...}` 注入文件/目录内容、`!{...}` 执行 shell（**都要确认**）；③`/rewind` 是**交互式选点**再确认 |
| **Codex CLI** | 仓库文档只剩一句外链（`docs/slash_commands.md`），目标站点 403 —— **这一家本轮没取到原文，不臆测** | — | — | — |
| **ZCode / DSH / QwenPaw**（本仓既有调研 §2.7） | ZCode 内置 20 条、DSH `ctx.commands.register` 重名即抛、QwenPaw 三类命令短路 | ZCode：md 文件名即命令名 + 嵌套目录用 `:` | `$ARGUMENTS` / `$N`；无占位符则追加 | 短路（进 LLM 之前）、执行写 log 不进历史、UI 只管"光标触发 + 分组菜单 + 路由" |

**四家的共识（我们现在缺的就在这里面）**：
1. **命令名要能分组命名空间**（`/frontend:component`）——Claude 与 ZCode 都这么做；
2. **参数不止"一个整体 + 位置"**：Claude 还有 **命名参数**（`arguments:` 声明 → `$name`）；
3. **每条命令要有"从哪儿开始"的发现路径**：Claude 的菜单可见性四档、Gemini 的 `/commands list|reload`、
   ZCode/QwenPaw 的"技能目录名即命令"；
4. **会话自身的动作是一等命令**：`/rewind` 三家都有（Claude、Gemini、ZCode），我们**只有按钮**；
5. **上下文/状态是一等命令**：Claude 有 `/context`；我们的上下文用量只在输入框旁边一个小仪表里。

**明确不抄的（以及为什么）**：
- **`!\`cmd\`` / `!{...}`（在提示里执行 shell）**：我们的命令跑在**服务器**上、面向局域网多用户，
  让一条聊天命令触发服务端 shell 是**新的攻击面**（Claude 那边是本地 CLI、还带政策开关与确认）。
  本仓的定位是"自托管知识库"，不是本机 CLI——**不做**，需要跑命令请用 MCP/技能那条有审计的路。
- **`@{...}` 注入文件内容**：我们输入框里已有 `@` 提及（选定即插入引用，走的是文件区那条路），
  比在命令正文里做字符串注入更可控——**不重复实现**。
