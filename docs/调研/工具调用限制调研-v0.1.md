## 一、核心结论

主流 Agent 产品对工具调用的限制，本质是围绕「模型 → 工具 → 回填 → 再模型」这个循环设计**多重安全闸**：

1. **最普遍的是轮次 / 步数上限**：默认值集中在 10~100 区间，但**计数口径差异很大**——有的按 LLM 调用轮数计，有的按工具往返计，有的按图节点步数计。
2. 其次是**单轮并行开关、工具白名单 / 审批、预算与超时、终止条件、上下文截断**五类辅助限制。
3. 主要设计分歧在三点：**计数口径、默认松紧度、超限后的行为**（抛异常 / 优雅降级 / 暂停可续跑）。

## 二、主流产品对比

### 2.1 次数限制参数与默认值

| 产品 / 框架 | 厂商 / 性质 | 次数限制参数 | 默认值 | 计数口径 | 超限行为 |
| --- | --- | --- | --- | --- | --- |
| OpenAI Agents SDK | OpenAI（开源 SDK） | `max_turns` | **10**（None 可禁用） | 1 轮 = 1 次 LLM 调用，一轮可含多个并行工具调用 | 抛 `MaxTurnsExceeded` 异常；可注册 `error_handlers` 优雅降级 |
| Claude Agent SDK / Claude Code | Anthropic | `max_turns` / `max_budget_usd` | **均不设限**（可自行设置） | 工具调用往返轮次（只算含工具的轮） | `ResultMessage` 返回 `error_max_turns` / `error_max_budget_usd` |
| Claude API（服务端） | Anthropic | 服务端工具循环迭代数 | **10 次迭代** | 服务端采样循环轮数 | 返回 `stop_reason="pause_turn"`，可续跑 |
| Google ADK | Google | `max_llm_calls` / `LoopAgent.max_iterations` | **500**（0 = 不设限） | 单次 run 的 LLM 调用总数 | 达到上限停止 |
| LangGraph | LangChain | `recursion_limit` | **25**（create_react_agent） | 图节点步数；一次工具往返 ≈ 2 步（迁移换算 ×2+1） | 抛 `GraphRecursionError` |
| CrewAI | 开源 | `max_iter` | **25**（版本间有 20/25 差异） | 单个任务迭代次数 | 强制给出最佳答案 |
| AutoGen | 微软 | 团队 `max_turns`；agent `max_tool_iterations` | 群聊 **20** 轮 | 群聊轮次 / 工具迭代轮次 | 由 TerminationCondition 判定终止 |
| Semantic Kernel | 微软 | `toolCallLimit`；StepwisePlanner `max_iterations` | **15**（StepwisePlanner） | 工具调用循环次数 | 默认 Stop，可配置询问用户确认 |
| Magentic（Agent Framework） | 微软 | `max_round_count` / `max_stall_count` / `max_reset_count` | 示例 10 / 3 / 2 | 编排轮数 / 停滞轮数 / 重置次数 | 达到上限停止编排 |
| Dify | 开源 | `MAX_ITERATIONS_NUM`；`LOOP_NODE_MAX_COUNT` | **99** / 100 | 迭代节点次数 / 循环节点次数 | 超限中断 |
| 阿里云百炼 | 阿里 | ReAct 最大轮次 | **范围 1–50** | 工具调用轮次 | 自动退出工具调用并生成最终回复 |
| Coze / 扣子 | 字节 | 工作流节点执行上限 | 单次运行最多 **1000 节点**（含循环） | 节点数（更粗粒度） | 超限中断 |
| AutoGPT | 开源 | `MAX_AGENT_CYCLES` / `max_iterations` | **50** / 25 | 循环 / 步骤次数 | 强制终止 |

### 2.2 并行、工具数量与资源限制

| 产品 / 框架 | 单轮并行控制 | 工具数量限制 | 资源 / 预算 / 超时 | 终止与恢复 |
| --- | --- | --- | --- | --- |
| OpenAI Agents SDK | `parallel_tool_calls=false` 禁并行；执行侧 `max_function_tool_concurrency` 限并发 | 无硬性数量上限（受 token 约束） | `ModelSettings.timeout` | 模型无工具调用即结束；handoff 切换 agent；error_handlers 降级 |
| Claude Agent SDK / Code | 每轮可多个 `tool_use` 块并行 | 无硬性上限 | `max_budget_usd` 花费上限（覆盖子 agent） | 权限审批（白名单 / 自动批准 / 询问） |
| Claude API（服务端） | 每轮可多个 `tool_use` 块 | 无硬性上限 | 服务端默认 10 次迭代 | `pause_turn` 暂停续跑 |
| Google ADK | 支持并行 | 无硬性上限 | `max_llm_calls`（默认 500） | `exit_loop` 工具显式退出循环 |
| LangGraph | 节点级并行 | 无硬性上限 | 按 config 调大 `recursion_limit` | `GraphRecursionError` 报错 |
| CrewAI | — | 无硬性上限 | `max_rpm` 速率、`max_execution_time` 时长、`max_retry_limit=2` | 强制给出最佳答案 |
| AutoGen | 支持并行函数调用 | 无硬性上限 | token 用量可作终止条件 | TerminationCondition 体系（消息数 / 函数名 / handoff / token 用量） |
| Semantic Kernel | `ParallelToolCallsEnabled` | 无硬性上限 | `MaxTokens` / `MaxCompletionTokens` | 过滤器可实现工具黑名单与调用计数 |
| Magentic | — | 无硬性上限 | — | 经理 agent 调度；stall / reset 计数 |
| Dify | `MAX_PARALLEL_LIMIT=10` | **`MAX_TOOLS_NUM=10`**（默认） | `MAX_TREE_DEPTH=50`（路径深度） | 超限中断 |
| 阿里云百炼 | — | 无硬性上限 | 会话最多 50 轮（1h 有效）；单应用 100 QPS | 自动退出并生成最终回复 |
| Coze / 扣子 | 代码节点并发 500 / 空间 | — | LLM 节点超时默认 180s（0.1–600s） | 循环节点支持无限 + 条件终止；恢复运行最多 3 次；API QPS 20–500（按套餐） |
| AutoGPT | — | 无硬性上限 | token 预算上限；任务超时 | 强制终止 |

## 三、限制的设计维度（六类）

以「模型 → 工具调用 → 执行 → 回填 → 再模型 → 无调用则输出」循环为骨架，六类限制分别卡在不同环节：

| 维度 | 作用点 | 典型实现 | 说明 |
| --- | --- | --- | --- |
| ① 轮次 / 步数上限 | 循环总闸 | `max_turns` / `max_iterations` / `recursion_limit` / `max_iter` | 最普遍的防死循环手段；计数口径各产品不同（LLM 轮次 / 工具往返 / 图节点步数） |
| ② 单轮并行控制 | 单轮内 | `parallel_tool_calls` / 执行侧并发上限 | 控制模型一次输出多个工具调用的粒度与执行并行度 |
| ③ 工具可用性约束 | 入口把关 | 白名单 / 黑名单 / 审批模式 / 工具数量上限 | 权限与安全；Claude Code 审批模式、Dify `MAX_TOOLS_NUM=10` |
| ④ 资源与成本限制 | 执行侧 | `max_budget_usd` / `max_execution_time` / `max_rpm` / token 预算 | 按消耗兜底，防止成本失控 |
| ⑤ 终止条件机制 | 退出机制 | TerminationCondition / `exit_loop` / `pause_turn` / error_handlers | 灵活收尾：条件驱动、显式退出、暂停续跑、优雅降级 |
| ⑥ 上下文管理 | 记忆侧 | 消息截断 / token 窗口压缩 / 会话轮数上限 | 隐性限制：上下文越短，可继续调用的空间越小 |

## 四、关键发现与设计启示

### 1. 计数口径是最容易踩的坑

同样是「限制 10 次」：
- **OpenAI** `max_turns=10` → 10 次 LLM 调用（一轮可含多个并行工具）；
- **Claude** `max_turns` → 只数工具调用往返轮次；
- **LangGraph** `recursion_limit=25` → 按图节点步数计，一次工具往返占 2 步；从旧版 AgentExecutor 迁移时官方建议按 **×2+1** 换算。

### 2. 默认松紧度反映产品定位

| 产品 | 默认值 | 定位解读 |
| --- | --- | --- |
| Claude Agent SDK | 不设限 | 把控制权交给预算与审批，适合需长时间自主执行的场景 |
| OpenAI Agents SDK | 10 轮 | 偏保守，防止失控 |
| Google ADK | 500 次 LLM 调用 | 宽松的生产兜底值 |
| AutoGen 群聊 | 20 轮 | 多 agent 协作场景的折中 |
| LangGraph | 25 步 | 按图步数计的默认安全网 |
| Claude API 服务端 | 10 次迭代 | 服务端强制兜底 |

### 3. 超限行为有三派

1. **抛异常**：OpenAI（`MaxTurnsExceeded`）、LangGraph（`GraphRecursionError`）——由调用方显式处理；
2. **暂停可续**：Claude API 返回 `pause_turn`——开发者决定是否续跑，最灵活；
3. **降级收尾**：阿里百炼、CrewAI——直接生成最终回复，用户体验最平滑。

### 4. 国内平台更倾向「配额化」设计

百炼 ReAct 轮次上限 1–50、Coze 单次运行最多 1000 节点、Dify 默认工具数上限 10 / 迭代上限 99——面向业务配置者，用可感知的配额数字代替底层机制。

### 5. 对自建 Agent 系统的参考

- 不要只设一个次数上限，建议组合「**轮次上限 + 预算上限 + 超时 + 显式终止条件**」四道闸；
- 把「计数器」与「超限处理策略」**解耦**：计数到了不一定要报错，可以降级输出、暂停等人工确认、或提高上限续跑（OpenAI `error_handlers`、Claude `pause_turn` 都是这个思路）；
- 明确**计数口径**并在文档中写清楚，避免多框架混用时换算错误。

## 附录：落地时（§12.211）补的两点

正文的五节保持原样，下面是把它落到 KYLAB 时补的两条——**不是对上面结论的修正，是这张表没覆盖到的两个维度**。

### A. 「执行位置」要和「计数口径」一起说

表 2.1 把 Claude Agent SDK 的 `max_turns` 与 Claude API 的"服务端 10 次迭代"并排放，
但它们**不在同一个位置**：一个是客户端自控、一个是服务端强制。自建系统必须自己决定
"两道闸谁先生效、是叠加还是取小"——只看数字会把两件事读成同一件事。
KYLAB 的位置是：**唯一一道闸在服务端（我们自己就是服务端）**，客户端不额外设。

### B. 缺的第七类：超限的**用户可见性**

同样撞上限，用户看到的可能是三种完全不同的东西：

| 做法 | 用户看到什么 | 谁在用 |
| --- | --- | --- |
| 抛异常 | 一条报错 | OpenAI SDK、LangGraph |
| 静默截断 | 回答突然变差，**没有任何解释** | 多数产品（表里未标注） |
| 一条过程事件 | "本轮时间已用尽，按现有信息作答" + 重试入口 | KYLAB（`degraded` 标记） |

这一维直接决定体验，也比"上限设多少"更影响用户对模型的判断——
所以它值得作为第七类写进框架里，而 KYLAB 是有意选了第三条。

**补充（v0.32）**：第三条还可以再分出一档——"**发一条过程事件 × 可续跑**"。
Claude 的 `pause_turn` 属于第二派（暂停后可续）但默认对用户是不可见的；
KYLAB 现在两样都有：过程面板里那一行说清"停在哪、为什么"，
横幅上给「继续」让用户自己决定要不要接着做（见开发计划 §12.212）。

### C. KYLAB 的实际口径（正文没有、但引用时要对齐）
