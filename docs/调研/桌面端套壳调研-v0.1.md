## 0. 一页结论

1. **走 Tauri 2，不碰 Electron。** 硬数字：Electron v44.4.3 的运行时压缩包 `electron-v44.4.3-win32-x64.zip` **158,247,567 字节**（macOS arm64 130,115,866、Linux x64 123,038,272，GitHub Releases API 实测）——这是任何 Electron 应用的地板，**壳再薄也背着一个 Chromium+Node**。Tauri 用系统 WebView（Windows 是 WebView2），官方口径是一个最小应用 "can be less than 600KB in size"。
2. **我们比参考项目还要轻，因为它的"壳"里其实装着服务端。** deepseek-harness-desktop 第一次运行会**下载 Node 运行时与 Harness 内核**，然后跑 `dsh --profile <档案> --host 127.0.0.1 --port 3080`，界面是那个本地服务的 `http://127.0.0.1:3080`。它那 5MB 装的是「外壳 + 安装器」。我们的后端在 NAS 上，**壳里一个字节的服务端都不该有**：一个本地配置页 + 一个指向远端地址的 webview，就这些。
3. **加载远端地址是 Tauri 的一等公民**，三处都能用：`WebviewUrl::External(Url)`（官方文档原话 "An external URL. Must use either the http or https schemes."）、`tauri.conf.json` 里 `app.windows[].url`、运行时 `WebviewWindow::navigate(url)`。所以"填地址 → 跳过去"不需要任何花招。
4. **前端已经是同源相对请求**（`src/api/client.ts` 里 `API_BASE = '/api/v1'`，全站 25 处 `fetch` 都走它），签名链接也是相对路径（`app/services/artifacts.py` 里拼的是 `/api/v1/…?expires=…&signature=…`）。**结论：壳只需要知道"源"**——不用打包前端产物、不用注入 base URL、不用开 CORS。
5. **三个必须现在就设计进去的坑**（都是本次核实过的原话）：
   - **`http://` 内网地址 = 非安全上下文**：那里 `navigator.clipboard` 根本不存在。§12.205 刚修的 `execCommand` 兜底因此不是"顺手加固"，而是桌面端**唯一**能走通的路。另外 Linux/Windows 上 Tauri 还要显式开 `enable_clipboard_access(true)`。
   - **macOS 不配菜单就没有 ⌘C/⌘V**：官方原话 "macOS doesn't provide such method and is always enabled by default, but you still need to add menu item accelerators to use shortcuts." → 壳**必须**带一个带标准加速键的 Edit 菜单。
   - **正文里的外链**（检索结果那一行、回答里的 Markdown 链接都是 `target="_blank"`）在 webview 里不该把壳带跑：用 `on_new_window` + opener 插件接到系统浏览器；否则点了没反应或壳整个跳走。
6. **形态建议：两段式。** 本地配置页（自绘美术：品牌块 + 地址输入 + 连接 + 最近使用）→ 校验 `GET {地址}/api/v1/health` → 存盘 → `navigate` 到远端。**回到配置的入口给原生菜单 / 快捷键**，别指望在远端页面里放按钮：远端页面要能调 Tauri 命令，必须在 capability 里写 `remote.urls`（那是一个安全面，见 §3.4）。
7. **本机环境事实（实测）**：WebView2 运行时**已装**（153.0.4234.48）；Windows 10 1803+ / 11 随系统带走，所以 `webviewInstallMode` 用默认的 `downloadBootstrapper` 就是 **+0MB**；有 VS 2022、Node v24.14.0，**但没有 Rust 工具链**（`cargo` / `rustc` 都不在 PATH）——动手第一步是装 Rust。

## 1. 先把"套壳"定义清楚：三种做法

"套壳"这三个字下面其实是三种很不一样的东西，装错一种就白费：

| | A 纯壳加载远端 URL（**本文推荐**） | B 打包前端产物 + 指向远端 API | C 连服务端一起打包（参考项目那条路） |
| --- | --- | --- | --- |
| 壳里装什么 | 一个配置页 + 一个 webview | 整个前端 dist + 一个 API 地址配置 | 运行时（Node/Python）+ 服务端 + 前端 + 数据目录 |
| 谁发版 | 前端改了**不用重发壳** | 前端每次改动都要重发壳 | 前后端每次改动都要重发壳 |
| 首次运行 | 直接可用 | 直接可用 | 要下载/解包运行时（参考项目：Node 22 + 内核） |
| 安装包量级 | **个位数 MB** | 个位数 MB | 十几 MB 起，另加首次下载 |
| 版本漂移 | 无（壳与界面天然同版本） | 有：壳 v1 配服务端 v2 要兼容 | 有 |
| 适配我们吗 | **是**：后端本来就在 NAS 上 | 否：等于把 NAS 上的前端再拷一份，还制造版本漂移 | 否：我们的服务端要 Postgres + pgvector，装不进用户的笔记本 |

**B 唯一的优势**是"断网也能开"，可我们断网本来就没用（数据在 NAS）。
**C 是参考项目的选择，但它的原因与我们无关**：deepseek-harness 本身是一个**本地 Node 程序**，
所以它的壳不得不把运行时和服务端拖下来。我们的服务端是 NAS 上的一个 HTTP 服务——
壳与服务端之间**只有 HTTP 一种关系**。

## 2. 选型对比：Tauri 2 / Electron

| | Tauri 2 | Electron |
| --- | --- | --- |
| 渲染引擎 | **系统 WebView**（Windows: WebView2 / macOS: WKWebView / Linux: webkit2gtk） | 自带 Chromium（版本自己说了算） |
| 运行时体积（实测） | 不打包渲染引擎；官方："can be less than 600KB in size" | **158 MB**（win32-x64 zip，v44.4.3）、130 MB（darwin-arm64）、123 MB（linux-x64） |
| 装机后体积 | 参考项目安装包自称 5MB | 上面那些数字是压缩包，装完更大 |
| 内存 | 未核实（与系统 WebView 共享，多进程共享一个 WebView2 运行时） | 未核实具体数字，但每个应用一份 Chromium 进程树 |
| 三平台产物 | `.msi` / `.nsis`、`.dmg`、`.AppImage` / `.deb` | `nsis` / `dmg` / `AppImage` / `deb` |
| 一致的渲染 | 差一些：三个平台三个内核（调试要分平台） | 好：一个 Chromium 到处一样 |
| 参考项目 | **就是它**（README 原话 "Tauri 2 外壳（非 Electron）：更小的安装包、更低的内存占用、原生窗口"） | — |

**对我们的判断**：我们这套界面本来就是"给浏览器写的"（Vue 3 + Vite），
不需要 Electron 那套一致性兜底；而"轻量"是明确要求 → **Tauri 2**。
代价要说清楚：**三个平台三个内核**，同一处 CSS 要在三边各看一眼；
Linux 上参考项目已经在 README 里抱怨过 Wayland 黑屏与 AppImage 的 Abi 不匹配。

## 3. Tauri 2 能力核实（逐条带出处）

### 3.1 加载远端地址

- `WebviewUrl` 三个变体：`External(Url)` / `App(PathBuf)` / `CustomProtocol(Url)`；
  `External` 的文档原话：**"An external URL. Must use either the http or https schemes."**
  → `http://192.168.1.10:8080` 合法。
- 创建：`WebviewWindowBuilder::new(manager, label, WebviewUrl)`；
  `tauri.conf.json` 的 `app.windows[].url` 同样接受绝对 http(s) 地址
  （另一档是"app URL 的路径部分"，例如 `users/john`）。
- 运行时跳转：`WebviewWindow::navigate(&self, url: Url) -> Result<()>`
  （另：`url()` 读当前地址、`eval()` 注入 JS、`reload()`）。

### 3.2 三个平台各自要什么

| | Windows | macOS | Linux |
| --- | --- | --- | --- |
| 渲染引擎 | WebView2 | WKWebView（系统自带） | webkit2gtk |
| 系统自带？ | Win10 1803+ / Win11 随系统；本机实测已装 **153.0.4234.48** | 是 | 否，打包时链接 |
| 最低系统 | Win10+（参考项目口径） | macOS 10.15+（参考项目口径） | AppImage / deb（参考项目口径） |

### 3.3 配置存哪儿

- 官方插件 `tauri-plugin-store`：**持久化 key-value**，要求 **Rust 1.77.2+**；
  Rust 侧 `.plugin(tauri_plugin_store::Builder::new().build())`，
  JS 侧 `const store = await load('store.json', { autoSave: false })`，
  另有 `new LazyStore('settings.json')` 首次访问才加载。
- 官方文档**没写**数据文件落在哪个目录（未核实）——真要用，实测一次 `app_config_dir()` 更稳。
- 我们只存**一个字符串**（服务器地址）加几条最近记录：插件够用，但也可以直接在 Rust 里
  写 `app_config_dir()/config.json`（少一个依赖，行为完全可控）。**建议后者**，
  理由见 §5.4：这个文件是"壳的唯一状态"，越可见越好排查。

### 3.4 远端页面能不能调 Tauri 命令（决定"回到配置"怎么做）

- 默认**不能**。官方原话：API "is only accessible to bundled code shipped with the Tauri App."
- 要放行，得在 capability 里加 `remote`：

  ```json
  {
    "identifier": "remote-tag-capability",
    "windows": ["main"],
    "remote": { "urls": ["https://*.tauri.app"] },
    "permissions": ["nfc:allow-scan"]
  }
  ```

- 官方 Caution：**"On Linux and Android, Tauri is unable to distinguish between requests from an embedded `<iframe>` and the window itself."**
  → 给远端页面开权限等于"任何能进到那个页面的东西都能调这些命令"。
- **结论**：v1 不给远端开 IPC。回到配置走**原生菜单 / 快捷键 / 托盘**，
  不进远端页面的安全面。

### 3.5 注入脚本、拦导航、管新窗口（都在 stable 的 `WebviewWindowBuilder` 上）

- `initialization_script(self, script)` —— 全局对象建好之后、HTML 解析之前跑，**只在主框架**；
  `initialization_script_for_all_frames(...)` 是所有框架。
- `on_navigation<F: Fn(&Url) -> bool>` —— **返回 false 就取消导航**。
- `on_new_window<F: Fn(Url, NewWindowFeatures) -> NewWindowResponse>` —— `window.open` / `target="_blank"` 的处置。
- 另有 `on_page_load`、`on_download`、`on_document_title_changed`、`on_web_resource_request`。
- 窗口：`decorations(bool)`、`title(...)`、`transparent(...)`
  （文档标注 "Available on crate feature macos-private-api or non-macOS only"）。
- **多 webview（在一扇窗里"上面一条本地工具条 + 下面远端内容"）**：docs.rs 的
  `WebviewWindowBuilder` 页面上**没有** `add_child`，`WebviewBuilder::new` 标注 gated by `unstable`
  ——也就是说这条"最好看"的路要开不稳定特性。**未核实其在 stable 下可用**，v1 不用它。

### 3.6 剪贴板（这条直接影响我们刚修的东西）

`enable_clipboard_access` 的文档原话：

> "Enables clipboard access for the page rendered on Linux and Windows."
> "macOS doesn't provide such method and is always enabled by default, but you still need to add menu item accelerators to use shortcuts."

两条推论：
1. **Linux / Windows 上要显式开**，否则页面根本拿不到剪贴板；
2. **macOS 上要带菜单加速键**，不然 ⌘C / ⌘V 在 webview 里是死的。

### 3.7 Windows 打包与 WebView2 体积

官方表格（`webviewInstallMode`）：

| 模式 | 需要联网 | 增加体积 | 说明 |
| --- | --- | --- | --- |
| `downloadBootstrapper` | 是 | **0MB** | **默认** |
| `embedBootstrapper` | 是 | ~1.8MB | Win7 + msi 支持更好 |
| `offlineInstaller` | 否 | ~127MB | 内嵌 WebView2 安装器 |
| `fixedVersion` | 否 | ~180MB | 内嵌固定版本 WebView2 |
| `skip` | 否 | 0MB | 官方标注"不推荐" |

官方同页：**"On Windows 10 (April 2018 release or later) and Windows 11, the WebView2 runtime is distributed as part of the operating system."**
→ 我们保持默认，**+0MB**，只有极老的机器才需要联网装一次 WebView2。

## 4. 参考项目解剖：dsh-tauri/deepseek-harness-desktop

### 4.1 它是什么（README + GitHub API，2026-09-20）

- 描述原话："DeepSeek Harness Tauri 桌面版 | Only 5mb installer, zero environment setup, preset plugins, Windows / macOS / Linux."
- 2,368★，主语言 TypeScript，topics 里有 `tauri`；创建于 2026-08-14（很新）。
- 许可：MIT + 附加非商用条款（**我们只能参考做法，不能照抄代码**）。
- 平台口径：Windows 10+ · macOS 10.15+ · Linux（AppImage / .deb）；"首次运行需要网络"。

**它的运行方式**（README 原话）：首次运行下载 Node 运行时与 Harness 内核 →
跑 `dsh --profile <档案> --host 127.0.0.1 --port 3080`（`DSH_HOME=~/.dsh`）→
"随后直接进入 http://127.0.0.1:3080 的 Harness 界面"。
**所以它的"套壳"是套一个自己刚下载下来的本地服务**——这正是我们不需要的那一半。

### 4.2 仓库结构（GitHub contents API 实测）

- 顶层：`.github`、`archive`、`assets`、`docs`、`packages` + 根级 `package.json`、`index.html`、`AGENTS.md`、`genapi.config.ts`、`bump.config.ts`。
- `packages/` 下 14 个包，按职责切得很细：
  `dsh-tauri`、`dsh-tauri-ui`、`dsh-tauri-bundle`、`dsh-tauri-connection`、
  `dsh-tauri-model-config`、`dsh-tauri-panel-extension`、`dsh-tauri-panel-scheduler`、
  `dsh-tauri-pet`、`dsh-tauri-rightclick`、`dsh-tauri-session`、`dsh-tauri-tsdown`、
  `dsh-tauri-turnrewind`、`dsh-tauri-worktree`、`.test`。
- CI：`.github/workflows/` 下 `build-windows.yml`、`build-macos.yml`、`build-linux.yml`、
  `build-test.yml`、`ci.yml`、`release.yml`（六条：**三平台各自交叉编译 + 一条汇总 release**）。
- `tauri.conf.json` / `Cargo.toml`：**未核实**（递归树接口返回被截断，没拿到这两个文件的位置）。

### 4.3 抄什么、不抄什么

| 它的做法 | 我们 |
| --- | --- |
| Tauri 2 而不是 Electron | **抄**。理由见 §2 的数字 |
| 三平台各一条 CI + 一条 release | **抄**（我们要发版时才需要） |
| `.deb` / `.AppImage` 明确列出来 | **抄**（NAS 用户里 Linux 比例不低） |
| 首次运行下载 Node 运行时 | **不抄**。我们的服务端是远端 HTTP，不需要运行时 |
| 跑本地 `127.0.0.1:3080` 再加载它 | **不抄**。我们直接加载 NAS 地址 |
| 一堆面板插件（pet / rightclick / scheduler…） | **不抄**。套壳就一个配置页，功能都在远端界面里 |
| 自更新 | **暂不抄**（它有自更新是因为内核在快速迭代） |

## 5. 建议方案（KYLAB Desktop 草案）

### 5.1 形态

```
┌───────────────────────────────────────────────┐
│  KYLAB Desktop                      ─  □  ✕   │  ← 原生标题栏（v1 不自绘）
├───────────────────────────────────────────────┤
│                                               │
│                    ╭─────╮                    │
│                    │ KY  │                    │  ← 品牌块：本地资源，随壳走
│                    ╰─────╯                    │
│                  连接你的知识库                │
│                                               │
│   服务器地址                                   │
│   ┌───────────────────────────────────────┐   │
│   │ http://192.168.1.10:8080              │   │  ← 回车即连
│   └───────────────────────────────────────┘   │
│                                               │
│   ┌───────────────────────────────────────┐   │
│   │              连接并进入                │   │
│   └───────────────────────────────────────┘   │
│                                               │
│   ⚠ 连不上：无法连接到该地址（检查 NAS 开着没、   │  ← 就地报错，不跳走
│     地址端口对不对）                           │
│                                               │
│   最近使用                                     │
│   · http://192.168.1.10:8080   刚刚            │  ← 一条即点即连
│   · http://nas.local:8000      3 天前          │
└───────────────────────────────────────────────┘
```

界面语言与美术沿用现有 token（`--Bg-*` / `--Labels-*` / `--space-*`），
配置页**就是产品的一部分**，不做第二套视觉。

### 5.2 连接流程（含失败态）

1. 用户输入（自动补 `http://`；只填 `192.168.1.10:8080` 也认）；
2. `GET {origin}/api/v1/health`（**实测返回** `{"status":"ok","app":"kylab","version":"0.2.0","api_version":"v1"}`）
   —— 顺便校验"这确实是 KYLAB"，连上后可以在配置页显示服务端版本，用户一眼知道 NAS 是哪一版；
3. 成功 → 存盘 → `navigate({origin})`；失败 → **停在配置页**，把原因分成三类说清楚
   （连不上 / 不是 KYLAB / 版本不兼容），不要只给一句"失败"。

### 5.3 回到配置的入口（三个，都不经过远端页面的权限）

- 原生菜单：**「连接」→「更换服务器…」**（⌘, / Ctrl+,）；
- macOS/Linux 的 Edit 菜单：Copy / Paste / Select All 标准 role（§3.6 的必要条件）；
- 托盘图标（可选）：右键「打开/更换服务器」。

### 5.4 存哪儿

`app_config_dir()/config.json`，**纯手工读写**（一个字符串 + 最近 5 条 + 窗口尺寸）：

```json
{ "server": "http://192.168.1.10:8080",
  "recent": [{ "url": "http://192.168.1.10:8080", "at": "2026-09-20T10:00:00Z" }],
  "window": { "width": 1280, "height": 800 } }
```

不用 `tauri-plugin-store` 的理由：它解决的是"多键、并发、自动保存"，
而我们只有两个键；而"配置不生效"这类问题，一个肉眼可读、路径明确的 JSON
比插件的黑盒文件好排查。什么时候该换成插件：键数上到十几个以上。

### 5.5 外链、下载、新窗口

- `on_new_window`：外链一律 `opener` 插件丢给系统浏览器（回答里的链接、检索结果的网址），
  壳自己不跟着跑；
- `on_navigation`：**只允许留在配置的那个 origin 内**（加白名单），
  别的地址要么丢系统浏览器、要么拒绝——否则这个壳就成了一个没有地址栏的浏览器；
- 文件下载（导出的 docx / xlsx / csv）：交给 WebView 的下载事件，
  存到系统下载目录并在完成后提示，**不要**在壳里做自己的下载管理器。

### 5.6 目录与构建

```
desktop/
  README.md            # 怎么跑、怎么打包、怎么改服务器地址的默认值
  src/                 # 配置页：index.html + shell.css（无打包器，见下）
  src-tauri/
    Cargo.toml
    tauri.conf.json    # app.windows[0].url 指向本地 index.html
    src/main.rs        # 建窗、菜单、opener、config.json 读写
    icons/
```

- **配置页不引 Vue / 不引打包器**：整页就两个状态（未连接 / 连接中报错）、
  一个输入框一个按钮，手写 HTML + CSS（复用 token）比再养一条前端构建链划算。
  将来若要工具条/多页，再引 Vue 也不迟——那时它和主前端共用组件才有意义。
- 与主仓库的关系：`desktop/` 是**独立构建单元**，不参与 `frontend` 的 vite/vitest，
  也不参与 `scripts/lint.sh` 里前端那几步；`cargo fmt` / `clippy` 等接了 Rust 之后再说
  （**本机现在没有 Rust**，见 §0.7）。

## 6. 对我们现有代码的影响

### 6.1 后端：**不用改**

`/api/v1/health` 已经能用（实测 200），`CORS` 不用动（壳加载的是同源页面），
签名链接本来就是相对路径。**一个字都不用改**。

### 6.2 前端：只有"非安全上下文"这一件事，逐条查过

壳加载的是 `http://` 内网地址，所以要在非安全上下文里活。全站扫描（`frontend/src`）：

| 只在安全上下文可用的 API | 出现次数 | 结论 |
| --- | --- | --- |
| `navigator.clipboard` | 4 | **已修**（§12.205：`execCommand` 兜底） |
| `crypto.subtle` | 0 | 无影响 |
| `navigator.mediaDevices` / `getUserMedia` | 0 | 无影响（将来做语音输入要注意） |
| `serviceWorker` | 0 | 无影响 |
| `Notification` | 0 | 无影响 |
| `localStorage` | 34 | 非安全上下文**照常可用** |
| `fetch` / SSE | 25 | 同源，照常可用 |

**结论：前端这一层，桌面端唯一的额外要求就是剪贴板那条兜底**（它已经在 v0.29 修好了）。

### 6.3 部署侧

NAS 只需要能被局域网访问到（现在就是）。**如果将来上 HTTPS**：
自签名证书会让 WebView2 / WKWebView 弹证书错误页，而**Tauri 是否提供"忽略证书错误"的开关本次未核实**——
建议走"内网 DNS + 真证书"（例如 Tailscale / caddy）这条路，别指望壳去忽略证书。
