# Kimi 界面逐处对照

本文是**组件层的取值依据**，与《Kimi 设计 token 对照表》配套：那一份管颜色与字阶（已落地），
这一份管**token 覆盖不到的东西**——结构、尺寸、动效、弹层的内部构造、以及"哪里该有小字"。

## 0. 口径

- **参考对象**：`https://www.kimi.com/` 的对话页（未登录态；侧栏与输入框在未登录时已经可见，
  弹窗取登录弹窗）。视口 `1280×860`，深浅两套主题分别取。
- **取值方式**：浏览器里读 `getComputedStyle` + `getBoundingClientRect`，不靠目测。
  下表的"Kimi"列与"KYLAB"列都是**实测值**。
- **不做的事**：不新增 Kimi 有、我们没有的菜单（PPT / 集群 / 定时任务 / Kimi Code 等）。
  对照的是**同一个东西在两边怎么画**，不是把它的功能搬过来。

## 1. 左下侧边栏（用户点名的重问题）

| 项 | Kimi | KYLAB（改前） | 结论 |
| --- | --- | --- | --- |
| 页脚上分隔线 | **无** | `border-top: 1px` 通栏 | 多一条线 |
| 页脚内边距 | `8px` | `12px 16px` | 水平多 8px |
| 账号行容器 | **完全透明**，无边框、无圆角 | `bg-surface` 填充 + `1px` 边框 + `10px` 圆角 | 多一个盒子 |
| 账号行外框 | `224×44`，与导航列同一条 8px 起始线 | `207×38`，从 16px 起 | **两栏没对齐** |
| 头像 | `28×28` 圆形 | `16×16` 线稿图标 | 小一半，且不是头像 |
| 名字 | `14px/20px 500` | `14px/20.58px 500` | 行高差 0.58px |
| 行右端 | 一个 `44×44` 图标按钮 | `14px` 折叠箭头 | 形态不同 |
| 悬停 | 整行填充 `Fills-F1` | 同 | ✓ |

**为什么会"看着很严重"**：侧栏里其余每一行都从 `x=8` 开始、宽 `223`，
只有页脚那个盒子从 `x=16` 开始、宽 `207`——**同一栏里两条起始线**，
扫视时它像"没对齐"，而不是"故意内缩"。叠加上下两条线（页脚上沿一条、
`.side-section` 上沿一条）和一个常驻填充底，页脚就成了整条侧栏里最重的一块。

| 导航图标 | `18×18` | `16×16` | 小 2px |
| 导航项 | 高 40 / 圆角 12 / `padding 0 8px` / `gap 6px` | 同 | ✓ |
| 图标与文字色 | 静止即 `Labels-Primary` | 同 | ✓ |
| 分区标题「项目」 | `14px/20px`，`Labels-Secondary` | `14px/20.58px`，0.42 | 基本一致 |
| 「新建会话」 | **填充块按钮**：`#1f1f1f` 底 + `1px` 边框 + 圆角 12 + 高 45，字重 500 | 与导航项同形（无填充） | 形态不同 |
| 快捷键提示 | 两枚 `20px` 高的小片，字 `14px`、`Fills-F2` 底、**无边框**、`padding 0 4px` | 单片，字 `10px`、带 1px 边框 | 字太小、多边框 |
| 区块之间 | `gap: 12px`，**没有分隔线** | `.side-section` 有 `border-top` | 多一条线 |

**一个有意的反转**：`.nav-item.new-chat` 上一版被改成"和导航项一样的形态"，
理由写在代码注释里（"同一栏里两种按钮形态，用户得先分辨哪个能点"）。
本轮按 kimi.com 对话页的实测改回**填充块按钮**——它的侧栏里唯一有底有框的就是这一颗，
其余全是透明的行。也就是说它对"哪个是主操作"的回答不是"都不强调"，
而是**只强调一个**。这条比"形态统一"更接近用户的实际用法。

## 3. 动效

| 项 | Kimi | KYLAB（改前） |
| --- | --- | --- |
| 列表行 / 导航项 | `background-color .15s, color .15s, box-shadow .15s` | 同 ✓ |
| 按钮 | `background-color .3s ease-in-out, box-shadow .3s, color .3s, opacity .3s` | **没有这一档**，各组件自写 |
| 发送按钮 | `background-color .15s cubic-bezier(.4, 0, .2, 1)` | 自写 |
| 侧栏折叠 | `transform .3s ease-in-out` | `width .18s, flex-basis .18s` |
| 折叠开关的图标 | 自带 `data-animation-icon`，进出各 `.2s` 的形变 | 静态图标 |

**两档而不是一档**：Kimi 的动效只有两种速度——`.15s` 给"底色/字色的状态切换"，
`.3s ease-in-out` 给"按钮这种有体量的东西"。我们此前只有 `.15s` 一档，
于是按钮的悬停与列表行的悬停同速，读起来"按钮太急"。

**侧栏折叠是 `transform` 不是 `width`**：它的折叠是内容整体左移（`.3s ease-in-out`），
主内容区**不重排**。KYLAB 是 `width` 动画——聊天应用必须让内容区让出空间，
所以这条**不改**，只把时长对齐到 300ms。

**折叠态不悬浮展开**：实测在折叠状态下把鼠标停在左缘 1 秒，`nav-item` 的 `x` 仍是 `-232`，
`aside` 宽度仍是 240。Kimi 用的是**显式开关**，没有 hover 展开。
我们的行为与它一致（也是显式开关），这条不用改。

## 4. 下拉菜单

| 项 | Kimi | KYLAB（改前） |
| --- | --- | --- |
| 容器底 | `#292929`（`Bg-Tertiary` 深色档） | `#121212`（`Bg-Primary`） |
| 容器圆角 | **16px** | 10px |
| 容器内边距 | **8px** | 4px |
| 容器边框 | 无 | 1px |
| 单项（单行） | 高 **36**、圆角 10、内边距 8 | 高 30、圆角 10、内边距 8 |
| 单项（双行） | 高 **58** | — |
| 主行 | `14px/20px 400`，`Labels-Primary` | `14px/20.58px 400`，`Labels-Secondary` |
| **副标题小字** | **有**：`13px/18px`、`Labels-Tertiary`、`margin-top: 4px` | **无** |
| 选中标记 | 右端**蓝色对勾** `20×20`（`Colors-KMBlue`） | 无 |
| 分组分隔 | `.divider` 高 17（`8px + 1px + 8px`） | 无 |
| 二级入口 | `36px` 行 + 右端 `进阶 ›` | 无（我们暂无对应功能） |

**"菜单下是否有小字"的答案**：**侧栏导航没有，下拉菜单有**。
导航项一律单行（图标 + 名称），唯一的例外是 "Kimi Work" 后面跟一枚蓝色 `Beta` 徽章——
那是徽章不是副标题。而下拉菜单里**每一项都是"标题 + 一行说明"**：
`14px/20px` 的主行下面压一行 `13px/18px` 的灰字，间距 4px，说明这档模式擅长什么。

我们此前的菜单只有主行、且用二级灰——那正好是把 Kimi 的两个层级合成了一个：
**它用"更大的字号 + 更亮的颜色"表示主行，用"更小的字号 + 三级灰"表示说明**，
我们只有主行，还把它压到了二级灰。

## 5. 弹窗

| 项 | Kimi | KYLAB（改前） |
| --- | --- | --- |
| 遮罩 | `rgba(0,0,0,.6)` | `--MaskBg-Base` = `.6` ✓ |
| 外壳 | `#181817`（画布色）、圆角 **20**、**无边框、无阴影** | `#121212`、圆角 20、**1px 边框 + `0 4px 14px` 阴影** |
| 头部带 | 高 **72**、左内边距 24 | 高 53、内边距 `12px 16px` |
| 内层卡片 | `#121212`、圆角 16、内边距 `40px 46px 36px` | 无这一层（弹窗自己就是卡片） |
| 表单输入 | 高 **44**、圆角 **12**、内边距 `12px 16px`、底 `#ffffff19` | 高 32（`--control-height`）、圆角 10 |
| 主按钮 | 高 **44**、圆角 **12**、字 `16px/24 500` | 高 32、圆角 10 |

Kimi 的弹窗**靠两层底色分开**（外壳 `#181817` / 内卡 `#121212`），
没有描边也没有投影——描边的活是那两层色差在干。我们反过来：
单层 `#121212` + 描边 + 投影。去掉描边与投影之后，色差本来就在，层级不会丢。

## 6. 输入框（对话页）

| 项 | Kimi | KYLAB（改前） |
| --- | --- | --- |
| 圆角 / 最大宽 | **24px / 768px** | 同 ✓ |
| 高度 | 130px | 125px |
| 底色 | **`#1f1f1f`**（`Bg-Secondary`，比画布**亮**一档） | `#121212`（`Bg-Primary`，比画布**暗**一档） |
| 边框 | `1px rgba(255,255,255,.06)` | 无 |
| 阴影 | `0 5px 16px -4px rgb(0 0 0 / 7%)` | `0 1px 2px rgb(0 0 0 / 4%)` |

**方向搞反了**。深色下 Kimi 的层级是"抬起来的那层更亮"（画布 `#181817` → 输入框 `#1f1f1f`），
token 表里也照着写了（`--bg-group: --BgGp-Secondary` = `#1f1f1f`），
但输入框取的是 `--bg-surface`（`#121212`）——于是它比画布还暗，
读起来是"凹进去的一块"而不是"浮起来的一块"。

## 7. 小字：哪里该有、哪里不该有

| 位置 | Kimi | 结论 |
| --- | --- | --- |
| 侧栏导航项 | 无小字 | 我们也没有 ✓ |
| 侧栏分区「项目」 | 只有标题，**没有空态说明** | 我们写了「还没有项目。项目决定"在哪儿干活"，会一直留着。」 |
| 侧栏分区「对话」空态 | 一行「登录以同步历史会话」 | 我们有「还没有对话。点上面的加号开始。」（两行） |
| 下拉菜单项 | **有小字** | 我们没有 |
| 对话输入框占位符 | 「尽管问，或做个 Agent 任务…」 | 我们有「纯对话，不查知识库…（回车发送，Shift + 回车换行）」 |
| 弹窗表单 | 无说明性小字 | — |

**规律**：Kimi 的小字只出现在**它解释了"选这个会得到什么"**的地方（菜单里的模式说明）；
它在**界面自己已经说清楚**的地方一律不加（分区标题、输入框）。
空态是一行**状态**（"还没有 / 登录以…"），不是一句**说明**。

## 8. 尚未对齐的一条：内容区应该是"抬起来的卡片"

本轮**发现了但没改**，因为它的影响面是 35 处调用点 + 每个页面，必须单独一轮做。

Kimi 的应用壳是三层：

| 层 | token | 深色 | 浅色 | 位置 |
| --- | --- | --- | --- | --- |
| 页面底 | `Bg-GroundPC` | `#181817` | `#fbfaf9` | 侧栏那一条 |
| 内容卡片 | `Bg-Primary` | `#121212` | `#fff` | 右侧那张**圆角 16、四周留 6px** 的卡片 |
| 卡内浮起层 | `Bg-Secondary` / `Bg-Tertiary` | `#1f1f1f` / `#292929` | `#f5f5f5` / `#fff` | 输入框、菜单 |

实测：`aside.sidebar` 盒子 `[0,0,240,860]`、背景 `#181817`；
`div.main` 盒子 `[6,6,1268,848]`、背景 `#121212`、圆角 16。
所以**侧栏与内容之间没有分隔线**——边界是"两块不同颜色的面"这件事本身。
Kimi 的 `aside` 没有 `border-right`（实测 `0px none`）。

KYLAB 现在是：`.content` 用 `--bg-canvas`（`Bg-GroundPC`），
与侧栏**同色**，靠一条 `border-right` 分开；面板用 `--bg-surface`。

对齐它需要两步，**必须一起做**，只做第一步会让卡内面板与卡片同色而消失：

1. `.content` 改成 `--bg-surface` + `border-radius: var(--radius-panel)`，
   `.shell` 加 `padding: 6px 6px 6px 0` 与 `background: var(--bg-canvas)`，
   同时删掉 `.sidebar` 的 `border-right`；
2. 全站 35 处 `var(--bg-surface)` 里"卡内浮起层"那一类（卡片、面板、输入框底）
   改到 `--bg-subtle` / `--bg-group`。

第 2 步是**逐页目视**的活：35 处里有一部分是弹层（本轮已迁移到 `--bg-menu`），
剩下哪些是"卡片"、哪些是"页面底"，得一个个看，改完每个页面都要复验。

### 10.1 补一条实测证据：**这个问题已经在页与页之间分叉了**

任务中心（`/tasks`）的「运行负载」面板底是 `--bg-subtle`（`#1f1f1f`）——
**比内容区亮**，方向是对的；
能力页（`/capabilities`）的卡片底是 `--bg-surface`（`#121212`）——
**比内容区暗**，方向是反的。

两个页面并排看就会发现：一块"抬起来的板"和一堆"凹下去的卡片"同时存在。
这不是两个页面各自的取舍，是**规则没定**留下的空间——`--bg-surface` 这个名字
既被当成"页面底"又被当成"抬起来的卡片"，用哪个取决于写那个页面时的直觉。

所以 §8 的迁移不只是"对齐 Kimi"，也是**把这条已经分叉的规则收回来**。

## 9. 「新建项目 / 工作区」的形态

参考对象只有一处可用：**kimi.com 的 `/project/create`**。
Kimi Work（`/products/kimi-work`）与 Kimi Code（`/code`）都是**桌面端的落地页**，
没有公开 web 应用；Kimi Code 的落地页里那张产品图显示，它的会话头上是**项目名**
（`landing-page`）而不是绝对路径。所以"它怎么选目录"这件事，没有可复核的答案。

### 实测到的那一处

点侧栏「项目」下面的「新建项目」，**路由会变**（`/project/create?project_create_from=sidebar_plus`），
页面内容只剩两样东西：

| 元素 | 实测 |
| --- | --- |
| 标题 | 「新建项目」 |
| 副标题 | 「同一件事，都在这里聊」 |
| 图标选择 | 一排文件夹图标，中间那个放大 + `+` 覆盖，悬停提示「点击切换图标」 |
| 输入 | **只有一个**：`取个名字`（`.project-create-input-wrap` 424×40、圆角 12、底 `rgba(255,255,255,.05)`） |

**它的项目不绑目录**——所以"一个输入框搞定"对它是成立的。

### 对我们的结论

我们的工作区**必须有 `root_path`**：它是 Agent 文件操作的边界，
后端 `validate_root_path` 有三道校验（必须已存在、拒绝文件系统根与系统关键目录、
拒绝指向数据目录）。这条是安全约束，砍不掉，所以"单字段"照搬不过来。

于是形态取**弹窗**而不是独立页：

- 与 Kimi 同构的地方是**专注**——没有清单、没有页面壳、一次只问这一件事；
- 不同的地方是**不占一次导航**（Kimi 那一次跳转之后，侧栏的「新建项目」还停在选中态，
  关掉再回来要再点一次）；
- **不用下拉框**：下拉框的语义是"从已有的 N 个里挑一个"，而新建是产出。
  我们也没有可填充的候选项（工作区通常只有一两个，没有"最近用过"这种列表）。

顺带清掉一处冗余：根目录那格下面原先还有一行 `text-micro` 小字
（"必须是**已存在**的目录（绝对路径）。它决定 Agent 能碰哪儿……"），
而它上面那颗 InfoTip 说的基本是同一件事。按规范 §5.1（界面里不写解释性小字）
**删掉那行**，把那行里 InfoTip 没有的信息（"绝对路径"、"不会替你建一个空目录"）
并进 InfoTip 的文案——信息没丢，只是从常驻改成按需。
