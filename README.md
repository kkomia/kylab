# KYLAB

一个**本地优先的知识库 RAG 系统**：把散落的文档收进来，用自己的模型提问，
拿到带原文引用的回答；AI 笔记补上「写」的一环，记录可一键入库成为可检索语料。
对外通过 **REST (OpenAPI) + MCP Server + 官方 Skill** 三条等价方式提供能力。

> 当前状态：**M0–M7 主干全部完成**，最新版本 **v0.2.0**（2026-09-17）——这一版是
> 一次破坏性的存储更换（SQLite → PostgreSQL）加上 0.1.0 之后全部工作的合集；
> 逐条变更见[变更记录](CHANGELOG.md)。迭代依据是
> [知识库产品对标调研](docs/调研/知识库产品对标调研-v0.1.md)与
> [Agent 工作区与能力层设计](docs/设计/Agent-工作区与能力层设计-v0.1.md)：
> 笔记、知识库 Wiki、记忆层、Agent 工具循环与子 Agent、技能与外部 MCP、
> 会话沙箱、Office 导出、联网。
> 门禁基线：后端 2176 条用例（需 PostgreSQL 测试库，见[快速开始](#快速开始)）、前端 526 条用例；
> 最近一次全绿记录见[开发计划 §12](docs/计划与记录/开发计划-v0.1.md)，跑法以 `scripts/ci.*` 为准。

## 定位演化（与最初设计的差异）

最初设计（[架构设计 v0.2](docs/设计/架构设计-v0.2.md) 成稿时）把它定位成**纯向量检索服务**：
只返回检索结果原文、不做任何 LLM 预处理、不做文档编辑。开发过程中定位发生了五次明确偏移：

1. **从「检索服务」到「检索 + 问答」**：v0.1.0 加入对话——流式回答、强制引用原文、
   引用存快照（回看时依据的仍是当时那几段），对话成为主入口；
2. **从「不碰 LLM」到「LLM 深度参与」**：思考模式（8 家供应商方言适配）、
   上下文压缩、会话标题生成、笔记 AI 处理；
3. **新增笔记板块**（对标腾讯 ima，见[调研报告](docs/调研/笔记功能调研-v0.1.md)）：
   Tiptap 富文本编辑 + AI 处理 + 一键入库知识库；此后同一思路又长出知识库 Wiki 与记忆层；
4. **从「知识库问答」到「带工具的个人 Agent」**：对话主流程换成了工具循环，
   知识库从「唯一通道」降级成**其中一个工具**；再叠上工作区、技能与外部 MCP 插件、
   子 Agent 派生、会话沙箱。注意**对外的检索通道没有跟着变**——它至今只返回检索结果原文；
5. **存储层换过一次地基**：最初承诺的「单机零中间件」（SQLite + sqlite-vec + FTS5）
   已作废——SQLite 实现被整体删除，**PostgreSQL 成为必选依赖**
   （pgvector 向量 + tsvector 全文 + DuckDB 表格副本）。这是本项目唯一一次
   破坏性地基更换，也是本 README 此前失真最久的一处。

**当前地基**：PostgreSQL 必选 + 对象存储（本地目录或 S3 兼容）+ DuckDB；
异步摄入流水线（租约/退避/断点续跑/协作取消）；逐文件动态解析路由。
从最初设计留到今天的只有两条：检索通道「返回原文」的语义，以及**单机可部署**——
PG 与后端同机即可，不需要 Redis、消息队列或独立检索服务。

> 过期的定位叙述不留在正文里：本 README 只描述**今天**是什么，翻旧账请看 git 历史
> 与[变更记录](CHANGELOG.md)。

## 它是什么

- **摄入流水线**：上传 → 逐文件探测（文本层 / 扫描件 / 版式）→ 解析 → 切块 → 向量化 → 索引。
  云端解析（MinerU / PaddleOCR）与本地解析按文件动态路由，首选失败自动降级换通道，
  路由决策写进任务记录——控制台能看到「这个文件为什么走了 OCR」。
  所有格式统一转 Markdown，向量化只针对 Markdown。
- **检索**：向量 + BM25 双通道 RRF 融合，可选 rerank，元数据过滤，
  「小块检索、大块阅读」——命中的小块自动补全为整段小节；检索调试台可复核效果。
- **对话与 Agent**：SSE 流式 + 平滑输出，强制引用原文（`[n]` 对应下方出处，
  出处卡片可就地展开看全文）；思考模式三档强度；**主流程是工具循环**——
  知识库检索、联网搜索与取页、Office 导出（docx/xlsx/pptx/pdf）、子 Agent 派生、
  **读工作区里的文件、在沙箱里跑命令、对表格副本跑只读 SQL、挂定时任务**
  都是工具，工具能碰哪些库、哪些目录按会话与工作区范围收口；上下文超限自动压缩，
  撞上步数/时间上限可以**接着上一轮继续**（不用从头再来）；会话与消息落库，
  引用快照可回看（回看时依据的仍是当时那几段）。
- **工作区与能力层**：账号 → Agent → 工作区（项目）→ 会话的归属链；
  能力层是**技能**（`SKILL.md` 渐进式展开）与**外部 MCP 服务**（照 Claude Code
  的权限模型分 allow / deny / ask / sandbox 四档）；会话沙箱给执行类工具一个
  受限目录，与工作区是两件事。
- **到点自己做事**：定时任务（cron / 一次性）挂在任务中心里，到点跑一轮问答，
  结果落进一条会话；「立即跑一次」可以当场试。执行走任务队列，
  失败重试与进程崩溃后的回收都复用同一套。
- **笔记 / Wiki / 记忆**：笔记是 Tiptap 富文本（图文混排 / 待办 / 占位引导），
  Markdown 落库为唯一事实源，`attach_note` 一键入库；
  Wiki 是知识库的一种形态（带出处的页面树）；记忆层把「人设文件 + 长期记忆」
  落成磁盘上的 Markdown，关掉记忆服务也读得到、改得动。
- **文档治理**：目录树、批量操作、删除前影响清单、7 天回收站、切块人工干预
  （编辑 / 禁用 / 删除——解析器一定会出错，这是质量的最后兜底）。
- **数据源**：RSS / Atom 订阅与单页 HTML，条件 GET 增量拉取，正文提取剥离导航与广告。
- **接入**：148 个 REST 端点；MCP Server 双传输 18 个工具；API Key（范围控制）；
  Webhook 事件推送（HMAC-SHA256 验签、至少一次投递、失败也推）。
- **账号与治理**：argon2 登录 + 会话滑动续期，管理员 / 成员两档角色，
  知识库分享读 / 写两档（不开放注册，首个账号由设置向导创建）；
  用量统计按本地日历日 / 用途 / 模型聚合（刻意不算钱）。
- **存储**：PostgreSQL 必选——元数据、向量（pgvector + HNSW，按知识库分区）、
  全文（tsvector 生成列 + GIN + jieba 切词）都在同一个库里；表格型文档另有
  DuckDB 结构化副本；原件 / Markdown / 图片走对象存储（本地目录或 S3 兼容）。
  没有 Redis、消息队列或独立检索服务，PG 与后端同机即可跑起来。

## 产品边界（重要）

- **不做**可视化编排 / 工作流引擎 / 文档协作编辑器 / 开放注册 / 多租户。
  Agent 只到「一个账号一个 Agent + 工具循环 + 子 Agent」为止，不提供编排画布，
  也不做跨账号共用 Agent；
- 对外**检索通道只返回检索结果原文**，提示注入防护的责任在调用方（对话通道内部已有
  资料块定界、声明「非指令」、打散文档内同形标记等缓解）；
- 默认 embedding 走云端免费 API，意味着**文本分片会外发**；隐私敏感用户请改用本地模型；
- 面向局域网单用户或小团队，不做多用户并发写与协作编辑。

## 快速开始

### 后端（Python 3.11+ / uv + PostgreSQL）

**先备一个带 pgvector 的 PostgreSQL**（必选——SQLite 已于 v0.12 退役，
没有可回退的本地实现）。最省事是用官方镜像，与本项目实测过的版本一致：

```powershell
docker run -d --name kylab-postgres -p 5432:5432 `
  -e POSTGRES_PASSWORD=kylab-dev-secret -e POSTGRES_DB=kylab `
  pgvector/pgvector:pg17-trixie
```

表结构与迁移由应用启动时自检并补齐，不需要手工建表。

```powershell
cd backend
uv sync
Copy-Item .env.example .env      # 至少填 KYLAB_DATABASE_URL，.env 不入库
uv run uvicorn app.main:app --reload
```

> 没配 `KYLAB_DATABASE_URL` 时服务**启动即失败**并提示该填什么——
> 不会静默退回别的实现（那样只会让「测试没跑」看起来像「测试通过」）。
> 跑后端测试还需要一个**独立的测试库**：`KYLAB_TEST_DATABASE_URL`，
> 未配置时依赖仓储的用例会整体跳过。

- 探针：http://127.0.0.1:8000/api/v1/health
- 接口文档：http://127.0.0.1:8000/api/v1/docs

### 前端（Node 20+ / pnpm）

```powershell
cd frontend
pnpm install
pnpm dev                          # http://127.0.0.1:5173，/api 自动代理到 8000
```

局域网访问与部署细节见[部署与运行 v0.3](docs/规范/部署与运行-v0.3.md)。

### 桌面端（可选，Rust + Tauri 2）

给"后端跑在 NAS 上、用户在别的电脑上用"准备的**纯套壳**客户端：壳里没有服务端，
只记住你的服务器地址并把窗口指过去。第一次打开填一次地址，之后每次打开直接进界面。

```powershell
cd desktop/src-tauri
cargo run --release            # 前置：Rust 工具链 + VS 生成工具 + WebView2 运行时
```

打包与细节见 [desktop/README.md](desktop/README.md)；选型与踩到的坑见
[桌面端套壳调研 v0.1](docs/调研/桌面端套壳调研-v0.1.md)。

### 一键脚本

```powershell
powershell -ExecutionPolicy Bypass -File scripts\dev-backend.ps1     # 后端开发服务
powershell -ExecutionPolicy Bypass -File scripts\dev-frontend.ps1    # 前端开发服务
powershell -ExecutionPolicy Bypass -File scripts\lint.ps1            # 规范检查（提交前跑）
powershell -ExecutionPolicy Bypass -File scripts\ci.ps1              # CI 门禁（规范检查 + 前后端测试）
```

装了 PowerShell 7 的话，`pwsh -File scripts\lint.ps1` 等价；Linux / macOS 用同名 `.sh`。

> 脚本兼容 Windows PowerShell 5.1 与 PowerShell 7；`.ps1` 必须以 **UTF-8 with BOM** 保存，
> 否则 5.1 会按 GBK 解码导致中文输出乱码。

## 工程质量门禁

**CI 在 Gitee Go**（`.workflow/kylab-ci.yml`）。它与本地命令
`scripts/ci.ps1` / `scripts/ci.sh` **调用同一批脚本**，
所以不存在「本地绿、CI 红」的分叉。

> 门禁也可以随时在本地完整复跑——这是刻意的：CI 挂了不该阻塞开发，
> 而「能在本地跑出与 CI 一样的结论」是这类项目最实用的一条性质。

每次提交与 CI 都跑同一套检查（内容见 `scripts/lint.*` 与 `scripts/ci.*`）：

| 检查 | 工具 |
|------|------|
| 后端 lint | `ruff` |
| 后端测试 | `pytest -m "not bench and not cloud"` |
| 前端类型检查 | `tsc`（Vite + React，见开发计划 §12.234） |
| 前端 lint | `eslint`（含自定义 `kylab/no-emoji` 规则）+ `prettier` |
| 前端测试 | `vitest` |
| 禁 emoji 扫描 | `scripts/scan_emoji.py` |
| 分层纪律与测试位置 | `scripts/check_layering.py`（机械核查工程规范 §3.3 / §5.1） |

三条分层铁律由脚本强制，不靠 review 记忆：

1. `api/`、`mcp_server/` 只做协议适配，禁止写业务逻辑；
2. `services/` 禁止直接写 SQL，存储访问只能经 `storage/` 的 Repository 接口；
3. `parsers/` 各实现只依赖 `base.py` 的 `ParseResult`，实现之间禁止互相 import。

## 已知限制（诚实清单）

- **容器路线只验证了一半**：`deploy/docker-compose.yml` 里的 **PostgreSQL 服务已在真实部署服务器上跑通**
  （同一镜像 `pgvector/pgvector:pg17-trixie`，PG 17.11 + pgvector 0.8.6，schema 自检引导成功、HNSW 检索实测可用）；
  但整份 compose 尚未在干净机器上「一键起」，本地 venv 路线已实测。
- **容量推荐表未填**：不同内存档位的实测数据尚未做，不编造并发数。
- **没有性能基线**：`backend/tests/bench/` 目前是空壳，CI 也用 `-m "not bench"` 排除它，
  于是性能改动前后拿不出可比数字——这是目前最容易说不清的一件事。
- **前后端之间没有类型契约**：`frontend/src/api/*.ts` 里的接口是手抄 `api/v1/schemas.py` 的，
  后端改了字段前端不会在编译期报错，只会在运行时静默错位。
- **WebDAV 数据源未实现**（架构 §14 缓做），接口处明确报「未实现」而非空实现。
- **不支持 JS 渲染的页面**：HTML 数据源抓的是服务端返回的 HTML。

## 贡献

- 分支：`main` 保护，集成分支 `develop`，功能分支 `feat/<简述>`，修复 `fix/<简述>`；
- 提交信息：`<类型>: <简述>`，类型限 `feat/fix/docs/test/refactor/chore`；
- 合并前 CI 必须全绿（**CI 是最终裁判**，本地通过不算数）；
- 新增文件先查工程规范 §7 决策树，测试按 §5.1 对号入座。
